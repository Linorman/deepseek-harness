# 邻里维修工坊开站演练

[English](README.md) | 中文

用一个小型社区工坊演练“独立治理 → 审批增员 → 外部联络 → 调岗交接 → 退出岗位”。重点不是让每一步必然成功，而是观察组织是否在证据不足、意见分歧和义务未清时正确停下。适合演示项目的 World v1、委员会、人员生命周期、独立外部代表与暂停恢复。

## 文件与当前状态

| 文件 | 用途 |
|---|---|
| [scenario.json](scenario.json) | 导入网页的完整 `clocky.world/v1` 定义；编辑的主版本 |
| [scenario.yaml](scenario.yaml) | 等价安全 YAML 定义；只选一种导入 |
| [deployment.example.json](deployment.example.json) | 运行档案、有限 Persona、领域版本与明确额度的部署目录示例 |
| [validate.mjs](validate.mjs) | 纯编译校验、JSON/YAML 等价检查、拒绝路径检查及配置拼装 |

定义已做结构与语义编译校验，没有运行 Agent 剧情或调用真实模型。部署文件的模型路由是占位值，`available: false`，正常预检应返回 `model-unavailable`。校验脚本仅在内存副本中将可用性设为 true，检查其他语义；这不安装 provider，也不证明该模型存在。它不依赖仓库测试 fixture；需要当前构建产物。

## 人物、权限与信息

| 角色（稳定 ID） | 责任 | 不能做的事 |
|---|---|---|
| 工坊负责人 `ceo` | 提出服务准则、独立投票、申请准则生效、接受交接后的新任务 | 代替居民监督员投票、宣布未交付工具已到账 |
| 居民监督员 `peer` | 独立审议准则与具体录用申请 | 修改冻结提案正文、用讨论消息代替票据 |
| 人员协调员 `hr` | 申请一名新成员、提出招聘审批、调岗和退出前盘点义务 | 直接分配 Person/Session，或替换原债务方 |
| 调控员 `director` | 核验真实请求、生成受限计划、协调原责任 | 代投、把自己的私密复盘当公共事实 |
| 新维修协调员（运行时分配 ID） | 在工具联络岗联络供应站，之后进入交接归档岗 | 读取调控员私密备注，凭空创建库存 |
| 供应站代表（按需展开） | 用独立 Persona/Session 回应授权询问 | 继承工坊内部知识，代表真实供应商承诺 |

所有组织、人物和资源均为模拟。10 credit 是工坊模拟录用账户，3 credit 是一次性模拟录用费用；不是工资、真实资金或模型账单。成功录用一次后应为7/3；拒绝或未提交时不能提前扣款。供应站库存初始未知，本场景不包含实际工具采购到账或维修实物的业务效果。

初始 `initial-hiring-approval` 是已安装的 validated 制度：工具联络岗至多录用一人，并需准确原申请的委员会批准。后续 `opening-service-charter` 是独立 advisory 准则；其文字帮助角色判断，但不会自动变成任意 Native 检查器。岗位与领域授权以定义中的 grants/permissions 为准，角色目标不会增加权限。

## 模拟时间与剧情

以下时间单位为模拟分钟，不是现实等待时长。目标和日历只提供行动机会，不预先写入成功结果；到点仍缺前提时应等待或明确阻塞，不跳过步骤。

| 时间 | 目标 | 必须查看的结果 |
|---|---|---|
| 1 | 负责人提议开站服务准则 | 原提案正文、hash、冻结两人 electorate |
| 2、3 | 两名委员分别投票 | 两个独立来源的票；反对/弃权也是真实结果 |
| 4 | 申请通过的准则生效 | 唯一 resolution 与对应 Norm；未通过则不生效 |
| 5、6 | 申请工具联络岗增员，再提出准确招聘审批 | 原 request、岗位、费用和批准对象一致 |
| 7、8 | 委员独立审议招聘 | 必须两票赞成；资料不足或否决不得强行录用 |
| 10 | 新岗位成员联系 `qiaobei-tools` | 稳定外部身份、独立代表、真实 Channel/回应来源 |
| 14 | 申请调至交接归档岗 | 原人和 Session 不变，旧/新任职时间不重叠 |
| 15、16 | 建立实际任务，再显式处理交接 | 原任务须被本人接受；取消原责任后才另建工作，由负责人独立接受 |
| 18 | 申请退出交接归档岗 | 义务未清保持阻塞；成功只结束任职，不抹除历史 |

重复联络时不要使用显示名称作为身份：引用稳定 key `qiaobei-tools` 与实际保留的代表 generation。这里仅安排一次首次联系；需要重复联系实验时，在 JSON 中增加有明确次数上限的日历，再同步 YAML 并重新预检。

## 本地校验与导入

从仓库根运行：

```sh
pnpm run build
node examples/simulation-company/scenarios/community-repair/validate.mjs
```

若当前构建已完成且源码未变，可直接运行第二条。脚本将报告与完整的 `administration.world` 配置对象保存到项目内 `.local/scenarios/community-repair/validation.json` 和 `.local/scenarios/community-repair/world-options.json`，不创建 run，也不推理。该配置对象不是完整 Cordis 配置，也不能直接作为网页场景定义导入。

接入已有 Simulation Host 时，使用生成对象配置 `@clocky/clocky-simulation-product/administration` 的 `world` 字段。保留部署自己的其他管理设置；Host 需要实际安装 local、Team、World execution providers、Simulation preset、三工具及模型服务，参见[现有组合](../../cordis.yml)和[示例说明](../../README.zh.md)。目录的 `provider/name/version` 必须与真实安装的模型元数据一致；只有确认可用后才改 `available`，并更新 catalog generation。示例的 token/Team cost-unit 上限不是货币费用保证，真实试验仍需另行确定提供方费用与硬预算。

在支持 World v1 的网页中选择“仿真 → 新建世界”，导入 JSON 或 YAML，检查定义与实际预检结果，创建暂停运行。确认角色、两人委员会、初始强制制度、模拟资源和有效限额后，才显式开始调度。当前没有真实模型配置，因此本次只交付可校验设计，不执行该开始步骤。不要把已有 `complete-world` 测试的 scripted model 直接套到这些新自然语言目标上；该适配器只识别原测试剧本。

## 观察与分支实验

成功轨迹不是验收的唯一结果。每轮保存 request/plan/execution/notification 四区状态、原Decision/Envelope来源、任职区间、资源与义务盘点；在暂停后创建完整 checkpoint，显式恢复应仍为暂停，原身份与原结果不重复。

可以分别运行以下独立实验，每次改定义都重新预检并创建新运行：让监督员在证据不足时投反对票；只调整其目标并不保证模型必然反对，以实际票据为准。让供应站保持未知库存，确认不会凭回复生成资产。保留一个已接受且未清的任务，确认离岗返回交接阻塞。重复提交同一管理命令，确认不会多录用或重复付费。检查新成员/代表上下文不含 `REPAIR-PRIVATE-ONLY`；读过私密信息的角色自由文本不能被简单字段过滤证明绝无泄漏。

基础规模是4名初始认知人物、1名新增成员和最多1名外部代表，2个驻留槽位、16个实体/历史参与者上限。50,000 token 的 Native/Team示例限额可能使真实模型在剧情结束前停止；这应记录为预算结果，而不是自动增加预算。两种编写格式必须同步维护；校验器在不等价时会失败。

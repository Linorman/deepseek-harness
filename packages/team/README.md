# team/ — durable Team work-system family

English | [中文](README.zh.md)

This family contains local Team work-system providers. The Service Definition remains [`core/team`](../core/team/README.md), so a provider can own durable Team state without making a Team an Agent, Session, or experimental Lead identity.

`team-workspace-sandbox` creates a provider-owned local root per exact attempt, optionally seeds it from a configured source directory, verifies an external allocation manifest during recovery and release, and publishes bounded changed-file artifacts. With explicit integration configuration it also applies its portable change set to a local target directory under an expected-version fence. The E2B `team-workspace-e2b` provider uses one explicitly mounted E2B execution world, allocates isolated remote roots, publishes bounded remote file artifacts, and can apply its own portable change set to a live configured remote target; it remains an opt-in POC and its sandbox state is not a cross-process durable store.

`team-hub` is mounted explicitly with [`clocky-team`](../core/team/README.md), [`clocky-storage-log`](../storage/storage-log/README.md), and a selected log backend. It persists Team-wide human-action records and provider usage aggregates alongside roster, task, activation, and channel state. `team-artifact-local` mounts with [`clocky-team-artifact`](../core/team-artifact/README.md) and stores hash-verified file, patch, log, screenshot, and report bytes under an owner-only root; the Team journal retains only references and provenance. `team-workspace-shared` mounts with [`clocky-team-workspace`](../core/team-workspace/README.md), `clocky-team`, and `clocky-agent`; it returns its canonical root only for an exact current local-Agent lease and Session header, and its optional artifact/integration configuration publishes portable change sets to separate provider-owned target directories. `team-workspace-worktree` adds the subprocess capability and creates a detached Git worktree only after current lease, local-Agent, and policy validation; its explicit command deadline and fresh bounded drain guard every Git lifecycle, and its accepted allocation retains normal retryable Git removal. `team-link-local` mounts with [`clocky-team-link`](../core/team-link/README.md) and `@clocky/clocky-team`, then replays pending recipient Envelopes through cancellable local watches, bounded handoff, retry, and binding-derived attempt settlement. `team-link-websocket` registers the remote provider, while `team-link-websocket-hub` authenticates remote upgrades against configured durable bindings. `team-activation-controller` exposes its bind-or-dispose owner at `ctx.teamActivations`; `team-activation-recovery` is a separately mounted, same-host startup scan that delegates selected SDK epochs back to that owner. `team-channel-direct`, `team-channel-basic`, `team-channel-task-assignment`, and `team-channel-workflow` register after a Team provider; `command-team-goal` scopes `/goal` to a Team-bound Agent and derives its actor from the Session header; `tool-team` registers task reporting and explicit final output in a Team-bound Agent scope; `tool-team-goal` reads and activation-fenced edits the durable objective only for an exact current TeamRun coordinator; `tool-team-task` registers default-worker task start and wait only for that coordinator; `team-agent-client` connects a selected Link only for matching durable-bound live Agent Sessions, then owns direct/task-assignment inbox admission, delivery-bound task start, usage forwarding, and eligible Link reconnection; `team-scheduler-dag` consumes Team state to expire leases, attach task-assignment channels, and commit unique assignment Envelopes without waking an Agent; and `team-run` owns the local default human/coordinator/worker topology plus human final-result receipt. `clocky-headless` and `clocky-web-app` mount the local Hub path with the shared workspace registry, its `process.cwd()` root provider, task-assignment adapter, bounded scheduler, `tool-team-goal`, and `tool-team-task` after `team-run`; Web additionally mounts `command-team-goal` and disables the same-Session Goal stack. The provider canonicalizes that root, leaves a mismatched Session `cwd` ineligible, and rejects allocation rather than changing either path. Their Team-run row selects the non-delegating `minimal` preset for a lazily activated worker; Headless resolves it through the profile-injected shipped preset root, and Web resolves it through its mounted roster. The scoped model tools register only for the exact live coordinator.

The optional `team-telemetry-otel` provider composes `clocky-team`'s `TeamTelemetryCoordinator` with the OpenTelemetry SDK's OTLP/HTTP logs pipeline. It is not in the default product bundles: deployments opt into `FULL`, choose an endpoint, and may configure rolling alert rules whose crossings become `ops` records. Exporter failure and alert policy never become Team journal authority.

The Team types and provider operations are defined in [docs/subsystems/team.md](../../docs/subsystems/team.md). The [local Team Hub decision](../../.agents/notes/implemented/architecture/2026-08-27-local-team-hub-durable-authority.md) records the ownership and recovery rules.

## Configuration and ownership

Browser configuration belongs in modules.browserConfig under `@clocky/clocky-client-ui-simulation`. `pageSize` defaults to 32 and `controlRefreshMs` to 2000 real milliseconds. The Host independently enforces its allowances and action preconditions. `watchWaitMs` defaults to 10000 and `watchRetryMs` to 2000 real milliseconds; one visible-run metadata watch detects native revision and policy changes. Policy resets remove old context text and revalidate its selected section without clearing drafts or original commands; other retained pages become stale and refresh remains explicit. `maxRetainedCommands` defaults to 64 and `maxCommandBytes` to 262144 UTF-8 bytes of complete retained original records, reserving transient result/error metadata before IO. `maxInputDrafts` defaults to 16 entity-input, exact-attempt review and operation-retry slots; `maxDraftBytes` defaults to 65536 shared bytes of complete creation, entity-input, review and operation-retry drafts. Capacity refusal preserves existing inputs and operations. World authoring drafts are counted separately: `maxWorldDraftBytes` defaults to 262144 complete UTF-8 bytes per slot (the Host compiler source ceiling), `maxWorldDrafts` to 4 concurrent slots and `draftUndoDepth` to 20 in-memory undo steps; `inspectorMaxWidth` (default 520 CSS pixels) caps the World inspector, which is resizable on content of at least 1440 pixels. One World management-flow draft shares the input/review draft count. `staleAfterMs` (optional; default fifteen `controlRefreshMs` intervals and at least 30000 real milliseconds, and it must exceed two intervals) is the age after which a run observation is shown as a last observation. `stopDrainMaxSteps` (32), `stopDrainMaxTokens` (262144) and `stopDrainMaxWallTimeMs` (600000) prefill the stop-target drain budget; each target carries its own values.

Business responses and original commands live in Client runtime. The UI store retains navigation, committed search, scroll position and bounded per-run raw input drafts. Account replacement or authentication retirement clears private input and prior operations; ordinary disconnect preserves them. Switching workspaces cancels view reads, not accepted Host work. Unsaved input stays in memory; explicitly saved author revisions persist on the Host, while localStorage and URLs contain no draft bodies. Leaving/reloading with retained input or an unknown operation invokes browser leave protection. Closed dialogs keep input; explicit discard confirms loss and preserves an unresolved original selector.

## Run state, stop targets and business summaries

One presentation function (`run-state.ts`) words every run state for the directory rows, the header and dialogs: running, stopping, saving, paused, idle (running requested with no work to advance), attention, blocked, failed, completed, reconciling and unknown. Native world facts, the management control (or the directory's operational projection), read health and the connection stay independent inputs; sources whose phases disagree show *reconciling* with Refresh rather than either source. Each state has at most one primary action: Continue when paused, Pause while running, Recover (token acknowledgement, checkpoint restore or explicit resume, whichever the Host allows) when failed or blocked, the resolving surface for attention, Edit target once a stop target is reached, and Refresh when stale. An observation older than twice `controlRefreshMs` is *aging*; a failed read, a lost connection or an age beyond `staleAfterMs` makes it *stale*: the chip reads "current state unknown · last observed …", motion stops and other controls are disabled with a reason. A failed native detail read alone keeps state, Pause and checkpoint saving usable from the live control and explains the limit. A terminal management, checkpoint, recovery or stop-target receipt calls the runtime's `invalidateRun(runId)`, so the directory row stays a last observation until a newer status batch answers it. A failed status batch marks every row individually and offers a retry; explicit refreshes report refreshed, failed or timed out.

Stop targets are a separate original command (`updateRunControl`): the start confirmation and the Edit target dialog offer "run until simulated time N" on the run's native clock, the default `drain-admitted` mode with an editable drain budget (`stopDrainMaxSteps`, `stopDrainMaxTokens`, `stopDrainMaxWallTimeMs` defaults) or `at-boundary`, and an optional checkpoint after pausing. Continue stays disabled until the Host's receipt is confirmed and its current control carries that target in effect; pending activation, Host boundary refusals (with the Host sentence in details) and unknown outcomes are distinct, and an unknown outcome retries the exact original command. The header chip and banner follow the Host state from armed through draining to paused, show the scope counts captured when draining began if its budget runs out, and distinguish complete, partial (`external-state-required`) and failed saves; after a failure, Retry the save opens an explicit checkpoint that the Host records as another attempt of the same stop-target save, keeping the failed attempt and calling no model. Closing the browser leaves the target on the Host; reopening shows it.

Scheduler failures render a failure card from the Host's safe facts only: which stage failed, whether accepted work still runs, that completed results are kept, and the next step mapped from `actionCode` (an unrecognized code only opens run details). Continue is offered only for an `explicit-resume` disposition; provider messages never reach the page and the failure identity is copyable for authorized correlation. Directory rows and details show localized unavailability reasons (history limit, unsupported version, damaged history, owner unavailable); the original Host message stays in technical details.

World matters lead with the domain projector's business action and three independent result layers (submission, judge execution, business outcome); a recorded result the judge rejected reads "judge rejected" without success color, unknown never counts as success, and without a projector the row says the domain provides no business summary. The generic `committed` status is neutral technical wording. The overview's domain business card shows the newest allowed projector counts on the first case page with their revision and definition; withheld, unknown, not applicable and zero stay distinct through one `DisclosedValue` component, which also replaces restricted content as soon as a grant is revoked. Technical bindings (resident seats, writers, participants, activations) live under Run management. The budget panel separates admission limits, reserved, settled and unknown usage by Host category (business choice, director ruling, result settlement, communication, compaction, unattributed) and token kind, estimates no cost and labels the Host-wide model limit as shared with every run. The recovery dialog leads with the restored time, that the run stays paused, that history is not rolled back and completed model calls are not repeated, and checkpoint completeness; coverage and technical identifiers follow as disclosures.

## Journal records and export

The Records module reads a separate metadata window and exact original-record inspector from runtime. Committed kind filters and source sequences survive URL reload/history; frozen context run-event references open that exact record. Original JSON is displayed as text only after separate Host historical-content permission. Ordinary read failures preserve the page; policy retirement clears private text and cancels old responses. Sequence order is not presented as wall or simulated time.

Explicit export reads all matching records from the first page at one revision and policy, then repeats an authenticated read before generating a file. Metadata and original exports have separate controls; originals require a whole-run `recordReaders` grant. Partial, reordered, repeated, stale, revoked and interrupted exports produce no file. `maxExportBytes` defaults to 16777216 complete UTF-8 file bytes and `maxExportPages` to 2048 data pages plus one final validation request; output includes its selection, revision and policy version. Cancel, view/run changes, disconnect and unload abort requests and discard buffered text. Completed downloads are files controlled by the user and are not revoked retroactively.

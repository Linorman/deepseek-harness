# Simulation browser workspace

English | [中文](README.zh.md)

This opt-in plugin adds a Simulation entry beside Team navigation and an independent product workspace. Its Host entry requires `simulationProducts`; absent deployment advertises no navigation. The [viewing composition](../../../examples/headless-agent/tests/fixtures/simulation/simulation-web/cordis.yml) supplies metadata only. The [administrative composition](../../../examples/headless-agent/tests/fixtures/simulation/simulation-administration/cordis.yml) additionally supplies installed templates and production scheduling. Shipped defaults do not enable Simulation.

The source inspector follows a retained decision ordinal in the URL and owns no business data in React. Runtime holds one source page, discards known revoked content and cancels old responses. Any Team revocation retires that single page because canonical-parent readership can depend on another Team. `sourceRefreshMs` defaults to 2000 real milliseconds and revalidates a located original at its exact position/page after each settled read; lookup continuation stays explicit. Policy, authority, run changes and hiding the inspector retire pending reads. Ordinary network loss retains visibly stale text; reconnect revalidates before redisplay. Keyboard entry focuses the source heading, and return restores its reference or parent control.

Entity bindings, accepted task references, frozen Team/channel sources and materialized checkpoint Session references link to exact Team inspection. Same-document navigation preserves retained private drafts and original operations; browser Back restores the Simulation selection. References grant no Team membership or content access. The destination checks the exact task/channel owner and participant/Session binding; historical Session mismatch refuses instead of substituting the current Session. Unmaterialized Sessions and checkpoint channels without a Team identity remain inert references.

The workspace separates identity/actions, grouped scheduling and in-flight facts, module navigation, and optional run diagnostics. Narrow collection inspection uses one primary panel and the shared module Menu. Collection columns use existing entity, decision, operation and checkpoint summaries; they do not issue per-row inspection reads. Creation uses the shared wide form, keeps basic input first, discloses installed configuration and limits on demand, and expands a rejected field before focusing it. The primary action explicitly creates a paused run.

Run progress emphasizes bounded entity and pending-work counts and token budget occupancy. Complete budget counters and Host-wide pool usage are independent disclosures; human review and unknown outcomes precede them. Read-only owner/version facts belong to run diagnostics, while empty review/task windows remain compact and retain their refresh and error paths. Confirmed cognition-only runs show their execution mode and omit automatic-task controls; unavailable scenario metadata keeps the recovery path. This distinction comes from the retained run creation, not the current catalog or task count.

CollectionWorkspace shares the filter, bounded page and inspector frame while the existing Workspace retains read ownership. Object summaries lead with authorized names and domain facts; technical identifiers remain copyable in their disclosure. Closing the inspector restores its row or the filter when that row is outside the current page. Known native journal kinds have localized labels and a quick selector; exact custom filters preserve whitespace, and unknown or truncated kinds remain literal.

## Configuration and ownership

Browser configuration belongs in modules.browserConfig under `@clocky/clocky-client-ui-simulation`. `pageSize` defaults to 32 and `controlRefreshMs` to 2000 real milliseconds. The Host independently enforces its allowances and action preconditions. `watchWaitMs` defaults to 10000 and `watchRetryMs` to 2000 real milliseconds; one visible-run metadata watch detects native revision and policy changes. Policy resets remove old context text and revalidate its selected section without clearing drafts or original commands; other retained pages become stale and refresh remains explicit. `maxRetainedCommands` defaults to 64 and `maxCommandBytes` to 262144 UTF-8 bytes of complete retained original records, reserving transient result/error metadata before IO. `maxInputDrafts` defaults to 16 entity-input, exact-attempt review and operation-retry slots; `maxDraftBytes` defaults to 65536 shared bytes of complete creation, entity-input, review and operation-retry drafts. Capacity refusal preserves existing inputs and operations.

Business responses and original commands live in Client runtime. The UI store retains navigation, committed search, scroll position and bounded per-run raw input drafts. Account replacement or authentication retirement clears private input and prior operations; ordinary disconnect preserves them. Switching workspaces cancels view reads, not accepted Host work. Input stays in memory; localStorage and URLs contain no draft bodies. Leaving/reloading with retained input or an unknown operation invokes browser leave protection. Closed dialogs keep input; explicit discard confirms loss and preserves an unresolved original selector.

## Viewing and creation

The directory retains its bounded name window and reads one ordered operational-status batch for exactly those IDs. Status refresh and real-time polling never scan all native runs. Rows distinguish unavailable/missing observations from zero, preserve exact tick strings, and display observed scheduling, in-flight work, residency confirmation and scenario/rules/policy versions. Failed reads keep marked stale status; replaced pages or authorization retire old replies. Unknown imported scenarios remain unavailable rather than being guessed from names.

Every run module keeps one shared status/control header, with browser connection, native clock, phase, scheduling stop and accepted work shown independently. Start confirmation and original commands keep one owner across module changes. The Host’s execution-history hint labels continuation; allowed start/pause hints choose action emphasis. A pending action keeps its label, and its late settlement does not refresh another selected run. Compact maintenance/input disclosure opens the existing retained dialogs. Overview shows native interval charges, reserved/unknown tokens, resident slots and pending work; Host model admission is a separate real-time active/queued observation. Charged token budget is explicitly not exact known model consumption, and absent older-peer metrics remain unavailable.

Simulation owns one page-content scroller. Header, module content and retained originals keep their natural height; dense narrow headers cannot collapse the input/review body into an unclickable zero-height pane. The view store remembers the page scroller under directory or collection context. Native dialogs keep their own bounded form scroll.

Directory search explicitly commits registered-name queries, clears immediately and uses bounded continuation. Collection status and entity cognition filters use bounded Host queries; committed filters, related entity/decision identities and operation sections survive URL reload and browser history. Changing filters returns to the first page without copying all records. Overview, Entities, Decisions, Operations and Checkpoints expose exact-object metadata in a non-modal inspector. Narrow views provide one main surface and a return action. Simulated time remains an exact decimal string. Registration ownership, saved phase, driver progress, proposal acceptance, effect application, publication and consumption remain distinct. A newer control revision marks overview counts for explicit refresh. An administrative-control refusal does not revoke separately authorized viewing metadata. Entity and decision details link to their related metadata. Operation details expose effect results, dependencies and publication timing separately from receipts; publication attempts and checkpoint references have independent first/next controls. Failed reads preserve content and disable continuation until refresh. Source references remain metadata only. Entity relationships retain historical intervals and explicit endpoint links. The decision context section shows frozen provenance and independently paged original section parts/references. Host body permission selects plain-text preview or explicit redaction; non-text payloads remain withheld. This local view is never labeled as the complete model request. Switching runs cancels both the browsing inspector and recovery-reference reads.

Creation selects only installed versioned templates and permitted name/stock inputs. Host catalog configuration names editable entity/residency/token/tick limits and their installed defaults/maxima; blank overrides retain defaults. The read-only shared Host model ceiling, tick unit, budget interval, rules and policy versions remain visible. Check configuration calls side-effect-free preflight without a command identity. Creation repeats that check for the unchanged draft before allocating its original command; editing, dismissal, disconnection or authority replacement retires pending validation. Semantic field issues preserve input, identify the responsible control and focus its first error. Unknown original creation retries retain the submitted limits and never recheck a changed draft as a replacement operation. Positive quantities remain decimal strings, including values beyond JavaScript's safe integer range. The form uses app-owned validation, field errors and IME-safe submission. Creating prepares a paused run and its initial full checkpoint without inference. Response loss retains the original command and payload; query or explicit retry recovers that operation rather than allocating another run. Later edited input remains separate from the submitted original.

The secondary More menu opens Request history (`simulationModule=requests`), separate from world-event Records. It combines each current persistent row with its retained original once, and lists off-page or management/ingress originals independently. The overview links to this surface; unknown creations without an assigned run remain reachable from the directory. Workspace owns the request-page read on entry to either overview or history, so hiding the presentation does not remove reconciliation from overview recovery. Request history discovers persistent administration receipts independently of private browser drafts. Its bounded request window uses its own journal revision and metadata-only authenticated cursors. Querying does not execute; accepted originals have an explicit retry using the Host-retained payload and command identity, while terminal requests remain unchanged. A warm original retains its complete captured input; cold discovery keeps only runId/commandId in runtime. Navigating or retiring credentials cancels reads and old callbacks cannot refresh a newly selected run. Cold review/external retry requires explicit owner restore. Native phase/ingress history remains separate from this administrative journal.

## Journal records and export

The Records module reads a separate metadata window and exact original-record inspector from runtime. Committed kind filters and source sequences survive URL reload/history; frozen context run-event references open that exact record. Original JSON is displayed as text only after separate Host historical-content permission. Ordinary read failures preserve the page; policy retirement clears private text and cancels old responses. Sequence order is not presented as wall or simulated time.

Explicit export reads all matching records from the first page at one revision and policy, then repeats an authenticated read before generating a file. Metadata and original exports have separate controls; originals require a whole-run `recordReaders` grant. Partial, reordered, repeated, stale, revoked and interrupted exports produce no file. `maxExportBytes` defaults to 16777216 complete UTF-8 file bytes and `maxExportPages` to 2048 data pages plus one final validation request; output includes its selection, revision and policy version. Cancel, view/run changes, disconnect and unload abort requests and discard buffered text. Completed downloads are files controlled by the user and are not revoked retroactively.

## Scheduling and original outcomes

Unknown external work has a separate bounded overview preview with exact-operation links. Its operation form waits for a current Host retry capability and captured attempt-count fence. A grant registers the Native bounded allowance for the original intent; it neither publishes nor resumes or requests a model. Queries and unresolved same-original retries preserve the retained normalized input and remain independent of new-request capacity. Confirmed terminal journal results and conflicting terminal observations are query-only. Later raw reason edits survive receipts, while a definitive refusal requires a changed reason or explicit current-fence confirmation before another command. Private operation drafts share input/review count and full UTF-8 bounds, survive navigation/disconnect, and clear on authority replacement. Explicit scheduling is required to reconcile the target after a completed grant.

Checkpoint and restore receipts and retained checkpoint details display only structured stage/code/canonical-subject diagnostics. Team, channel and Session links carry their complete exact ownership identities; run/entity/checkpoint navigation stays inside authorized Simulation metadata. Cleanup remains independently unconfirmed where reported. Private provider messages, storage paths and error-string parsing never enter the diagnostic UI. Known failed diagnostic receipts retain original lookup even when fresh maintenance admission is unavailable.

Administrative task review appears in the overview as one bounded revision-pinned page. Rows expose only scenario-verified inventory-transfer and report-publication IDs, exact quantity, attempt/reviewer metadata and Host action hints; task instructions and original report text remain private. Approval and rework target the original operation, attempt and task revision. Changed revisions require an explicit current-revision confirmation for that same attempt; another attempt never replaces a retained target. Review does not start inference.

Private review drafts use exact run/operation/attempt slots and share count/complete UTF-8 capacity with entity input. Closing, navigation and ordinary disconnect preserve authored text and original command selectors; authorization replacement clears them. Unknown outcomes allow only original query/exact retry. Submission normalizes whitespace and retains a bounded raw submitted draft; completion clears only that exact raw input, so even later whitespace edits survive. A terminal failure cannot allocate another command for the same reason, decision and revision; a semantic edit or explicit current-revision confirmation is required. Review-write refusal preserves authored originals, drafts and independent viewing; actual authentication retirement still clears them. Old commands reopen their original review form and never enter the maintenance form.

The Host supplies start/pause allowability and model, token-interval, resident and shared-host concurrency limits. Start confirmation identifies the run and these limits; the browser cannot change the shared permit ceiling. Background control refresh preserves valid controls while each write rechecks native admission. Pause distinguishes saved intent from accepted work still finishing.

The retained-operation view shows original command identities and receipts, with explicit original-result queries and exact retries for unresolved operations. `not-found` is not failure. Unknown start/pause outcomes prevent another identical new intent while permitting a distinct explicit intent. Known terminal receipts can be released; pending or unknown originals cannot. Querying, reading or navigating does not resume inference.

Task cancellation has its own bounded overview and exact revision/nullable-attempt form. Raw reason and original command share the existing draft quota and survive dismissal, navigation and disconnect. Unknown results permit only original query/retry; a new refusal requires semantic edits or explicit current-fence confirmation. Authentication replacement clears private drafts. Cancellation belongs to Simulation administration and retains previously applied effects.

## Checkpoints, recovery and entity input

Host administrative hints govern explicit checkpoint, recovery, preparation and entity-input forms. Checkpoint confirmation explains pause/drain/actor retirement and preserves the last complete cut on failure. Recovery displays the exact compatible checkpoint, real publication time, prefix/current revisions and independently paged Run/Team/Channel/Session references. Reference reads neither verify sources nor take a writer; explicit restore validates retained history/current suffix, retires old writers and leaves a paused owner without rollback or model replay.

Entity input selects only one Host-approved target and canonical earliest tick; it does not broadcast or add authority. Raw text/target/time survives dismissal, module changes and ordinary reconnect. Unknown result keeps the same original selector; later edits remain separate. Receipts display assigned time separately from pending/claimed/consumed/cancelled status and linked decision. Dedicated retained-input/original-operation entries remain available when a new operation is blocked. Explicit receipt acknowledgement clears only unchanged submitted fields; later edits remain. Shared quota refusal preserves previous drafts and sends no operation.

## Model Experience

### Explicit Simulation scheduling

#### What the model sees

Browsing, creation and original-result queries contribute no model input. An explicit start invokes the deployed scenario driver and its recorded authorized context through the selected Simulation preset. The [company preset](../../../examples/simulation-company/presets/simulation/agent.cordis.yml) supplies a complete Simulation persona and `simulation_observe`, `simulation_stage` and `simulation_submit`; ordinary Team tools are withheld from these requests.

#### Token effect

Zero direct effect from viewing, creation or result queries. Explicit scheduling consumes the configured native model permits and run budgets; pause prevents later admission while accepted requests may finish.

#### KV Cache effect

The scoped persona and tool definitions remain stable for an actor. Context and tool results append through its existing Session history.

## Known Limitations and Deferred Work

- Additional automatic task scenes, full failure/interruption matrices retain separate acceptance requirements.
- Source views expose supported original text; arbitrary provider payloads remain withheld. Entity current knowledge and decision-selected exact versions use dedicated pages; context references open exact knowledge selection. Current audience revocation clears these bodies on world invalidation. Original report text is displayed only under its separate Host source permission. Metadata links and source references grant no Team/Session content authority.
- Complete language/theme/zoom/keyboard, grant revocation and interruption matrices remain required acceptance. Real JSON/SQLite browser creation, control, response loss and credential replacement cover their declared flows; the external model is scripted, not a live-provider or multi-host test.

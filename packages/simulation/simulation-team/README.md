# Simulation Team coordination

English | [中文](README.zh.md)

`ensureTeam(run, creation, ownerName)` reserves a root Team id in the run journal before Hub IO and confirms the durable result. Retrying a lost response preserves that identity and creation payload. Close drains accepted creation; an unconfirmed root prevents attachment, entity binding and execution. Call this before attaching the lifecycle owner.

`ctx.simulationTeams.attach(run, teamId, ownerName)` attaches an open run to a dedicated Team whose immutable `rules.activationLifecycleOwner` equals `ownerName` and `rules.simulationRunId` matches the run id. The returned connection binds cognitive entities to fresh active local participants, mints stable Session ids, activates them, reconciles recovery, and drains owned activations on close. All entities retain one canonical execution Team.

`ensureParticipant(entityId, participant)` reserves immutable actor configuration and Participant/Session identities while the run is paused, then reconciles invitation, membership activation and binding. It does not start an Agent. Conflicting configuration rejects, incomplete provisioning blocks run execution, and close drains accepted topology IO. Each invitation and phase-change reply must name the reserved Participant before binding can complete; a mismatched reply leaves the reservation retryable.

`ensureChannel(request)` reserves one direct-v4 identity and ordered membership, reconciles the original WAL and Team attachment, then obtains each canonical Session endpoint’s consent. Recovery preserves invitation deadlines and does not start Agents. Changed membership or limits reject; the run cannot execute while channel confirmation is incomplete.

`invitation(entityId)` supplies channel creation options frozen to the canonical Session. `acknowledgeInvitation(entityId, channelId)` confirms that direct-v4 endpoint without activating cognition or requesting a model. A revocable proof binds the exact invitation and current active entity; expired invitations and withdrawn authority reject. The confirmed channel retains deliveries while the recipient is dormant. Connection close drains accepted standalone invitation acknowledgements before releasing the run owner, including when no Agent is resident.

The activation controller enforces the owner on direct calls as well as connection calls. Startup always has a durable Team reservation, shared with the Simulation writer epoch. The integration pins the actual in-process provider before startup, enables a writer only after exact durable binding, revokes before termination, and releases only after confirmed quiescence. Missing owners, wrong identities, duplicate bindings and external runtime implementations reject. Model authority is published only after binding succeeds; a rejected retry preserves the established writer. Run actor capacity is reserved before provider startup, including direct controller calls. Revoked or uncertain writers retain their charge until controller-confirmed release; Team capacity applies independently.

Run close invokes connection retirement outside the run write queue. Failed shutdown retains ownership for retry. Recovery distinguishes a committed binding, unpublished startup, and a Team reservation that never passed domain admission; another live coordinator remains excluded by the run lock. The [Loader fixture](../../../examples/headless-agent/tests/fixtures/simulation/simulation-team/cordis.yml) and its subprocess tests cover both storage backends.

`hibernate(entityId)` closes new cognition and delivery admission for an idle actor, drains accepted deliveries, checkpoints its Session and stops its exact controller-owned activation. Open or submitted decisions must settle first. Checkpoint or termination failure retains writer capacity for retry. `resume(entityId, request)` reuses the proven-stopped canonical Session without starting inference; pending delivery input is restored before the next decision. Unknown startup history requires explicit recovery. Model dispatch reserves run token capacity after acquiring a model permit. Stream cleanup flushes Session usage before settlement and before releasing the permit; missing terminal usage retains the reservation. Every re-entry into the model stream allocates an independent attempt. Proven cancellation before downstream dispatch releases the reservation.

`ensureResident(entityId, choice)` uses explicit placement and an ordered eviction list. It hibernates only idle actors with settled decisions; unavailable capacity and unconfirmed writers return distinct results. `driveResident(request, clock, choose)` applies this policy when transport requires a dormant recipient, within the same coordination-round limit, and stops before inference. Concurrent coordinator calls are rejected while this drive is active.

`registerDeterministicPolicy()` installs a named, versioned, bounded synchronous policy. `executeDeterministicDecision()` runs it under the canonical actor’s maintenance lock over the frozen authorized view. Selection and output are durable; retries reuse recorded output, and ordinary submission/resource checks still apply. Opaque decision ids, including JavaScript property names, are valid for this path as well. Selected decisions cannot request inference or reserve model tokens. Policies are trusted plugin code and must perform no IO. Closing drains admitted computation and prevents late acceptance. Completed deterministic delivery wakes retire their exact inbox copies before subsequent cognition or hibernation, without fabricating a model turn. Knowledge-backed reports already present as canonical Team messages are referenced without repeating their body. If no original is visible, the authorized retained body is materialized. After compaction, missing report originals are rematerialized from the same knowledge versions in a durable, rebudgeted presentation. Required-content overflow stalls; a masked Simulation view is appended again without replacing unrelated history. Declare a deterministic window’s `policy` at opening so its frozen view retains full report content. Caller-supplied report-visibility hints cannot suppress a policy’s report bodies.

`openWindow()` resolves each resident actor’s context budget and a shared Team cursor before the run freezes its slots. `executeDecision()` can run concurrently for those actors and returns `submitted`; `run.commitWindow()` performs ordered acceptance. `cancelDecision()` retires an unfinished slot without reusing its identity.

`openDecision()` and `submitDecision()` derive the writer from the attached entity. The live Agent and current Team membership are checked inside the run write queue, so a direct run submission cannot skip the installed admission check. Retirement closes new admission immediately, including when the durable revocation fails.

Config requires positive `maxContextBytes`, `deliveryPageSize`, `maxCoordinationRounds` and `maxConcurrentModels` bounds, plus non-negative `maxQueuedModels`. The context budget is measured on the UTF-8 JSON encoding of the selected content-block array, independently of the model route's total token limit. `prepareContext()` accepts already-authorized sections and source references. The run reserves identity, authority, input, goals and commitments, plus every additionally required section; optional sections are selected whole in priority order when they fit. Required overflow durably stalls with `SIM_CONTEXT_REQUIRED_ITEM_OVERFLOW`; cancel the decision, adjust the deployment budget and explicitly resume before allocating another slot.

Before inference, the pre-step owner requires the current prepared decision, appends or precisely replaces its `simulation/context-view`, flushes the Session and rechecks live writer authority. At model dispatch, the prepared input must belong to the active Agent turn. The stream must match the recorded request header, conversation and single current view, including a final recheck after token reservation. The complete request prefix, including consumed input and its header, is flushed before the downstream stream is constructed; writer authority and cancellation are then rechecked. Failed flush prevents inference. Auxiliary model purposes are not admitted by this conversation policy. Repeated preparation preserves the selected content, policy fingerprint and input id.

Model permits are shared across this service’s attached runs. Waiting is bounded FIFO; cancellation removes a waiter, while a granted permit remains charged through downstream stream cleanup. Permission and recorded-request checks repeat after admission. `modelUsage()` reports reserved/executing and queued counts. Decision deadlines include admission waiting. Closing a connection cancels its waiters; service unload closes all admission before stopping owned actors.

`executeDecision()` prepares and dispatches one resident actor’s decision, then requires its exact input’s completed turn, submitted or accepted proposal and durable Session flush. A timeout returns its retained cancellation. Missing submission and context overflow reject; retries reuse the recorded selection without repeating consumed input. Decision ids are opaque; names shared with JavaScript object properties remain valid and retain the same retry identity. The [company scenario](../../../examples/simulation-company/README.md) uses this entry for a two-entity model workflow.

The run’s required `decisionTimeoutMs` covers all model and tool steps from the first model admission attempt. Timeout is journaled before the matching Agent input is interrupted. Pause does not extend this infrastructure deadline. Completed proposals cannot expire while waiting for slot order. Service shutdown immediately closes admission and starts closing every attached connection, including while another run is draining bootstrap work. Timers remain active for an unsubmitted idle turn and are retired on submission, activation release or connection close; close drains accepted timeout writes, input persistence, direct outbox dispatches, recipient discovery and failure reconciliation, hibernation, recovery lookups, model-decision completion, and both ordinary and automatic-residency coordinator drives before releasing the connection.

`dispatchDecision()` flushes the frozen input identity and its control message before calling `Agent.wakePending()`. Concurrent retries share admission; consumed inputs return their durable status without another wake. Pending inputs of terminal decisions are retired before a new slot runs. These statuses describe input delivery, not business acceptance.

`dispatchOperation()` publishes accepted due communication through direct v4. A runtime-only proof binds the complete draft, retry key, run, decision, operation, accepted revision and fingerprint; Hub revalidation owns target membership and policy checks. Writer retirement does not cancel accepted publication. Withdrawal permits reconciliation of an exact committed result, not a new post. A publication receipt does not prove recipient Session persistence or business acceptance.

`receiveOperation()` serves a resident recipient through dedicated claim/receipt proofs and the shared direct-v4 renderer. It deduplicates the exact input, flushes the Session, records delivery plus its wake atomically, acknowledges the Hub, and retains that receipt in the run. `run.drive()` returns `delivery-required` until this completes. Before a new decision, already-admitted input can be restored locally without another Hub notification. A confirmed receipt does not cause repeated input or repeated inference.

`connection.drive(request, clock)` alternates journal scheduling with required publication and receipt, bounded by `maxCoordinationRounds`. It stops for a decision, unavailable or busy recipient, technical retry deadline, unknown outcome, or scheduler limit. Concurrent calls with the same horizon share progress; a different horizon rejects until the current call settles. The caller supplies residency and decision handling after these explicit stops.

The coordinator recognizes only exact durable `channel/delivery-expired` records as target failure. Channel phase and transient read errors alone do not establish failure. `reconcileDeliveryFailure()` retains recorded input, reconstructs a wake after an interrupted input flush, attests absence under the canonical live writer, or records irreversible entity termination. The run stays stalled until reconciliation and explicit resume; business commitments remain independent.

`modelRequest()` binds observation, proposal staging and submission to the registry-owned Agent, current writer and consumed prepared input. Observation returns the frozen selected sections. Staging replaces one complete list within that epoch; accepted submission survives retirement. The tool execution guard admits only the three Simulation tools for these actors.

A handle used only to inspect replayed state can close without retiring historical writers; any admitted mutation, recovery or retirement owner requires writer quiescence. Failed pre-admission validation releases the run lock without changing durable writer records, allowing exact source repair and retry.

## Model Experience

### Cognition residency

#### What the model sees

`ctx.simulationTeams` creates or resumes the entity's local Agent and Session. A prepared decision contributes its recorded supplementary context and one identified control message; received direct content uses the standard Team projection once. The `tool-simulation` consumer exposes observation, staging and submission.

#### Token effect

Residency and preparation do not start inference. An admitted request includes the selected context blocks; optional omitted sections cost no model tokens.

#### KV Cache effect

The stable Session survives epoch replacement. Context refresh replaces one prior view while retaining other messages; changing that view invalidates the reusable request prefix from its position.

## Known Limitations and Deferred Work

- Decision selection and authorized context remain caller-owned. Conflict retries supply durable wakes, but decision selection and refreshed context remain caller-owned. Ingress text and its receipt reference are required context only for the decision claiming that input’s consumed event. Ingress does not mutate World facts or grant authority.
- Recovery supports this module's actual same-process runtime composition on local storage. External runtime recovery and forked Session seeds are rejected.

`registerSummaryPolicy()` registers bounded synchronous, IO-free summaries. `summarizeKnowledge()` supplies only an explicit authorized subset, excluding audience metadata and all ambient Session/channel history. Every target reader is checked before computation and again at publication; exact retries reuse retained output. Residency and model requests are unnecessary, and closing drains accepted summary writes.

Model-backed compaction records its assembled request in `compaction/request` before dispatch. Simulation admits only the exact options stamped by the compaction owner for the active canonical Session transaction, flushes that request, and shares model capacity and token accounting with decisions. Auxiliary reservations retain the compaction identity without creating a world decision; unknown usage survives restart until reconciliation. Writer revocation closes auxiliary admission and cancels only that writer’s streams; retirement keeps the Session and residency charged until provider cleanup and token settlement finish. Altering an owned request’s Session routing or purpose rejects before provider IO. Model-free backends use the same context repair path, including compaction of an original report while its context view remains visible.

`reconcileTask()` reads an existing task from the canonical Team owner and durably retains its identity, revision and phase for an accepted interaction. The first linkage is immutable. Later observations reject stale revisions or changed facts at the same revision. Task execution remains separate from commitment state: only the explicit `task-completed` policy fulfills from a completed task; transfer and creditor-approval policies still require their own evidence. Cancelling a commitment does not cancel the Team task or allow later completion to revive the commitment. Accepted `task/create` operations use the shared outbox attempts, readiness, retry budget and unknown-outcome recovery. The target proof retains the exact task fields, including review policy, and only authorizes Participant tasks under the Team’s grants and limits. The creation receipt identifies the task; it does not prove completion or fulfillment.

`collectCheckpointCandidate(maxDrainRounds, maxAttempts, signal?)` closes new connection admission, pauses scheduling, cancels local turns and drains admitted work while Sessions remain live, then stops local activations through their lifecycle owner. It holds the run cut while collecting and rechecking Team, channel and physical Session references; only observed cursor/source movement is retried. The returned candidate is unpublished and keeps admission closed until `release()`. Release leaves scheduling paused and actors retired. Missing history, unprotected retention, unconfirmed activation quiescence and child-Team owners reject. Collection and restoration verify applied publications against their exact channel records and task receipts against immutable Team creation attribution; independent owner fingerprints alone do not prove these references. The MVP requires owners that retain full history; it does not use per-checkpoint pins or publish a manifest.

`checkpoint(request, signal?)` retains the request and pauses scheduling atomically, collects owners and publishes the manifest with its completed outcome in one run-journal record. Requests carry an implementation version and collector bounds. Pending requests block resume and new external input. Exact terminal retries return the original result; publication failure preserves the previous complete manifest. A manifest binds full run-prefix content, pending responsibilities and protected owner references. Manifests distinguish materialized Session prefixes from unmaterialized canonical identities. Absence is valid only without a run writer or retained Team activation and is rechecked before publication; missing executed history rejects.

`restore(selection, request, signal?)` exclusively opens an existing run, checks the selected completed manifest and implementation version, validates retained Team/channel/Session prefixes and current suffixes, then retires interrupted writers through the lifecycle owner. It returns a caller-owned paused run and connection without model calls or outbox effects. Retries revalidate current suffixes; restoration never rolls back subsequent accepted work. Owner movement retries are bounded; missing, incompatible or changed prefixes reject before execution admission. Restoration closes an interrupted decision window only after controller-proven writer retirement leaves every slot accepted or cancelled. Submitted proposals remain cancellation evidence and are not accepted during restoration; prior accepted intents, released wakes and unresolved token reservations remain durable. A failed window-close write is retryable. A root reservation or completed checkpoint fixes the canonical execution Team even before any entity is bound. Binding, root reservation, checkpoint publication and attachment must agree with that retained identity; an unconfirmed root cannot be published as a complete checkpoint. Collection requires the Team lifecycle owner to match the attached connection and every confirmed run channel to remain listed by the Team. Collection and restoration also require every recorded writer activation id to match retained Team activation history for the canonical Participant and Session, including released writers. Expiry persistence failure cancels only the matching prepared model input, even if failure reporting also throws; it does not fabricate a durable timeout result. Deadline shutdown and actor retirement wait for accepted expiry writes, including decisions already expired before model dispatch. Checkpoint acquisition and connection close drain admitted direct activation calls, including their pre-controller lookups. Cancelling acquisition releases its wait without cancelling accepted startup work. Unpublished Team reservations left by a process exit are reconciled through the lifecycle controller; an unreleased reservation prevents manifest collection even when no run writer exists.

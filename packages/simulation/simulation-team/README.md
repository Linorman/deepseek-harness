## Request budgets and compaction

Optional `requestPolicy` sets `maxOutputTokens`, `safetyMarginTokens`, `inputSafetyFactor` (1–4), and `compactionAttempts` (0–2). It requires the shared TokenMeter. Conversation output is capped before its canonical request header is recorded. Admission prices the full system, tool schemas and messages, keeps the provider-backed meter floor, and checks input × safety factor + output + margin against the smaller of the original Native reservation and known model capacity. An oversized request retains `SIM_REQUEST_BUDGET_EXCEEDED`, cancels its decision, returns the wake and closes a settled window before dispatch. Reported overruns retain their actual charge and immediately cancel the decision with `SIM_TOKEN_RESERVATION_EXCEEDED`.

The actor's compaction provider can compact pressure before the next request within the configured attempt bound. Compaction uses the shared model pool and Native token accounting; failure never creates an unmetered retry. After compaction, the owner restores the current authoritative context and flushes the Session before inference. Original Session events remain retained. A required context that still cannot fit is refused; compression cannot enlarge an immutable run allowance. Omitting `requestPolicy` preserves explicitly composed legacy behavior.

Consumption receipts identify the original context before its single entered input. A later presentation requires a completed compaction summary and its recorded surface replacement, and cannot replace that original consumption. Canonical consumption or persistence failures cancel the decision and retain `SIM_CONTEXT_INTEGRITY`; they stop the Agent rather than entering a model repair loop. New deadline expiries retain `SIM_DECISION_TIMEOUT`, return the wake and close a window whose slots have settled. Existing expiry records without the explicit stop flag retain their original replay semantics. Both stops require explicit operator action before more scheduling.

Observation accepts distinct `sections` names to return only those frozen chapters, in canonical order; this cannot be combined with `detail: full`. For a result decision, submit may carry `notification: {resultId}`. The owner resolves the exact frozen communication, records consumption and submits it; arbitrary text, a different result and conflicting staged actions are refused by the same Native authority checks.

Message staging validates recipient Entity IDs, canonical same-Team bindings and delivery time through the same pure validator used by Native acceptance. Participant IDs are never silently converted. A rejected stage leaves the turn available for a corrected complete proposal list.

A resolution stage must name the request selected by its prepared resolve context. A stale request ID is rejected before submission so the same turn can correct it; final Native authorization remains authoritative.

Staging checks request and apply-plan payloads against the exact domain pin authorized in the current frozen context. It allocates no request or execution lease. A rejected replacement preserves the previously valid staged list; bounded diagnostics report at most eight paths and eight allowed values per issue, without echoing proposed private text. A union with exactly one matching `kind` branch reports that branch's nested field errors; ambiguous unions retain the union diagnostic. Expanded diagnostics retain the same byte and item limits and indicate truncation. Corrected submission still runs Native authority, timing and business validation.

## Model Experience

### Cognition residency

#### What the model sees

`ctx.simulationTeams` creates or resumes the entity's local Agent and Session. A prepared decision contributes its recorded supplementary context and one identified control message; received direct content uses the standard Team projection once. The `tool-simulation` consumer exposes observation, staging and submission. Each control message names its current input identity, requires a fresh observation and distinguishes earlier submissions from the open decision. A no-action decision still stages an empty proposal list and submits it; a prose summary is not acceptance.

#### Token effect

Residency and preparation do not start inference. An admitted request includes the selected context blocks; optional omitted sections cost no model tokens.

#### KV Cache effect

The stable Session survives epoch replacement. Context refresh replaces one prior view while retaining other messages; changing that view invalidates the reusable request prefix from its position.

## Known Limitations and Deferred Work

- Decision selection and authorized context remain caller-owned. Conflict retries supply durable wakes, but decision selection and refreshed context remain caller-owned. Ingress text and its receipt reference are required context only for the decision claiming that input’s consumed event. Ingress does not mutate World facts or grant authority.
- Recovery supports this module's actual same-process runtime composition on local storage. External runtime recovery and forked Session seeds are rejected.

`registerSummaryPolicy()` registers bounded synchronous, IO-free summaries. `summarizeKnowledge()` supplies only an explicit authorized subset, excluding audience metadata and all ambient Session/channel history. Every target reader is checked before computation and again at publication; exact retries reuse retained output. Residency and model requests are unnecessary, and closing drains accepted summary writes.

Model-backed compaction records its assembled request in `compaction/request` before dispatch. Simulation admits only the exact options stamped by the compaction owner for the active canonical Session transaction, flushes that request, and shares model capacity and token accounting with decisions. Auxiliary reservations retain the compaction identity without creating a world decision; unknown usage survives restart until reconciliation. Writer revocation closes auxiliary admission and cancels only that writer’s streams; retirement keeps the Session and residency charged until provider cleanup and token settlement finish. Altering an owned request’s Session routing or purpose rejects before provider IO. Model-free backends use the same context repair path, including compaction of an original report while its context view remains visible.

`assignTask()` explicitly reserves a caller-retained attempt identity before the Hub assigns its canonical task. The selected entity must already be resident. Its runtime-only proof binds the original creation, task revision, actor/epoch, ordinal and lease duration; the Hub rechecks it around policy IO and retains ordinary capability, workspace, budget and retry checks. Assignment neither delivers a model input nor starts inference. Response loss retains the original selection; exact retry reads the same target attempt before another assignment. Known terminal facts remain original receipts.

Controller quiescence retires pending execution links after the old writer stops. Simulation task leases interrupted by that quiescence fail with `SIM_WRITER_RETIRED`; other task releases retain their semantics. Native observations and retirement records remain writable during admitted cleanup. Checkpoints drain assignment IO, retain or retire its responsibilities, and validate target attempts and controller evidence against the captured Team. Safe residency eviction skips an entity with an unresolved task execution. Automatic task selection remains scenario-owned.

`executeTaskDecision()` records ordered decision/predecessor identity and canonical task instructions before creating its input. The required context input section retains exact task/attempt/epoch/source data under the existing `simulation/context-view` Session event and configured context allowance. After the Session inbox flush, a native input receipt authorizes the dedicated Hub attempt start before wake. The same decision retry reuses its logged context and inference result; another decision requires its retained predecessor and reason. Task and decision indexes survive native replay. Model/tool admission rechecks the actual task lease and recorded instructions. Submission leaves world effects pending; applied effects still do not complete the Team task. A registered scenario policy owns completion evidence.

`reconcileTask()` reads a Simulation-created task from the canonical Team owner. Its immutable creator, original idempotency key and accepted creation receipt must match this run. The journal retains creation operation, task revision, phase and current or last settled attempt identity; any observed executor must be the interaction assignee. A completed task requires its exact completed attempt, including review completion. Ordinary Team-created tasks and unrelated receipts reject without changing the interaction or commitment. The first linkage is immutable. Later observations reject stale revisions or changed facts at the same revision. Task execution remains separate from commitment state: only the explicit `task-completed` policy fulfills from a completed task; transfer and creditor-approval policies still require their own evidence. Cancelling a commitment does not cancel the Team task or allow later completion to revive the commitment. Accepted `task/create` operations use the shared outbox attempts, readiness, retry budget and unknown-outcome recovery. The target proof retains the exact task fields, including review policy, and only authorizes Participant tasks under the Team’s grants and limits. The creation receipt identifies the task; it does not prove completion or fulfillment.

`collectCheckpointCandidate(maxDrainRounds, maxAttempts, signal?)` closes new connection admission, pauses scheduling, cancels local turns and drains admitted work while Sessions remain live, then stops local activations through their lifecycle owner. It holds the run cut while collecting and rechecking Team, channel and physical Session references; only observed cursor/source movement is retried. The returned candidate is unpublished and keeps admission closed until `release()`. Release leaves scheduling paused and actors retired. Missing history, unprotected retention, unconfirmed activation quiescence and child-Team owners reject. Collection and restoration verify applied publications against their exact channel records and task receipts against immutable Team creation attribution; independent owner fingerprints alone do not prove these references. The MVP requires owners that retain full history; it does not use per-checkpoint pins or publish a manifest.

`checkpoint(request, signal?)` retains the request and pauses scheduling atomically, collects owners and publishes the manifest with its completed outcome in one run-journal record. Requests carry an implementation version and collector bounds. Pending requests block resume and new external input. Exact terminal retries return the original result; publication failure preserves the previous complete manifest. A manifest binds full run-prefix content, pending responsibilities and protected owner references. Manifests distinguish materialized Session prefixes from unmaterialized canonical identities. Absence is valid only without a run writer or retained Team activation and is rechecked before publication; missing executed history rejects.

Collection and recovery failures identify their actual stage and canonical owner/reference through the [structured native diagnosis](../simulation/README.md). Explicit rule checks supply categories; unknown provider IO is source-unavailable and moving-source errors retain the bounded retry rule. Public diagnostics contain no private error prose or physical paths. Recovery preserves its primary validation error and independent cleanup error, marking cleanup unconfirmed when close fails; failure never permits execution or replaces a successful checkpoint.

`restore(selection, request, signal?)` exclusively opens an existing run, checks the selected completed manifest and implementation version, validates retained Team/channel/Session prefixes and current suffixes, then retires interrupted writers through the lifecycle owner. It returns a caller-owned paused run and connection without model calls or outbox effects. Retries revalidate current suffixes; restoration never rolls back subsequent accepted work. Owner movement retries are bounded; missing, incompatible or changed prefixes reject before execution admission. Restoration closes an interrupted decision window only after controller-proven writer retirement leaves every slot accepted or cancelled. Submitted proposals remain cancellation evidence and are not accepted during restoration; prior accepted intents, released wakes and unresolved token reservations remain durable. A failed window-close write is retryable. A root reservation or completed checkpoint fixes the canonical execution Team even before any entity is bound. Binding, root reservation, checkpoint publication and attachment must agree with that retained identity; an unconfirmed root cannot be published as a complete checkpoint. Collection requires the Team lifecycle owner to match the attached connection and every confirmed run channel to remain listed by the Team. Collection and restoration also require every recorded writer activation id to match retained Team activation history for the canonical Participant and Session, including released writers. Expiry persistence failure cancels only the matching prepared model input, even if failure reporting also throws; it does not fabricate a durable timeout result. Deadline shutdown and actor retirement wait for accepted expiry writes, including decisions already expired before model dispatch. Checkpoint acquisition and connection close drain admitted direct activation calls, including their pre-controller lookups. Cancelling acquisition releases its wait without cancelling accepted startup work. Unpublished Team reservations left by a process exit are reconciled through the lifecycle controller; an unreleased reservation prevents manifest collection even when no run writer exists.

`registerTaskCompletionPolicy()` installs an effect-owned, versioned, bounded synchronous rule over detached frozen world and original-attempt views. `completeTask()` pins that generation, waits for the actor to finish, and records immutable terminal intent before target settlement. Native independently verifies exact associated accepted decisions and applied operations; communication also requires recipient persistence. Submission or publication alone cannot complete a task. The Hub settlement proof rechecks the current writer and retains ordinary result, review, cancellation and budget checks. Accepted-result retries reuse the original intent even after policy removal or response loss, without inference or effect replay. A conflicting terminal attempt remains an interruption; review completion and interaction fulfillment remain separate.

A task decision can select an exact registered deterministic policy. Its cognition choice is immutable in the attempt association; replay rejects a different generation or model/policy substitution. Under the actor maintenance lock, the producer records the prepared context and identified consumed input in the Session, flushes it, and starts the canonical task before pure computation. It creates no model turn or model request. The policy output uses ordinary decision acceptance and world-operation checks; the same completion rules apply after effects. Exact retries reuse retained output.

`assignTask()` can explicitly select an accepted interaction. Native atomically reserves its original attempt and links the canonical pending task, checking the assignee and open commitment. The task keeps that association across retries and later attempts; ordinary tasks cannot acquire one retrospectively. Required context records the association and original reservation source. Completion reconciles newer facts after windows close, waits for required review, and skips closed commitments. Its open-commitment condition is checked again inside the native queue; cancellation cannot cause partial linkage or revive fulfillment. Only `task-completed` derives fulfillment from a completed task.

`simulationTeams.inspectPersonnelObligations(selection, query, signal?)` performs the same cross-owner inventory for a closed run without creating a connection. It rechecks the Native binding and owner cursors, preserves partial coverage on source movement, and drains admitted observations on service disposal. Cancellation suppresses publication; reads never acknowledge deliveries or create task/activation ownership.

`generate(jobId, authorize, signal?)` explicitly executes an accepted Native job in its dedicated canonical Session. The input contains only frozen job material, with no tools or ambient history, and is persisted as `simulation/generation-input` before dispatch. Existing conversation or other-scope history rejects. Calls use the shared FIFO model pool; `simulation/generation-output` flushes before Native output/validation. Retry reconciles a retained Session result without another model call. Connection shutdown cancels and drains admitted generations, retaining unknown responsibility and token reservations. The host must materialize the original Session and authorize every disclosure; generation is not an automatic per-role default. The [ownership note](../../../.agents/notes/implemented/architecture/2026-10-19-world-generation-planners.md) explains isolation and recovery.

A sealed checkpoint collection's `exportArchive(limits)` captures original Native, Team, Channel, materialized Session and canonical image bytes, retaining unmaterialized Session references. Full histories conservatively pin every earlier case, plan, context, cleanup and checkpoint reference; child Teams and Session ancestry outside that closure reject. `planWorldArchive` reports exact bytes and counts with zero reclaimable capacity. `publishWorldArchive` verifies content before atomic location publication, and `readWorldArchive` verifies body and attachment hashes; these APIs never delete source history. `restoreWorldArchive` imports into isolated sibling staging, requires owner-parser validation, closes owners, then publishes the directory atomically. It preserves IDs/events and requires explicit source-to-final-host cwd mapping, recording changed headers in a receipt while preserving the original package. Unknown versions, missing owners, corrupted images, Session headers or image metadata differing from their retained references, and destination collisions reject. Deployment code supplies target owners whose storage roots all lie inside staging; successful retries revalidate the published owners. See [archive ownership](../../../.agents/notes/implemented/architecture/2026-10-19-world-reference-archive.md).

Archive v1 covers exact builtin domain pins, in-process participant runtimes and direct-v4 Channels without custom view providers. External domains additionally require an exact registered `WorldExternalArchiveProvider`; registration of an execution domain alone does not establish portable coverage. Raw archive bodies omit Product creation and Host configuration. Full Product bundles add original creation provenance; the Host-only Product import helper registers the paused target after validation. Provider/preset configuration remains explicit on the target.

### Private full backup and offline conversion

`createWorldBackup(body, limits)` wraps a sealed archive with `world-backup/1` metadata: every Native/Team/Channel/Session cut and version, per-owner hashes, image hashes, domain pins and unmaterialized Session IDs. `verifyWorldBackup` validates the complete closure and manifest within the complete serialized bundle byte budget. Required unknown Session events reject; explicitly ignorable records remain unchanged. Installed owner reducers and providers are validated by the target composition before publication.

External archive providers capture, verify and restore their original private state under the same sealed Native/Team/Session vector. Provider IDs, exact pins, payload hashes and record counts enter the full manifest and aggregate bounds. Harbor's `clocky.harbor.private-backup/1` carries the pinned source, original judge journal/state and bridge inputs/receipts. Missing originals, changed identities, unsafe paths, links or incompatible versions reject; restore uses deployment-selected fresh staging paths. A Native checkpoint retains `external-state-required` until a complete external bundle actually exists. Provider registration is scoped to the installing plugin lifetime.

`publishWorldBackup` writes owner-only files, verifies staged bytes and publishes an immutable content address without overwriting an existing package. Concurrent identical retries share the same result; conflicting bytes reject. `readWorldBackup` checks size, address and manifest before returning private records. Full historical memory may itself contain secrets: the confidentiality policy is private plaintext, requiring owner-only storage or externally managed encryption; keys and executable provider configuration are not included. Source cwd values remain evidence and require explicit target mapping. A redacted dataset cannot use this writable full-backup format.

`restoreWorldBackup` delegates to isolated archive restore and publishes a paused target only after validation. It does not start inference or authorize real external effects. `planWorldBackupMigration` supports exactly `world-archive/1` → `world-backup/1` using `archive-envelope/1`, binding exact input/output hashes and an empty loss set. `migrateWorldBackup` verifies that plan before publishing a new package. Conversion preserves original record values and cannot supply missing approvals, Persona records, senders or receipts. Missing required closure, unsupported formats and changed converter/input reject. The original archive is unchanged. Product-directory registration and target provider/preset routing remain deployment responsibilities.

`migrateWorldNative101` is the separate, explicit `native101-to102/1` offline converter. The host supplies the fixed W0 parser (`0e85170d1236cfe846ebc3b88a073d848903fb47`) and current pure validators. Both replays must reproduce the exact archived paused projection. The target changes the physical journal descriptor and adds creation provenance; all original IDs, sequences, record values and historical checkpoint manifests remain evidence. A retained historical context profile applies only inside the hashed original cut; new contexts use current rules. Native verifies every original prefix entry before returning a projection. Unknown domain profiles, missing source/external state or mismatched replay reject. Ordinary backends continue to refuse format 101. `publishWorldNative101` retains exact raw source bytes, a complete conversion proof and the target bundle under separate immutable content hashes. Restore still requires an isolated target, fresh checkpoint and explicit start; conversion never resumes the original run.

`createWorldExperimentBranch` creates a paused branch from an owner-validated initial-world or settled-world archive cut. It replays the immutable Native prefix through the installed provider without accessing original storage and rejects active writers, unresolved effects and responsibilities without a supported seed owner. The immutable `run/branch-init` records parent hash/revision, command namespace, memory policy, explicit intervention and budget before new owner allocation. Exact retries reopen that namespace and reconcile reserved identities and inherited input. Inherited Sessions are prepared detached and persisted before runtime attachment; seed actors resume those actual logs on first activation, while later generated actors use normal fresh startup. Writer epochs are scoped by the new run/entity even when their decimal counters independently begin at one. Entities receive explicit lineage identities; Team, Participant, Session and Channel owners allocate fresh writable identities. Current entities, relations and balances are initialized through ordinary Native commands; dynamic text facts cite the new branch-init event and inherited private knowledge becomes a newly recorded belief; original proofs and receipts remain in read-only provenance. The exact parent archive is retained in a dedicated storage owner and included recursively in branch exports; complete bytes, aggregate entries and an eight-parent depth limit bound that closure.

The supported intervention is `public-facts` versus `authorized-memory`. Both retain authored profiles and scenario facts; public-facts omits initial private knowledge and all parent Session events. Authorized-memory supports textual Session history only, rejects media and nontext content blocks during pure preflight, and uses a detached `Session.create(...).deriveMessages()` to quote only each original actor's actual model-history messages into a new persisted `user/message`, with source cut and policy. It does not reuse parent Session events as executable proofs. Callers supply a current whole-record grant around every operation; branches default to no real effects. This policy is not a general redaction of authored profiles. Pending obligations/events, federation sources/provenance, institution/committee/external/environment/evolution seed owners, arbitrary model interventions, total lifetime token budgeting and automatic history merges are unsupported. Settled-world seeds preserve simulated cut time and refuse unsupported state rather than silently dropping it.

`buildWorldCausalIndex` reads real Native `event/queued`, `decision/opened`, `operation/intent` and `operation/settled` records. It ignores mutable snapshot relationships and uses the B1 length-delimited prefix hash. Resolve actions retain their explicit request reference; absent inception or receipt sources stay unknown. The index is disposable. `queryWorldCausalIndex` recomputes source permissions and bounds depth, node count and complete response bytes. `compareWorldExperiments` requires the same parent commitment, uses explicit lineage ID fields without rewriting free text, separates fact/resource/personnel/policy changes, reports quality/cost as unknown when evaluator evidence is absent, and never asserts causation from correlation.

Ordinary full bundles reject Native federation-time evidence in the current run or any retained provenance, including a journal fence omitted from the supplied snapshot. That dependency requires a complete federation checkpoint with the original mailbox prefixes. Raw `exportArchive` remains available as a component of that composite format; neither ordinary bundle verification nor envelope migration may label an incomplete federated closure as a full backup.

Experiment initialization and inherited-input payloads use version 2. Version 1 initialization is rejected by Native replay; the previous raw-event memory format is never migrated or rewritten. Ordinary current-format runs without branch initialization remain readable; Native 101 requires the explicit offline converter. Entity references follow declared schema fields; resource, fact, knowledge, relation and template IDs retain their own run-local domains, and authored text/Persona names remain byte-exact. Missing declared Entity owners reject during pure preflight.

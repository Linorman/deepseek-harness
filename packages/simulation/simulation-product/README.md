Public frozen context items expose this ordinal. Native and Team provider bounds remain independent. Reads never publish, acknowledge, activate or claim recipient consumption.

`readRecords()` / `simulation.records.list` reads original native journal sequences through actor-free metadata/original modes, optional exact sequence/kind, revision and cursor. `totalRecords` counts filtered records; original bodies split into ordered Unicode-safe JSON text parts under `maxContextPartBytes`. The complete response, including policy tags and encrypted continuation, uses `maxBytes`; a single part that cannot fit is refused. Ordinary registration ownership and entity `contextReaders` never authorize original journal bodies. Separate trusted `recordReaders` entries name the authenticated principal and optional owned run; they grant **whole-run historical content**, including old private inputs, contexts and deployment reservations. This administrative permission does not inherit entity audience limits and must not be assigned as a substitute for entity-scoped knowledge access. `context-readers` accepts an independent `recordReaders` list for disposable deployment policy. Revocation invalidates `readVersion`, wakes watches and rejects held replies and old cursors. Metadata mode always withholds original JSON even when this grant exists. Original content is text for inspection or export, never executable markup; native private values are not public structured DTO fields.

## Registration and authorization

Deployment `imports` associate an opaque product ID and display name with one immutable provider/run spec and owning product principal. Browser requests accept only product IDs and query parameters. Directory stream format 1 retains registrations and timestamps; restart replays the complete prefix, rejects corruption, duplicates and changed configurations, and reuses exact registrations. Removing an import from configuration does not delete or transfer its retained registration. Each provider/run pair has one product identity on this directory.

`directoryStream` is required and uses its Storage Log backend route. `maxRuns` bounds retained registrations. `recoveryPageSize` bounds replay pages. `maxDirectoryEntryBytes` checks each complete UTF-8 JSON registration during import and replay independently of public response limits. Initialization must finish before the service becomes active; unload closes read admission, drains admitted work, then closes its stream.

Every call requires a transport-authenticated `AuthenticatedProductCall`. Only the registration's owning principal can list or inspect it. Missing and private product IDs share the same refusal. Cancellation or credential retirement rejects reads before provider IO and after either its success or failure. Callers must obtain each call through the principal lease; an opaque product ID grants no authority.

## Public reads

`retryOperation()` accepts only an owned original creation with a held administration owner and an exact unknown due external intent. The durable command retains `runId`, trimmed `commandId`, `operationId`, a positive `expectedAttemptCount` and normalized nonempty reason. Native receives a stable derived grant id and the original product `acceptedAt`; lost replies reuse that same payload and cannot add another allowance. `request()` exposes the original `retryOperation` input alongside its `retry-operation` receipt. Cold accepted requests remain inert until explicit owner restoration and an authenticated retry of the same command. Grant and query never publish or infer; a stalled/paused run needs explicit start afterward. Operation execution details expose current retry reason, count fence and unchanged bound; an effect-owned metadata reader supplies owner/capacity admission and retires on unload. These read hints do not authorize later mutation. See the [retry permission decision](../../../.agents/notes/implemented/architecture/2026-10-01-simulation-original-outbox-retry.md).

`list()` reads directory metadata without inspecting provider journals. Search covers registered names; IDs sort by ordinal string order. Pages bind search, limit, directory revision, principal issuer/subject/ID, credential generation and service lifetime to an encrypted cursor. Replaced or tampered cursors reject with a first-page restart instruction. No public summary contains provider paths, the private spec, principal association or physical scan counts. Names use `maxTextBytes` and explicitly report truncation.

`inspect()` resolves the registered provider/spec and invokes native read-only inspection. Missing history is distinct from inaccessible identity or unavailable/corrupt history; discovery remains possible when inspection is unsupported. World output includes exact decimal time, bounded tick/rule/policy labels, ownership, counts and observation time. `world.metrics` derives current granted interval limits and actual admissions from the same Native budget functions, including charged reservations and unknown token attempts. Slot usage retains reserved/active/revoked writers until release; recovery counts distinguish unresolved confirmation. Pending decisions include open/submitted decisions and queued/reserved nominations; external counts include unsettled communication/task-create intents and explicit unknown outcomes. A scheduler stop exposes only its fixed code and recovery action. Private profiles, context, instructions, paths and raw configuration are omitted. Older peers may omit new fields; omission or unsafe numeric accounting is unavailable, never inferred zero. Ownership grants no takeover, and persisted running phase does not imply active scheduling.

`runStatuses({ runIds })` observes one finite directory window in request order. IDs must be distinct, owned registrations, at most `maxPageSize`; `maxBytes` bounds the complete request and response. Independent provider or accounting failures produce safe per-run `unavailable` summaries, while missing history remains `missing`. Every item checks authorization around IO; credential retirement rejects the complete batch. Disposal drains all admitted provider reads even after another item fails. This method never opens, restores or drives a run. Native-only results explicitly mark administrative scheduling and shared model-pool observations unavailable; an installed administration owner may enrich those observations from its own current metadata without per-row control calls. See the [status observation decision](../../../.agents/notes/implemented/architecture/2026-10-01-simulation-runtime-status-observations.md).

`maxPendingReads` bounds all admitted reads, including initialization waiters. Reads proceed independently; slow history observation does not block directory discovery. `maxPageSize` bounds public rows and `maxBytes` checks complete public JSON requests and results, including cursors and wrappers. A row that cannot fit is refused. Native provider inspection retains its separate history limits and validation. [Configuration defaults](../../../docs/config-catalog.md) are generated from the schema.

`browse()` supplies entities, decisions, operations and checkpoints through `simulation.collections.list`. Filters are collection-specific; decision slots use exact decimal ordering, operations follow their parent decision slot and local index, and checkpoints follow their retained request sequence. Each page carries one `snapshotRevision` and the complete filtered total. Continuations bind the registered run, collection, filters, limit, revision and current credential; changes require explicit first-page refresh through `simulation-product-stale`. Missing native history is unavailable, while an observed successful empty collection has total zero.

`inspectObject()` supplies exact metadata through `simulation.objects.inspect`: entity identity/binding or relationships, decision execution/accounting or frozen context, operation execution or technical attempts, and checkpoint references. Optional `expectedRevision` fences the read observation; it grants no write CAS. Relationships, context parts/references, attempts and checkpoint references paginate independently, and their complete outer section wrappers share `maxBytes`. Unknown and other-run object IDs share missing status. Source references grant no Team/Session content access. Only public entity name labels are selected; arbitrary profile bodies, complete model requests, current knowledge, attempt diagnostics, storage streams and fingerprints remain withheld. The context section has its own explicit body-disclosure rule below.

Decision submission/acceptance is distinct from applied effects. Operation output separates publication, Session input persistence, recipient receipt, task creation and retained delivery-failure resolution. None asserts recipient business processing or task completion. Checkpoint completion means a retained manifest; `sourceValidation: 'not-performed'` explicitly avoids claiming current cross-owner validation. Decision real inference times remain distinct from its simulation time. Context accounting is metadata with `content: 'withheld'`, not the complete model request.

The fetch carrier exposes `client.simulations.list/inspect/browse/inspectObject`. Browser DTOs and parsers use `./types` and `./schema`, which include no Host Cordis declarations. Private registration types remain in the root Host entry. Host dispatch resolves current authentication for each call and maps forbidden, invalid, unavailable and stale failures separately; unknown failures omit internal diagnostics. An undeployed directory returns unavailable. Response parsing rejects substituted run, collection, object, section or selected revision.

## Relationships and frozen context

The `relationships` entity section returns incoming, outgoing and scoped relations in stable ID order. It retains original half-open validity intervals and marks activity at the observed simulation time using exact decimal comparison. It neither changes topology nor grants authority through an endpoint link.

The `context` decision section reads the exact retained context view, its original projection/version/clock metadata, knowledge-version references and Run/Team Envelope sources. It does not retrieve current knowledge or claim to show the entire model request. Ordinary run ownership permits metadata only. Trusted `contextReaders` entries separately select `principalId`, `entityIds` and optional product `runId`; omitted run selection covers only that principal’s own registrations. There is no browser-supplied grant or body switch. Configuration is validated and copied before IO. Retired credentials reject pending reads; service unload redacts accepted context text that can still settle as metadata. Policy retirement does not impersonate principal replacement or discard unrelated original commands.

Authorized recorded plain text is split into ordered block parts under `maxContextPartBytes` (default 16384, minimum 4 UTF-8 bytes). Unicode scalars are never divided; exact parts can be reassembled without label truncation. Redacted and unsupported blocks contain no original payload. The complete section envelope still obeys `maxBytes`; an oversized row rejects explicitly. Context continuation binds body permission and part allowance in addition to object/revision/credential/service identity. A first-page refresh removes the observation fence. Historical context permission does not authorize current knowledge retrieval or source Team/Session bodies.

## Current and selected knowledge

The entity `knowledge` section selects current temporally visible records. The decision section uses the exact versions originally recorded in its prepared context and may select one `reference` without traversing pages. An unrelated reference has the same missing status as unknown data; no newer version is substituted. Both paths share the native `knowledgeVisible/selectKnowledge` projection in the Simulation definition package. Current audience, latest-version revocation, temporal bounds and every derivation premise still apply to historical retrieval.

A reader’s optional `content` selects `context`, `knowledge` and `sources`; omission preserves context-only permission. Knowledge bodies require explicit `knowledge` permission. Report source text additionally requires `sources` and an exact retained communication/durable-delivery match; it exposes only that original text, not channel history, private diagnostics or arbitrary source data. Provenance distinguishes observations, delivered reports, beliefs, inference and summaries from authoritative world facts. Parts and complete wrappers remain bounded; policy, frozen reference and world revision bind continuations. Knowledge caches are released on later world observations because audiences can change independently of deployment policy.

## Bounded invalidation waits

`watch()` and `simulation.changes.watch` return only the current read-policy identity, world revision or explicit missing/unavailable status, and a credential-bound continuation. `waitMs: 0` is an immediate probe; the Host clamps other waits under `maxWatchWaitMs` (default 20000 real milliseconds). `watchPollMs` (default 2000) bounds native observations, and `maxWatchers` (default 32) separately bounds admitted waits. Sleeping watches do not occupy ordinary read admission; their native probes do. A native IO already admitted can outlast the wait interval. Credential retirement rejects, service unload cancels and drains, and neither path opens execution. A foreign/expired continuation returns reset and a fresh cursor without publishing old-policy data.

The opt-in `./context-readers` plugin independently registers trusted `readers` through a process-local capability; discovering that capability has no grant effect and it cannot cross JSON. Contributions augment base `contextReaders` only while mounted. Reload/removal changes the policy version, wakes waiting observers and fences context continuations and pending bodies without replacing the directory, execution owner or browser module. Caller-owned input is copied and strictly validated. Browser runtime releases old text on reset, ignores obsolete tagged replies and automatically rechecks the selected context; unrelated drafts and uncertain original commands survive. Ordinary network loss retains marked readable data; a confirmed unavailable policy clears private text.

## Persistent company creation

The explicit `./administration` plugin provides `ctx.simulationAdministration` and Host fetch `catalog/preflight/create/prepare/request`. It requires the read directory, native Simulation/Team owners, the LLM registry and Agent Presets. Its trusted `templates` contain version 1 procurement settings, the complete native policy, preset, driver route/offsets and checkpoint bounds. Activation validates native inspection, preset resolution and template structure without requiring any registered model provider. Installed `driver.model` is either an explicit `{ provider, name }` route or `{ source: 'agent-default' }`; the latter reads `agentDefaultModel.currentSelection()` at preview and admission, mapping its `model` ID to driver `name`. Catalog and preflight expose strict `readiness`: `ready` with a route, `needs-model`, or `unavailable` with a safe reason. Metadata lookup performs no inference or automatic connection test. Explicit reasoning-effort overrides are unsupported by company activation and return `reasoning-unsupported`; provider default behavior is supported. Browser requests contain command identity, installed template/version, display names, canonical positive initial stock and explicitly editable allowances; arbitrary specs, paths, code and credentials reject.

Trusted `editableLimits` names permitted reductions of `maxEntities`, `maxResidentActors`, `tokensPerModelRequest`, `maxTokensPerInterval` and canonical decimal `maxTime`; omission freezes every allowance. Installed spec values are defaults and maxima. The catalog publishes these limits, the allowlist, tick/budget units, policy versions and current shared model capacity. `preflight()` accepts creation semantics without `commandId` or `expectedModel`, returning resolved configuration or bounded issues with machine-readable field/code. It validates scene capacity, one-request token admission for model procurement, completion horizon, stock, providers, preset and current product capacity, without journal writes, identities, Teams, actors, inference or permit reservations. Deterministic-only task workflows permit a zero interval token budget and make no model requests. Create rechecks the same allowance rules at durable acceptance; a ready preview is no reservation. Limits cannot change clock definition, routing or Host shared permits. The original public choices and full resolved native spec persist together; later template edits cannot change retries or recovery.

Create requires `expectedModel` matching the route shown to the caller. It rechecks that route, authorization and capacity at the serialized acceptance position. A mismatch returns `SIMULATION_PRODUCT_MODEL_CHANGED` (`simulation-product-model-changed` over RPC), proving that this attempt allocated no run; the caller must review and confirm again. Network uncertainty retains the original identity. Exact accepted retries compare the confirmation with the frozen driver before consulting current defaults, templates or model availability.

The required `journalStream` uses a separate format 2 command journal. Its structure is unchanged: durable semantic input omits the redundant confirmation, whose exact route is reconstructable from the frozen driver. Deployment selectors never enter that driver or native spec. No format conversion or automatic rewrite occurs. Acceptance persists the original principal, allocated product/native identity and full immutable template resolution before directory registration or native IO. Exact retries require the original owner and payload and return that request's retained state. A lost or retired HTTP waiter does not cancel accepted preparation. `request()` only reads the original journal result; `not-found` is not proof of failure. Later attempts cannot replace a failed outcome. A distinct `prepare()` command reconciles the original run and uses its own checkpoint identity.

Preparation holds at most one exclusive native handle per allocated run. It fills missing topology and publishes a complete initial checkpoint, leaves the run paused and keeps no actor or temporary Team connection resident. A currently held run can collect another explicit preparation checkpoint. Foreign ownership returns `recovery-required` without takeover; partial preparation failure returns `preparation-required` after confirmed close. A failed terminal append retains `accepted`; explicit exact retry can reconcile the original allocation. Startup replays commands and registers discovery without opening native runs or resuming models.

`listRequests()` / `simulation.requests.list` discovers receipt-only administration history for one run under its current authenticated owner. `maxRequestPageSize` defaults to 32; `maxBytes` bounds complete requests and pages. Rows sort by original acceptance time and command identity. `snapshotRevision` counts that run’s accepted and terminal journal entries, independently of native world revision and unrelated runs. Encrypted continuations bind run, page bound, journal revision, principal generation and service lifetime; changed observations require first-page refresh. No original parameters, input text, review reason, native writer or model work is exposed or created.

`retryRequest()` / `simulation.requests.retry` takes only the selected run and original command ID. Unknown, foreign and cross-run selections share refusal and cannot allocate anything. Terminal receipts remain unchanged. Accepted originals dispatch their retained exact inputs through the existing create, prepare, checkpoint, restore, review or operation-retry method, preserving each method’s ownership, admission, serialization and waiter rules. Cold accepted review and operation-retry commands require explicit restoration of the run owner before this retry. Reauthentication discovers durable facts under the new credential; it never retains stale credentials or restores old private browser drafts.

`maxCommands` and `maxEntryBytes` bound retained intents and complete journal entries during acceptance/recovery; history must retain a contiguous prefix. `maxPendingPreparations` bounds durable pending attempts, and `maxHeldRuns` counts unique pending/held runs before allocation. `maxPendingRequests`, `maxBytes` and `maxTextBytes` independently bound transport waits, complete public payloads/results and catalog labels. ## Product scheduling ownership

Control observations include a redacted immutable model/budget summary: provider/model, reserved tokens per request, per-interval token allowance, exact decimal interval, resident limit and current configured shared-host model concurrency limit. These fields grant no configuration authority. The caller confirms this summary before explicitly starting; native admission still rechecks the live owner and budgets.

`ctx.simulationAdministration.control/manage/managementRequest` and Host fetch `control/manage/managementRequest` observe and control original product creations. `manage()` accepts an opaque `managementId` and `paused` or `running`, with native ordered semantics and no proxy-only revision CAS. The native run journal retains the original request and terminal result; a completed retry returns that historical result alongside a separate current control observation. Changed phase under the same ID rejects. Read-only queries work after restart without opening or resuming the run; a new cold scheduling request requires explicit recovery.

Each successfully prepared run has one product owner. Construction and reads allocate no connection or model work. An authorized start checks current model and actual in-process runtime registration, preparation progress and the complete checkpoint anchor, attaches one canonical Team connection and schedules bounded company-driver batches. Pause stops future timer admission while accepted inference or cleanup can remain in flight; the response reports that work separately. A failed initial preparation may use a new completed preparation checkpoint as its anchor without rewriting the original failure. Preparation and management share the owner queue; preparation cannot replace an attached scheduler.

`driverIntervalMs` controls real time between productive batches; `driverRetryMs` bounds observations of temporary capacity and transport retry. Native retry timestamps are respected, and the native driver rechecks them. Completed, unknown, recovery, stalled and scenario-blocked results require explicit intervention rather than automatic repeated inference. `maxManagementRequestsPerRun` bounds retained native scheduling identities; original retries and reads remain available at capacity. Public observations withhold exception text. Carrier retirement affects only its waiter. Service unload closes owner admission, cancels supported connection work, drains accepted management/model work and then releases native runs; unconfirmed connection retirement retains ownership.

`control().modelPool` observes real-time Host-wide active permits, queued requests and their limits through the existing model admission owner. It is independent of per-run simulated interval usage in native inspection metrics and of the immutable budget caps in `control().budget`. Pausing scheduling does not release an admitted model permit; confirmed stream cleanup does. Observed zero is a measured value, while absent or failed observations explicitly report `unavailable` without counts. Older peers may omit new fields.

`control().versions` comes from the original immutable spec and trusted company template, with bounded rule/policy/tick labels and scenario/template/driver versions. Observed scenario metadata includes the immutable `cognition-only` or `automatic-tasks` execution mode from the retained creation driver; the current catalog and task counts do not determine it. Administrative `runStatuses()` enriches one authorized native batch with these scenario identities and current owner/driver/in-flight/stop/retry metadata, plus one shared model-pool observation. A readable imported run with no company creation remains readable and reports scenario/administration unavailable. Metadata reads never acquire owners, restore checkpoints or infer scenario identity from display names. Cold known-company metadata retains its trusted version and reports `not-held` without scheduling models.

## Checkpoints, recovery and input

Failed checkpoint/restore receipts and checkpoint details expose only the recorded safe stage, category and source reference; private native error text remains withheld.

`control().administration` returns separate current checkpoint/recovery/preparation/input hints from native ownership, retained request capacity and lifecycle. Recovery exposes a compatible full anchor ID, real publication time, exact simulated time, prefix revision and source counts; actual source/suffix verification still belongs to explicit restore. Ingress exposes only current allowed entities, exact horizon and complete native byte allowance, with bounded public names. These hints grant no write authority and every operation rechecks admission.

`checkpoint()` accepts only original run/command identity and derives `product-checkpoint/<commandId>` plus collector policy from retained creation settings. `restore()` selects an existing full checkpoint with a new or exact-retried command; implementation version and owner selection remain server-derived. Both persist accepted intent before native IO and return the same `SimulationProductRequestReceipt` used by `request()`. Its closed kinds include `checkpoint` and `restore`, whose receipts carry their exact checkpoint ID. Terminal failures retain their original category and identity; a failed request requires a distinct attempt rather than reviving its old result.

Collection shares the product owner admission queue, closes future driver admission, pauses the native run, cancels/drains supported inference, retires writers and publishes the existing complete cross-owner manifest. Success closes its temporary connection and remains paused; failure preserves the latest successful anchor. An interrupted accepted collection can resume on its original identity only after validating a retained full checkpoint and the current suffix. Recovery validates a compatible full anchor before retiring a held run, then uses the native Team restoration path to revalidate Run/Team/Channel/Session sources and retire old writers. It restores current facts without rollback or inference. Same-command terminal retries return the historical result; a fresh recovery command performs fresh validation. Unconfirmed cleanup retains native ownership responsibility.

`ingress()` accepts one allowed company entity (`buyer` or `supplier`), original ingress ID, text and canonical decimal earliest time. Source comes from the authenticated principal; no browser attribution, broadcast, world mutation or route override is accepted. The native input/event append preserves original assignment. `ingressRequest()` reads pending/claimed/consumed/cancelled facts and associated decision independently of text visibility. A collected event is not reported consumed until its wake is completed. New input requires a prepared or recovered owner; original input queries/retries remain read-only on cold history. The input does not change scheduling phase. A running completed scenario can process a new future input through bounded driver batches, while a paused run waits for explicit start.

`maxIngressRequestsPerRun` bounds retained native input identities, including completed ones. Exact retries and queries remain available at capacity. Actor input text and principal details are absent from public receipts, and all original run/command/checkpoint/entity/time references are checked by the typed Host carrier. ## Automatic task batches

`SimulationTaskExecutor` consumes accepted `task/create` operations with canonical Team receipts. Its trusted version 1 settings map each source entity to an execution entity and optional exact creation operation (multiple routes from one source require distinct exact operations), deterministic cognition, a completion policy generation and explicit interaction. Task text selects none of these. `maxControlSteps` bounds control iterations, `maxDecisionsPerAttempt` bounds cognition within one attempt (default `1`), and `leaseDurationMs` fixes the original assignment lease. The caller supplies its canonical task reader, authorized context, placement and lifetime; it owns the prepared run, connection, cadence and checkpoint admission.

Construction and paused batches do not activate or infer. Running batches check dependencies, establish residency, reserve one stable attempt before assignment, deliver recorded task input, execute scoped decisions, apply currently due operations and settle only evidenced results. Response loss reuses the original attempt, decision and result intent; route changes reject against retained facts. Review, missing completion evidence, cancellation, technical retry, unknown effects and writer recovery have separate stops. The validated `retry` policy defaults to `never`. `before-effects` permits a physically retired attempt to be replaced only before any world-operation intent is accepted. `scene` requires a trusted synchronous recovery function over frozen facts after driving original accepted operations. Team cancellation, remaining attempts and native source/writer checks still gate replacement. Physically retired attempts use distinct epoch-qualified identities; accepted world effects retain their original identities. The scene scheduler advances future due effects.

The optional trusted synchronous `nextDecision` callback reads frozen run/execution facts only after an accepted decision remains running with missing completion evidence. It explicitly returns `waiting`, `blocked`, or a new decision with a reason and optional cognition policy. Missing callbacks and `waiting` admit no cognition; `blocked` and requests beyond the attempt decision limit return `task-blocked`. A selected successor retains its predecessor, reason, policy and task instructions before execution; response loss resumes the last retained decision without selecting or executing it again. Each successor consumes a control step and the existing native budgets.

A canonical reviewer returning the latest completed attempt to `pending` authorizes a distinct next attempt, subject to cancellation, dependencies and `maxAttempts`. It does not revive the old attempt or change its result. Pending review admits no new cognition. Scene completion and native interaction authority still apply: rework cannot repeat an already fulfilled transfer through an unsupported continuation. The company template remains a single-decision, no-review scenario. See the [progression decision](../../../.agents/notes/implemented/feature/2026-10-01-simulation-task-progression.md).

`advance()` coalesces a serial batch and `drain()` awaits accepted work. Owner retirement and pause are rechecked after awaited admission work. The executor allocates no background timer and does not open or restore a run. The [Loader scenario](../../../examples/simulation-company/tests/task-executor.snapshot.ts) exercises actual automatic attempts and completion with both model and deterministic cognition; the [product task scenario](../../../examples/simulation-company/tests/product-task.snapshot.ts) exercises background scheduling and nine cross-owner process-exit points. Catalog entries report `cognition-only` or `automatic-tasks` from the installed template, and Web/SDK clients preserve that mode.

## Company task mode

The optional trusted `driver.tasks` config fixes version `1`, `cognition` (`model` or `deterministic`), `leaseDurationMs`, `maxAttempts` and `retry`. It replaces direct transfer cognition with one scoped Team task creation and execution. The company task has no filesystem scopes, uses the shared workspace and defaults to no review; the trusted `review: buyer` mode freezes the buyer participant as reviewer. Browser creation accepts no task/executor configuration. The administration owner registers the exact scene policies under its effect lifetime, retains the original template resolution and drives tasks through its existing serial timer and checkpoint admission.

Scene recovery starts a new attempt only after the old writer is physically retired and original effects are reconciled. Before effects it retries the task; after the original transfer fulfills the purchase, it records an empty acknowledgement with the new input and epoch. Native independently restricts this `continuation` to the original task's retired-assignee transfer evidence and rejects new world proposals. Completion references the original transfer, leaves the failed old attempt intact and does not rewrite the closed commitment. Exhausted attempts, cancellation, unknown results or unsupported effects remain explicit stops. An accepted target completion is reconciled without another attempt or task-model request.

Trusted report workflows may recover an applied report through `reportContinuation` after the latest interrupted attempt is physically retired. Native verifies the same run, original creation, executor, participant, Session, original prepared-context fingerprint and durable recipient receipt. The fresh attempt records that selector in required input and accepts only an empty acknowledgement; completion consumes the original report without republishing. ## Trusted report workflows

An installed `driver.scenario` of kind `task-workflow`, version `1`, selects up to 64 sequential report steps instead of procurement. Each uniquely named step fixes its task creator, executor, recipient, channel, optional reviewer, task instructions, report text, lease, attempt bound and retry mode. The company foundation supplies `buyer`/`supplier` and `purchase`; optional trusted `scenario.topology` adds up to 30 actors (`id`, `name`) and 31 channels (`key`, distinct `members` with `entityId`/`role`), for at most 32 actors/channels. Extra actors inherit the single installed in-process participant preset/model with no capabilities; channel limits remain empty. All route identities and report sender/recipient membership validate at load; executors cannot receive or review their own reports. Workflows require two resident actors and cannot coexist with `driver.tasks`. Public creation accepts only the installed template identity and permitted parameters. Catalog entries expose `kind: task-workflow`, `cognition: deterministic` and `review: participant` when any step selects a reviewer.

Preparation, admission and single-target ingress resolve the same complete topology. Entity capacity must cover every installed actor; two resident slots suffice for sequential report delivery and independent human review. The original driver and preparation retain matching topology, so changed deployment names/routes cannot alter an existing run. Initial preparation reconciles each actor/channel reservation without inference, and complete checkpoint/restore includes every participant Session and channel. Reviewer identity must differ from the executor and may be an independent third actor.

Workflow cognition is deterministic only. Creation, report and notification acknowledgement proposals are recorded as authorized context before computation; no arbitrary model proposals or ordinary Team tools are admitted. Completion verifies the attempt’s single exact accepted report and matching native outbox/recipient Session receipts. Review derives its entity from that immutable step and exposes report operation/delivery metadata without inventory evidence or report text. Rework creates a new bounded attempt containing canonical feedback. Later steps wait for the preceding task’s canonical completion. Interrupted attempts use only `never` or `before-effects` recovery; already accepted effects cannot be repeated through a fresh attempt.

Completed report tasks do not discard accepted future inputs. A pending ingress keeps the driver active: it advances to the earliest pending native event using exact decimal ticks, then records an empty acknowledgement for the selected actor. Paused runs consume nothing until explicit resume. Retrying the original consumed input preserves its receipt and decision; it does not create another report, task or resource effect.

## Known Limitations and Deferred Work

- Access is one owning authenticated principal per immutable registration. ACL changes, shared roles and registration removal require separately designed durable operations.
- Directory lists carry unobserved metadata; they do not claim current world status. Inspection replays bounded full native history, so there is no performance or supported-scale claim.
- Other entity kinds, arbitrary participant grants/providers, additional effect/completion kinds, model-driven report workflows and the complete new-scene Web/process-exit recovery matrix remain deferred. Model-driven workflows require native operation admission for the exact scene before world effects apply. Public creation selects an installed scene without altering its frozen strategy. The [product-directory decision](../../../.agents/notes/implemented/architecture/2026-09-29-simulation-product-directory.md) owns metadata authorization and redaction.

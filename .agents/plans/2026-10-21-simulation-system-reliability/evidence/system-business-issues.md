## 2. 状态和优先级定义

- **已修复**：有具体代码改动及相应验证；只在已验证范围内成立。
- **已缓解**：通过配置或局部优化使本次运行继续，根本效率或扩展性问题仍存在。
- **未解决**：现象有证据，尚无完成并验证的修复。
- **待验证**：缺少足够覆盖，不能直接认定为已发生缺陷。
- **外部原因**：不由项目代码直接修复，但项目仍需提供正确处理和解释。

优先级表示下一轮处理顺序：P0 为停止控制或重要状态可信度；P1 为运行可靠性、恢复和成本；P2 为效率完善与覆盖扩展。优先级不代表已发生数据损坏。

## 3. 详细问题

### SYS-01：独立裁判案例缺少 Simulation 接入

**状态：已修复基础接入，完整长程验收待验证。优先级：P1。**

**现象与影响：** 河港目录包含可执行裁判和自己的日志、视图、检查点，不是可直接导入的 World 定义。如果把它简化成预制事件或由一个模型代替所有主体，就改变了案例的独立决策和信息隔离要求。

**原因：** 原案例环境协议与 Simulation 的领域请求、执行器和恢复生命周期之间缺少适配。

**已做修复：** 增加可选 Harbor provider，通过已有扩展点注册领域和执行器；校验固定源码清单，为每个运行隔离原始裁判目录；记录公开观测和各角色私有视图；由独立 Session 做业务选择，Host 绑定真实 Team/Session 身份。裁判命令串行执行，保留幂等执行身份与不确定结果责任。

**剩余边界：** 新创建的案例主体仍由创始者 Session 代表，不能宣称它拥有新的独立认知。备份必须同时保留案例目录、Native 和 Team/Session 数据。本次第 12 天结果不能替代全年验收。

**后续验收：** 用原始审计验证完整运行；抽样核对私有信息可见范围、真实身份和动作依据；恢复不允许遗漏原始裁判日志或重新初始化世界。

**责任入口：** [Harbor 接入说明](../../.agents/notes/implemented/feature/2026-10-21-harbor-original-judge.md)、[provider](../../packages/simulation/simulation-world/src/harbor.ts)、[裁判桥接](../../packages/simulation/simulation-world/src/harbor-case.ts)。

### SYS-02：模型混淆新决策与旧提交，反复确认而不推进

**状态：已修复主要诱因，模型行为仍需持续观察。优先级：P1。**

**现象与影响：** 恢复后的 Session 保留旧提交结果，模型可能把新唤醒当成对上次任务的总结；另有确认消息引发继续确认的情况。表现为新决策未提交、时间不前进、额外推理消耗，最终可能触发期限或额度限制。

**已做修复：** 每次输入明确当前 `inputId`，要求观察并提交本次决策；旧结果不能完成新决策；没有效果也需要显式空提案提交。预设要求交流新增信息、必要问题或变更提案，减少无新增信息的确认循环。

**剩余边界：** 提示词改善不是确定性保证，不能把最终文字响应自动当成空决策。后续应区分业务决策、结果收尾、纯消息等推理成本，而不是用总调用次数判断业务进度。

**验收：** 保留旧历史后发出新决策，必须形成新的观察和提交证据；断点恢复保留原输入身份；确有新增信息的消息仍能正常送达。

**责任入口：** [决策输入](../../packages/simulation/simulation-team/src/input.ts)、[决策边界说明](../../.agents/notes/implemented/bug-fix/2026-10-21-simulation-decision-boundaries.md)。

### SYS-03：暂存与提交边界不清、错误参数纠正成本高

**状态：已修复提示和诊断，错误参数仍会出现。优先级：P1。**

**现象与影响：** 模型反复调用暂存而不提交；复杂 resolution 结构出错时，泛化 schema 提示难以指导修正。后续北区请求仍出现字段层级错误、缺少 `after`、错误 `command.kind`，但通过现有错误返回最终修正并被裁判接受。

**已做修复：** 工具说明明确暂存没有业务效果，最终需要提交；对带共同判别字段的 schema 提供更准确的分支错误定位，同时维持严格校验。

**剩余问题：** 模型仍需理解较深的通用协议。成功纠错证明拒绝路径可恢复，不证明协议易用性问题消失。

**建议：** 在不改变 Native 权威校验的前提下，提供当前阶段的最小合法示例、结构化字段路径和允许值；评估提前检查纯结构错误，避免暂存后才发现错误。不得自动替模型更改业务含义。

**验收：** 错误字段能精确定位；修正后只提交一次有效业务操作；不存在宽松解析悄悄丢弃未知字段的路径。

**责任入口：** [schema 诊断](../../packages/core/tools/src/json-schema.ts)、[Simulation 工具](../../packages/simulation/tool-simulation/src/index.ts)。

### SYS-04：旧 requestId 被带入新裁决，形成永久提交阻断

**状态：已修复前置检查。优先级：P1。**

**现象与影响：** Session 历史中的旧请求 ID 被用于当前裁决，错误到 Native 正式提交时才被发现，可能使该决策永久阻断。对长程测试而言，这会使大量已完成历史无法自然续跑。

**已做修复：** 暂存 resolution 时比较 prepared resolve context 中的当前 requestId，让这类错误先以可纠正工具错误返回。Native 仍校验完整提交，未放宽最终权限约束。

**验收：** 错误 ID 暂存失败；模型修正后可提交；旧请求不能被重新执行，也不能通过篡改 ID 获得另一请求的权限。

**责任入口：** [Simulation 模型适配](../../packages/simulation/simulation-team/src/model.ts)。

### SYS-05：调控者转抄长请求时改变内容

**状态：v3 已修复，旧失败运行保持原状。优先级：P1。**

**现象与影响：** 早期河港运行在第 5 天出现调控者反复改写长业务 payload，违反必须保留原请求的约束；最终无效提交导致永久阻断。调整措辞或简单增加 token 额度无法保证逐字一致。

**已做修复：** v3 的批准计划只携带 `{forwardOriginal:true}`，Native 请求身份绑定原始完整 payload；执行器读取原请求，不再要求模型转抄。调控者仍进行真实观察、给出裁决并提交，未伪造模型同意或消费证明。

**验证：** 对后续运行逐项比较动作、依据、viewId 和 Team/Session 身份，与原始裁判决策一致。

**验收：** 长文本和边界字符内容保持一致；拒绝替换 payload；重试与冷恢复不重复执行。旧失败运行不得通过改写日志伪装成成功续跑。

**责任入口：** [协议](../../packages/simulation/simulation-world/src/harbor-protocol.ts)、[执行器](../../packages/simulation/simulation-world/src/harbor-execution.ts)。

### SYS-06：生成引用长度与协议版本不匹配

**状态：已修复新版本边界，部分早期历史仍有观察限制。优先级：P1。**

**现象与影响：** 裁判给 offer ID 加上 `order-`、`loan-` 前缀，生成引用可能超过输入身份长度。直接替换旧 schema 又会改变序列化 schema 哈希，破坏已消费上下文证明，即使旧值仍满足新长度也不能视为兼容。

**已做修复：** 新版本允许准确的生成引用长度；保留 v1/v2 精确契约，v3 作为新创建运行的协议。增加最长引用和旧 schema 哈希检查。

**剩余问题：** 更早的未正确版本化试验不能因新版本注册而自动修复。当前列表仍存在不可观察运行，原始证据保留，尚无面向用户的充分诊断或受控导出流程。

**验收：** 每个版本以原 parser 恢复；不允许别名静默重解释；不可恢复时明确拒绝并保留原始文件。

### SYS-07：角色生命周期状态并发更新冲突

**状态：已修复所测竞争路径。优先级：P1。**

**现象与影响：** 多角色并发退休等场景中，状态读取、证明和写入竞争，有限重试可能耗尽，妨碍资源释放或检查点完成。

**已做修复：** 对同一 Team 的相关操作串行协调，并验证 JSON/SQLite 下的多角色更新。运行中的同一同步权限检查也改为复用一个 detached Native snapshot，异步等待后仍获取新快照。

**验收：** 多角色同时完成/退休时，状态不丢失、写入身份一致、writer 最终释放；不能通过无限重试掩盖竞争，也不能跨异步边界复用过时授权快照。

**责任入口：** [生命周期控制器](../../packages/team/team-activation-controller/src/index.ts)。

### SYS-08：默认额度与历史读取上限不适合长程案例

**状态：已缓解，不是扩展性问题已经解决。优先级：P1。**

**现象与影响：** 较低区间额度很早耗尽；65,536 单请求 token 上限在第 2 天压缩后仍拒绝请求；历史读取达到默认字节上限后，后端可能仍在运行，但观察页面无法正常读取。

**已做调整：** 本次专用部署使用 262,144 单请求额度、每七模拟日 1 亿 token 区间额度、更高的 Team 消息与计划大小，以及显式 1 GiB 历史检查字节上限。提示模型避免重复请求完整当前视图。已有运行保留创建时冻结的额度。

**剩余问题：** 增加上限只延后压力点。需要测量历史大小、快照复制、读取耗时、内存与压缩效果，不能承诺凭这些配置可以稳定完成全年。

**建议与验收：** 创建前做静态可行性检查；运行时按来源显示预算占用；历史读取有明确分页、截断和不可用原因。模拟超过默认上限时仍可安全暂停、保存和读取必要状态，且不会无限增加内存上限。

### SYS-09：无收益压缩反复执行，整体推理效率偏低

**状态：未解决。优先级：P1。**

**证据：** Session 中出现多次 `summary is not smaller than the shadowed content`。系统正确保留原内容，但后续仍可能对相近范围再次付费压缩。河港到第 12 天共有 1,669 次模型用量结算记录，已报告用量汇总约 45,546,584 token，包含缓存读取；这不是提供方账单，也不能把每次结算都当作业务决策。

**影响：** 时间和成本增加，业务进度与调用量难以对应；错误修正过程中重复压缩进一步放大成本。尚未做完整性能剖析，不能把所有额外调用归因于同一原因。

**建议：** 区分固定上下文与可压缩历史压力；按选中内容及策略的指纹识别无变化重试，加入有界退避；新内容达到阈值后再尝试。分别统计业务推理、调控者裁决、收尾和压缩。

**验收：** 同一内容无变化时不无限重做无收益压缩；新有效内容出现后能恢复压缩；上下文溢出恢复仍有效；摘要必须通过现有证据和收益检查，不能为降低调用数而接受错误或无收益摘要。

**责任入口：** [压缩引擎](../../packages/compaction/compaction-basic/src/index.ts)、[摘要收益校验](../../packages/compaction/compaction-basic/src/region.ts)。

### SYS-10：缺少强制执行的“运行至指定日”停止能力

**状态：未解决的产品能力缺口；本次已人工满足停止要求。优先级：P0。**

**证据：** 用户改为第 12 天停止后，本次通过 WebUI 向协调者写入正式输入，确认其在 Session 中消费，再监测实际日期并人工暂停。界面未提供已验证的自动停止边界配置。

**风险：** 模型忘记约束、一次推进跨过终点、浏览器断开或操作者不在线，都可能导致继续运行。仅在提示词中写“不要超过”不是执行保证。

**建议：** 持久化独立的运行控制目标，区分“到达日期就停止”和“完成该日已受理工作后停止”；在日期请求准入、实际执行和驱动循环处保持一致检查。独立裁判日期与 Native 调度时间都必须受约束。超过终点的请求应明确拒绝或要求重新规划，不得静默截断模型业务意图。

**验收：** 从第 11 天请求推进到第 13 天而终点为 12 时不能越界；恰到 12 后不产生新的越界工作；重启、冷恢复、断开 UI 后约束仍生效；保存失败时维持暂停并显示可重试状态。恢复继续运行需要显式修改或解除停止目标。

### SYS-11：调度失败原因不完整，旧停止原因误导排障

**状态：旧原因残留已修复，安全故障分类未完善。优先级：P1。**

**证据：** 上游余额不足返回 HTTP 402 / `Insufficient Balance` 时，WebUI 曾显示调度失败和上一批的工作上限原因。Native `running` 只表示请求运行，不能证明驱动器仍在推进。

**已做修复：** Company/World owner 在新批次抛错后清除上一批结果，避免继承旧停止原因和重试期限；保持显式恢复要求，不自动反复推理。余额由用户充值解决，随后从同一检查点恢复运行。

**剩余问题：** 公开控制接口尚缺足够易用的安全原因分类。建议输出经过归一化的原因、重试性质和处理建议，例如余额不足、限流、网络失败、上下文限制；原始错误单独按权限披露，防止暴露路径和凭据。

**验收：** 先正常完成批次再抛错时不能显示旧 work-limit；已知余额不足不进行无界重试；恢复前后历史不丢失；页面不会把 phase、driver、inFlight 混为一个状态。

### SYS-12：浏览器连接、热更新与本地认证互相干扰

**状态：已修复本次复现路径，覆盖仍有限。优先级：P1。**

**现象：** 隐藏标签页保留连接、Root 注册和挂载时序、已退休插件异步回调等问题影响重连和页面稳定；同主机不同端口的认证 Cookie 曾互相干扰。

**已做修复：** 隐藏页面关闭 HMR 连接并在返回时补收更新；挂载等待 Root 注册；退休实例拒绝迟到回调并正确清理；认证 Cookie 按端口隔离。相关组装浏览器和双 Host 测试通过。

**边界：** 端口 Cookie 隔离不是同主机不同服务之间的保密边界。多个可见窗口、长时间运行和更多浏览器组合仍需覆盖。仅凭某次页面超时不能认定服务死亡并重启。

### SYS-13：权限内可观察数据与案例语义不完整

**状态：未解决的领域展示/读取能力缺口。优先级：P1。**

**证据：** 当前河港事项可见执行元数据，但正文和业务键要求独立披露授权；通用人员数来自技术绑定，不能自然表达原始裁判的公司、联盟和雇佣关系。该现象的 UI 后果详见 UI 报告。

**建议：** 领域提供方定义受权限约束的业务摘要和结果投影，分开记录请求已提交、裁判接受、业务目标实现三个层次。允许安全公开的摘要不等于允许披露全部私有视图。

**验收：** 不提升权限即可看到已授权的必要状态；未授权内容明确 withheld；同一结果在列表、详情与导出中使用同一语义；新增读取能力有越权和撤权测试。

## Audit repairs

1. Previously both SDK transcript paths knew `compaction/assessment` by name but did not validate its new payload or `compaction/end.noGain`. Added strict envelope and payload validation with positive / negative wire tests. Successful compaction/end with noGain is rejected because noGain requires a string error; no lifecycle is inferred from standalone notification data.
2. Python failure UUID fields previously accepted unsupported UUID versions/variants; regex now matches Native Zod UUID (including nil/max). Newly introduced driver/failure/read-limit counts now preserve Native safe-integer bounds.
3. Python business-summary labels now enforce the same 80 UTF-16-unit limit as Native (40 astral characters accepted, 41 refused). Raw selection limits now preserve the same safe-integer ceiling as the TypeScript wire parser.

`@clocky/clocky-compaction/no-gain` is browser-safe: source imports only `CompactionNoGain` as a type, erased emitted JS imports no Node or Cordis service. Package export, exact tsconfig source alias, SDK peer/dev dependency and compiler reference are present. Package files already include `lib/types/**/*.js`. Runtime face refreshed for Compaction and SDK client.

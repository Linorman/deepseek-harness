# B2 protected archive and required portable-recovery evidence

The supported archive is a complete self-contained root-Team owner closure. A sealed Native cut exports its original full journal; Team and Channel queues export original versioned streams; Session persistence supplies physical events and headers; the attachment owner verifies canonical image bytes. The archive retains all historical records, so older checkpoints, cases, plans, approvals, contexts, outbox/cleanup and generation responsibilities remain protected. Unmaterialized Sessions stay identities without fabricated events. No source log is deleted or compacted and no Participant/Activation allowance is released.

Unsupported ownership rejects explicitly: child Teams, Team/task workspaces, workspace allocations and provider-owned artifacts require their own export/mapping providers; non-image structured attachments, external Session parents and unknown branch lineage are not silently treated as closed roots. This is a finite supported-format guarantee, not arbitrary filesystem backup. Installed owner parsers validate opaque journal records; JSON shape alone is not semantic validation.

`planWorldArchive` reports full bytes, object counts and conservative pins with zero reclaimable bytes. Copy, SHA-256 readback, fsync and atomic location publication precede archive availability. Missing locations, incomplete closures, unknown bundle versions and bad body/image hashes reject. `archiveLogFacet` exposes original sequences through the standard bounded read interface, rejects missing originals and forbids writes/compaction. Rebuilds use original records; no index is treated as truth.

`restoreWorldArchive` first imports into isolated sibling staging. Header cwd mappings are explicit and preserved in a source-hash receipt; events and original Native journal prefixes remain byte-equivalent. A target owner validates all imported sources and publishes a legal new checkpoint for relocated headers. The original checkpoint manifest is unchanged and correctly rejects the changed Session fingerprint. The new checkpoint supports real `simulationTeams.restore` and explicit canonical `ensureResident(seed:resume)` with the original Session. Publication occurs only after validation and owner closure. Failed staging is unpublished and retryable; successful identical retries validate the published owners and the same import anchor.

Product `retentionPreview/retentionExecute/retentionRead/retentionRecords` make these actions available through authenticated original commands. Preview requires an already checkpointed, paused, quiescent World and never pauses writers or calls models. Execution first atomically stores original input, plan and archive bytes in its dedicated journal, then publishes completion; retries after failure continue from accepted bytes. Original record pages require the current separate whole-record grant. Owner-only metadata access does not disclose private Session bodies. Entry and byte limits are explicit deployment Config fields.

Validation records in `.tmp/world-post-mvp/b2/`: `final-integration.log` passed nine environment/authoring/archive tests; `writable-restore-current.log` passed both JSON and SQLite offline restore/real resume chains; `product-host-current.log` passed both backends through all four `InProcessApiClient(toFetchHandler(...))` methods, including publication failure, same-command retry, service restart, changed-payload rejection, stranger rejection and record-reader revocation. `snapshot.log` passed two independent runnable example snapshots. Final aggregate checks and SDK transport tests are recorded by the integrating task.

The source directory is renamed away before target creation in the recovery tests. Fixtures include actual accepted plans, a real PNG, an empty materialized Session with a mapped cwd and an unmaterialized canonical identity. Tests preserve original records and counts before resume; resume may append a legitimate new activation while retaining all prior activation history. No provider model is invoked in these probes.

This is the B2 original-history recovery prerequisite, not complete D1 Product migration. The bundle does not contain Product creation records, resolved generated-actor runtime configuration or directory registration. Target provider/preset composition is explicitly supplied by the deployment. The verified new anchor and canonical actor resume do not claim that an imported Product automatically resumes its original driver. Full Product migration remains unaccepted. Custom domain pins and runtime/Channel providers without explicit covered reference contracts are unsupported, even when installed and replayable.

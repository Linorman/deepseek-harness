# 世界模拟 MVP 剩余工作详细 checklist

本清单分解[剩余设计](design.md)和[开发计划](development-plan.md)。它不替换原 112 项，不改变原分母；初始全部未勾选表示本轮尚未执行这些新增或复核任务。已有证据可在核对输入一致后引用，不能仅因同名测试以前通过就勾选。

每项完成记录包括：ID、源码/配置/产物 hash、实际命令及退出码、日期、source/lib/后端、原件链接、未解决问题。原 B04 对应 A/B，R08 对应 D/F，R09 对应 B/C/F，R13 对应 E/G；仅完成部分子项不勾原整项。

## A 基线和配置 W0 W1

- [ ] A01 固定真实工作区输入，HEAD 与未提交实现分别记录，版本/场景/lockfile/构建模式明确。
- [ ] A02 原清单 108/112 与四个未完成 ID 核对，旧正文和勾选保持不变，历史证据标注适用范围。
- [ ] A03 建立历史证据漂移表，列出后续复查超时的确切组、用例、命令和未解决原因。
- [ ] A04 明确 World eval 与单 observer benchmark 的不同，live 入口不导入 scripted 输出选择器。
- [ ] A05 严格 spec parser 覆盖 route/version、case/suite、预算、price/currency、披露、输出路径及未知字段拒绝。
- [ ] A06 每 run 和整批调用/token/费用/决策/mutation/墙钟限额均有限且冻结，模拟时间进入新区间不会重置整批总额。
- [ ] A07 route/费率/输入输出上界有可核验来源；未知价格、隐藏 retry、无法证明收费上界时拒绝 hard-budget 运行。
- [ ] A08 validate/dry-run 零模型/零身份/零世界写入，远端 probe 独立计费；坏路径、溢出、非法金额和配置缺失有诊断。

## B 调用前预算 W2

- [ ] B01 普通 actor、director、外部代表和 compaction/辅助流在 dispatch 前均有原 Native token reservation 与唯一 eval attempt 关联。
- [ ] B02 预算账只拥有费用和证据关联，不替代 Native/Team/Session 或重复计 token。
- [ ] B03 费用预留持久成功后才能发起；同预算并发竞争由单 owner 原子决定，run 与整批 cap 同时满足。
- [ ] B04 排队后再次校验预算、权限与取消；额度变化不能沿用排队前准入结果。
- [ ] B05 完整请求、工具 schema、缓存/推理/输出全部计入保守上界，未知缓存命中不预先折扣。
- [ ] B06 费用以精确整数/有理数并向上舍入；刚好 cap、多一单位、极值与溢出均有拒绝路径测试。
- [ ] B07 SDK/provider 内部自动 retry 关闭，每次实际重试都获得新尝试身份和新的预留，无旁路调用。
- [ ] B08 真实 usage 互斥 buckets 归一化，reasoning 不重复计算，合法零 output 可正确 complete。
- [ ] B09 同原件重复 settlement 幂等，异 usage/费率拒绝；模型/单价变化不能改写原尝试。
- [ ] B10 实际 usage/cost 超预留立即停止并记录 overrun，不能提高 cap 或隐藏超额后继续。

## C 断流和预算恢复 W2

- [ ] C01 reserved/dispatched/settled/not-dispatched/outcome-unknown 都有严格持久状态和合法转换。
- [ ] C02 只有确证未进入 provider 的请求释放预留；超时、abort 或无回复不构成未收费证明。
- [ ] C03 provider 断流、缺 usage 或 Session barrier 失败保留占用并关闭新推理，所有未知责任可查询。
- [ ] C04 Native 已结算但费用未结算时用原 usage 恢复，重复 reopen 不重复计费或释放。
- [ ] C05 覆盖预留前后、可能 dispatch 标记后、返回后/flush 前、token 结算后/费用结算前的进程故障。
- [ ] C06 评测账排他恢复，同 attempt 不可能由两个 owner 同时执行；原 accepted Persona/plan 不重新推理。
- [ ] C07 无 provider 精确查询能力时 unknown 保持未知，人工处理记录依据，不能凭超时归零。
- [ ] C08 达到任一 cap 关闭新 dispatch，排空/记录在途责任；run 暂停且业务、outbox、维护和退休责任不丢。

## D 用例和检查器 W3

- [ ] D01 公司与实验室各 V/M/A/P 四例正式登记，suite/rubric/预算先冻结再执行。
- [ ] D02 两个 V 用例经实际产品/Agent/三工具完成治理、招聘、外部代表、调岗/交接离职，checker 读取真实日志。
- [ ] D03 M 用例缺依据时补证或拒绝，不先提交效果；case/version/deadline 和补证上限可核验。
- [ ] D04 A 用例无越权业务；区分 Native 正确拒绝与模型本身未理解权限的质量问题。
- [ ] D05 P 用例使用非秘密 canary，检查模型输入、Session、结果/通知及公开报告；外部代表不见 director 私密历史。
- [ ] D06 自动 checker 有故意缺阶段、假成功、重复效果、越权/泄漏反例，不只测试自己接受正确样本。
- [ ] D07 incomplete、provider error、预算不足、超时和重试全部保留分母，不删除失败原件。
- [ ] D08 人工评分采用预先冻结 applicable 0/1/2 标准和门槛，保留判断依据，不用八例估计一般可靠率。
- [ ] D09 报告/inspect/原已接受结果恢复零模型；raw 证据和公开脱敏报告分开，凭证及鉴权 headers 不落日志。

## E 时间敏感失败 W4

- [ ] E01 使用复查原命令和配置重现失败组，保存机器/并发/输入 hash 与完整退出码。
- [ ] E02 采集窗口、Session、模型池、维护/退休和子进程时间线，区分可证明的产品、测试或环境原因。
- [ ] E03 修复根因或测试等待条件，不扩大 timeout、降低断言、加隐藏 retry 或修改业务预算。
- [ ] E04 正式模式原失败整组及相关生命周期回归通过，重复检查记录次数和结果，不以筛选通过替代整组。
- [ ] E05 未定位或仍间歇失败保持风险开放，R13 不提前完成；已确认环境前置具备机械检查。

## F 真实执行 W5

- [ ] F01 实际执行前 route/model/version/凭证引用/价格及硬预算确定，已有暂缓条件已明确解除；配置不含明文秘密。
- [ ] F02 W2/W3 keyless 与预算故障通过后才发起收费调用，最小 probe 也进入总调用/费用账。
- [ ] F03 核验真实 provider 返回的模型标识、usage、output 限制和无隐藏 retry；不满足时停止，不换成 scripted 成功。
- [ ] F04 公司/实验室八例实际结果完整，两个 V 达成终态，六个负向/隐私样本符合各自标准。
- [ ] F05 每次调用、缓存/推理 token、真实结算、保守占用、停止原因和世界因果引用可关联。
- [ ] F06 出现硬不变量失败、unknown 或预算耗尽立即按预登记策略停；不临时加钱、换模型、代模型补计划。
- [ ] F07 人工评价满足预定门槛，所有失败/不完整/重试可见，明确样本局限及未证明的能力。
- [ ] F08 B04/R08/R09 分别按证据验收；预算配置通过不自动意味着任务/质量/费用停止全部通过。

## G 当前集成和最终交付 W6

- [ ] G02 按实际改动执行 owning tests、keyless、分发/SDK/browser、类型/lint/build/doc-sync，记录失败/skip/未跑范围。
- [ ] G03 共享模型入口或生命周期变化触达时验证原采购/招聘/完整世界和两后端恢复，零重复业务/身份/资源效果。
- [ ] G04 当前源码的私密数据、未知退休、预算和原命令不变量无开放阻塞缺陷；E 组时间敏感问题已关闭。
- [ ] G05 历史 48.5% 与旧限制标明时点；更新相关 README/双语提案但保留原清单、真实失败和未支持 P1–P5 边界。
- [ ] G06 最终证据包包含输入、准确命令、全部尝试、费用/未知、人工评分、漂移和验收者结论。

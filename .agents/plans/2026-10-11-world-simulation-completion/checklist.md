# 世界模拟完整 MVP 验收 checklist

本清单对应[原设计 MVP](evidence/source-design.html#s17)、[剩余设计](design.md)与[开发计划 C0–C7](development-plan.md)。所有产品项初始未勾选：已有招聘证据可复用，但新范围需完整核对，不能把文档写好视为实现通过。原[75 项招聘清单](../2026-10-08-world-director-mvp/checklist.md)保持独立。[UI 第二轮](ui-refinement.md#13-验收)的 V01–V24 单独跟踪，不计入本清单分母。

只有整条所列行为和拒绝路径都有证据才能勾选。每个 ID 的完成记录必须包含源码 revision 或输入 hash、准确命令、日期、后端与 source/lib 模式、结果、日志/产物路径。若一条只能部分证明，记录部分结果并继续保持未勾选；不能删掉难项来改变完成率。所列新类型和能力仍是拟议实现。

## B 基线与范围 C0

- [x] B01 固定包含现有工作区实现的集成基线，记录原 HTML hash、Native/场景/driver 版本；不以原 HEAD 代替未提交实现。
- [x] B02 原 75 项 checklist、历史证据和范围声明保留；评估明确原设计与缩减版差异。
- [x] B03 现有 JSON 创建、原命令、招聘、readiness、维护、取消和双后端冷恢复通过相关回归。
- [x] B04 真实 provider/model 路由及硬 token/决策/费用上限已确定，敏感配置不进入文档或日志；无法配置时明确保留验收缺口。
- [x] B05 新场景版本、Native stream 拒旧和 SDK 消费策略形成可执行规则，旧格式拒绝有测试；不伪造缺失历史。

## P 通用协议与领域实现 C1

- [x] P01 domain/operation/version、intent、plan、result、mutation 与 typed evidence/read-set 都有严格 public/persisted/tool parser、Branded ID 和错误分类。
- [x] P02 所有内建 domain schema/version 在受控注册表登记；未知字段、未知操作和未安装版本在副作用前拒绝。
- [x] P03 普通角色从目标决策提出未预建 HireIntent 的新世界事项，并由 Native 从实际决策派生真实主体、epoch 和来源。
- [x] P04 请求准入核验当前任职、scope、已安装操作权限和制度；修改 profile.role、伪造 requester、Session/proof 或 director 字段不能提权。
- [x] P05 同 command/operation 身份的同 payload 返回原件，异 payload 拒绝；跨 decision 的同 businessKey 不产生第二业务效果。
- [x] P06 更换 businessKey 仍受岗位、资源、每 actor/周期和历史额度限制，不存在以新 ID 绕过配额的路径。
- [x] P07 request 记录、post 意图与映射同次 acceptance 固定，额度按展开后 operations、messages、UTF-8 字节计算。
- [x] P08 deliverAt、原 Channel/Envelope、recipient、指纹及持久 Session 消费逐项核对；复制 requestId 或未消费输入不能计划。
- [x] P09 stage、submitted、accepted 分开；未 accepted 的草稿不触发执行，accepted 内容/实际 Persona 不因重试改变。
- [x] P10 typed read-set 对关键对象 stale，普通无关 revision 不 stale；后继 plan 保留 supersedes，未成功规划尝试仍占额度。
- [x] P11 awaiting-evidence 保留缺失字段、允许响应者、版本、期限和最大次数；非法补证/超期被拒，不能无限循环。
- [x] P12 请求、计划授权、执行、通知四类状态分别投影；rejected、blocked、outcome-unknown 可辨，不把未知当失败重做。
- [x] P13 原招聘 handler 通过新分派运行，主 driver 不含公司、实验室、招聘之外新增领域的剧情分支。
- [x] P14 会议室预约测试领域只注册自身 schema/验证/效果投影，即可走实际请求、Channel、计划、结果和恢复。
- [x] P15 accepted plan 固定 implementationRef/generation 并持有执行 lease；卸载关闭准入、排空并保留未知责任。
- [x] P16 缺失必需 schema/reducer/provider 版本拒绝 writable restore，未知事件不当成功忽略；两端 SDK 同步拒绝规则。

## F 版本事实与模型上下文 C1 C2

- [x] F01 WorldFact/Norm 记录版本、来源、作用域、audience、recordedAt、生效区间和 availableAt；区间和规范模拟时间验证一致。
- [x] F02 更新追加新版本与 supersedes；旧 Decision/context-view 仍重建旧内容，逆改历史和覆盖旧版本被拒。
- [x] F03 今日公告明日生效、已生效未公告和私密事实各有测试；生效、可知、收件、理解不混为一项状态。
- [x] F04 belief/report 与权威事实不同；director 摘要不自动升级来源，未知事实保持 unknown。
- [x] F05 advisory 仅作为获准背景，validated 必须映射已安装原语；未知 policy/参数和任意代码拒绝。
- [x] F06 新规范默认不重写已接受任务/承诺；需要迁移却不支持时返回原义务引用与明确阻塞。
- [x] F07 普通成员、director、外部代表和用户各自投影；每次模型输入有完整 Session/context-view 来源，不注入隐藏回调上下文。
- [x] F08 低权限结果使用可信结构化投影或模板；director 自由文本不自动进入新人/供应商或全员背景。

## G 治理制度 C2

- [x] G01 提案冻结正文 hash、目标 Norm 版本、committee/scope、electorate、策略、quorum、通过阈值和 deadline。
- [x] G02 每名委员在独立真实 Agent/Session 决策中投票，voter 从 binding 派生；CEO 声称全票通过不起授权作用。
- [x] G03 非成员、替人投票、旧 epoch/未消费上下文、错误正文 hash/revision 和结案后投票全部拒绝。
- [x] G04 一人一票业务唯一；同原件重试幂等、异 choice 拒绝；改变正文或投票内容必须新提案。
- [x] G05 unanimity、绝对阈值、quorum、no/abstain 语义均有边界测试，包括空/非法 electorate 和不可达阈值。
- [x] G06 成员变更不改变冻结 electorate；早结案仅在结果不可再改变或票齐时发生，deadline 同时刻投票准入固定。
- [x] G07 close 从真实票据确定性产生唯一 resolution 和 wake；重复调用/失去回复不产生第二 resolution。
- [x] G08 enact 通过真实 world Channel；Native 核对 passed resolution、原 hash/版本、scope、当前制度与 policy，不信 director 自述。
- [x] G09 Norm 生效、旧区间结束、结果与公告责任原子提交；重复请求或恢复至多一次生效。
- [x] G10 招聘 validated 策略在 reserve/commit 两处约束实际权限、批准和额度；无审批及旧审批均拒绝。
- [x] G11 撤销制度产生新版本或结束区间，保留旧票据和历史合法效果；模型上下文读取正确时点版本。
- [x] G12 vote/close/enact append 前后和通知丢失分别在 JSON/SQLite 杀进程恢复，不重复投票、生效或公告业务责任。

## O 人员和任职 C3

- [x] O01 hire-existing 检查人物资格、cognition、terminated 和冲突任职；复用原 Entity/Participant/Session/Persona，不复制新人物。
- [x] O02 generate-and-hire 保留有限模板实际结果，恢复不重新生成；新人首次行动和独立 Session 维持原回归。
- [x] O03 岗位 occupied + reserved 不超 capacity；必要资源 available = balance − 有效预留，单位/控制权/批准均由 owner 核验。
- [x] O04 reserve/commit 之间权限、制度、资源或岗位变化使旧计划明确 stale/blocked，不偷偷改 plan。
- [x] O05 所有跨 owner 身份、资源和岗位预留在 IO 前保存；相同 mutation 精确复用，取消后仅释放确认可释放占用。
- [x] O06 preparing Entity 经 driver、Native writer/decision/task、直接 activation、冷替换/恢复都不能取得普通行动资格。
- [x] O07 调岗关闭旧任职、建立新任职、更新授权、结算预留并写 result/wake 为同一原子批次；原身份和记忆不变。
- [x] O08 调岗 requested/actual 生效时间明确；错过严格时刻返回 stale-time，不回填过去或修改已冻结 slot。
- [x] O09 义务预览覆盖 open/submitted 决策、已接受 operations/outbox、tasks、commitments、资源控制、wake、消息及下属关系，并返回稳定引用/revision。
- [x] O10 departure intent 一旦受理关闭该任职新工作准入；旧 writer/旧权限 generation 不能新增岗位操作。
- [x] O11 已接受效果由原 owner 对账；未完成义务返回 handoff-required 或明确等待，不能改 inactive 使责任消失。
- [x] O12 仅用底层支持的显式取消/再建工作处理交接，绝不冒充新 assignee/debtor 已接受旧任务。
- [x] O13 职责结算后结束 assignment 并撤销未来岗位权限；普通离职不自动 terminated、不承诺擦除历史记忆。
- [x] O14 需要退休时等待 controller 精确停止回执；超时、卸载和迟到回调保留 writer/capacity 责任，不能启动第二 writer。
- [x] O15 重新入职新建 assignment，保留 Person/Session；显示在职、非终止人物、resident、未释放 writer 和历史身份的不同计数。
- [x] O16 取消与 prepare/commit 同队列竞争，取消先赢不提交，提交先赢返回 already-committed；未知 IO 精确清理，不删除历史身份。
- [x] O17 两后端调岗 append 前后、离职撤权后/退休前、准备/提交/通知断点有 SIGKILL 恢复，既不重复扣资源也不丢义务。

## X 外部世界 C4

- [x] X01 ExternalIdentity 以 run/scope/externalKey 唯一，显示名字不作身份，未展开库存/信用等保持 unknown。
- [x] X02 simulated-rule 保存输入、策略/版本和实际输出/采样；重放和重试不重新抽样。
- [x] X03 director-mediated 仅产生允许的 typed outcome，保留 subjectRef、依据、来源和 disclosure，不伪装真实观察或外部 sender。
- [x] X04 既有库存、资源、合同与事实约束裁决；冲突拒绝，未核实报价只能以明确 report 保存。
- [x] X05 相同 external key 的并发请求复用持久展开 reservation，至多一个有效代表 generation，不重复生成供应商。
- [x] X06 外部组织 cognition 保持不变；代表用独立 Person/Participant/Session 和 represents 关系，复用原主体资产/合同。
- [x] X07 原子提交 representation、ready、结果及首次 wake；准备中直接 controller 不能提前激活代表。
- [x] X08 代表只见获准 Persona、事实和新通道消息；私密底价 canary 不进入其 Session、上下文或公开结果。
- [x] X09 代表普通通信有真实 canonical sender proof；director 不接受任意 sender 字段代发供应商消息。
- [x] X10 director、代表、生成与辅助调用计入共享模型/token/resident/history/展开额度，超限有稳定停止原因。
- [x] X11 展开不增加库存或资金；source/sink 未安装时拒绝，若安装则一次性 grant、单位、额度和台账等式均被验证。
- [x] X12 请求/采样保存、代表准备、commit/receipt/通知及取消竞赛在两后端恢复，身份/实际结果/资源不重复。
- [x] X13 真实 URL、网络适配器、邮件/付款及凭证 payload 在副作用前拒绝；API/UI 都清楚标明 simulated-only。

## S 场景输入和事件 C5

- [x] S01 新场景版本严格覆盖组织单位、委员会、人物/岗位、任职、公开事实、私有知识、初始资源、通道、外部身份和行为定义。
- [x] S02 JSON 与安全 YAML 进入同一 compiler；拒绝重复 key、自定义 tag、merge、alias/anchor、多文档、非法 key/标量及可执行 include。
- [x] S03 原文件字节、解析深度/节点/引用数和最终序列化容量均有上限；YAML 时间不被隐式日期转换。
- [x] S04 重复身份、跨域坏引用、组织环、任职重叠、容量、委员会门槛、资源单位/控制权及时间可见性错误都有字段诊断。
- [x] S05 纯 parse/validate/preflight/preview 无模型、身份分配或 world 写入；不可用模型/领域版本在副作用前拒绝。
- [x] S06 resolved 固定模型/模板/策略/implementation 及全部默认/上限；create 重验预览 hash/generation 并先保留原命令。
- [x] S07 所有初始数据和跨 owner 准备步骤失败后同 commandId 复用原件；完成 checkpoint 返回 paused，未显式 start 时零推理。
- [x] S08 JSON/YAML 导出再导入保留支持的语义/hash；不包含凭证、私有运行日志或宿主路径，明确不是运行备份。
- [x] S09 普通目标与日历能产生非预建招聘事项；日历持久 occurrence 去重，每轮只排有限后继，不无限展开未来。
- [x] S10 岗位日历接收者在触发时冻结，截止/生效/回应按模拟时间排序；horizon 与到期错误不使用墙钟替代。
- [x] S11 director 主动世界事件必须有已记录场景授权和触发源，普通角色在资源充足时能在有限批次获服务。
- [x] S12 请求、出生、外部展开、pending mutation、模型/token/字节、历史/驻留/microstep 全部有明确冻结额度与停止原因。
- [x] S13 公司、研究实验室、小型协会三个定义走相同 driver，第三场景覆盖不同事件/领域组合，不能只改人物名称。

## U 产品和双 SDK C6

- [x] U01 模板、导入文件和空白入口可创建同一种定义；基础表格与 JSON/YAML 源码共享草稿，不静默丢域字段。
- [x] U02 背景/组织岗位/成员/委员会/制度/资源/外部/事件可编辑；非法引用可定位，切换视图保留未完成草稿。
- [x] U03 创建预览显示实际模型、director 权限、advisory/validated、模拟来源和有效额度，动作明确为创建暂停运行。
- [x] U04 请求/plan/执行/通知状态分别显示，领域正文/Persona/Session 独立授权，不以 run owner 代替内容权限。
- [x] U05 制度和 votes 来源、任职时线、义务与外部身份/表示均可按 case 跳转到实际 Decision、Envelope、Entity 和 checkpoint。
- [x] U06 组织/制度/外部查询有 limit/cursor/revision 和覆盖说明；cursor 绑定 query 及 reader/disclosure generation，不能伪装全量图。
- [x] U07 管理 preview 返回实际影响和阻塞；submit 采用固定 commandId/payload，并重验 preview；标记真实用户干预，不伪造模拟角色。
- [x] U08 超时后保留原命令，查询后精确重试；双击、刷新、后退和多标签不产生第二事项或第二 owner。
- [x] U09 浏览、预检、导出、页面重开和过时数据刷新均不推理、不启动 run、不做 writable restore。
- [x] U10 等待投票、资料不足、容量满、交接未清、版本缺失、退休未知、拒绝、空列表和网络失败都有原因与可执行下一步。
- [x] U11 撤权清除敏感正文并使 pending 读取失效，迟到响应不能复活内容；断网保留标记过时的数据及原命令。
- [x] U12 Host/Client/TS client-server-protocol/Python parser-client-server 同步新 DTO、事件与错误；未知必需事件显式拒绝。
- [x] U13 SDK 既通过源码流程，也通过 compiled TS 和已安装 Python wheel 的创建、查询、控制及新进程恢复，build 前置条件明确。
- [x] U14 实际浏览器完成三个场景创建、开始、投票/制度、招聘、外部、调岗/离职与恢复，使用真实产品/Agent 链而非预构造成功对象。
- [x] U15 键盘/焦点、窄屏、浅深主题和减少动效通过实测，无阻止核心操作的控制台错误；GUI PR 附真实 server/model flow GIF。

## R 恢复与发布 C7

- [x] R01 checkpoint 包含 domain 版本、facts/norms/votes/resolutions、所有 Persona/计划、外部 registry、mutations/reservations、通知及清理责任。

- [x] R03 纯回放不调用模型、不重新抽样/生成、不访问真实外部系统；冷恢复保持 paused，仅显式新 start 可以继续生产性调度。
- [x] R04 维护与用户新 pause/cancel 竞争时保留新意图，不被维护结束的自动 resume 覆盖；IO 不占住 Native 写队列。
- [x] R05 原设计完整剧本在两后端通过：独立投票→制度→HR 申请→新人→供应商代表回应→调岗→交接离职。
- [x] R06 设计故障矩阵每个危险边界都有 barrier/SIGKILL/新进程证据；原身份、Persona、投票、制度、资源与通知责任不重复或丢失。
- [x] R07 现有采购、task、消息 proof、窗口、checkpoint 和招聘相关回归通过，原成功/失败语义不被新领域旁路破坏。
- [x] R08 公司和非公司真实模型小样本完成，包含有效、缺信息、越权、隐私探针，保留模型版本、输入/输出来源、token/费用和人工判断。
- [x] R09 真实试验达到硬预算即停，失败区分协议与质量，不修改不变量、测试阈值或自动加预算以制造演示成功。
- [x] R10 保存三领域工作负载下的冷恢复、历史增长、人员 churn、外部重复交互原始样本、版本和硬件；支持规模只基于实际测量。
- [x] R11 按最终 diff 完成相关 focused/keyless、类型、lint、build、分发、浏览器及 doc-sync；失败、未跑和 pending 均如实登记。
- [x] R12 README/子系统/事件/工具/API/配置目录、双语提案和示例按当前实现更新，模型可见变化有 runnable snapshot。
- [x] R13 所有必需项证据齐全、无重复效果/越权/隐私串用/失踪义务/未知退休早释放后，才宣布原设计 MVP 完成并按规范更新 proposal 生命周期。

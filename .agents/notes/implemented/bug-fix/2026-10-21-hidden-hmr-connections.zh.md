# Agent Note: 隐藏标签页的 HMR 连接生命周期

Status: implemented

[English](2026-10-21-hidden-hmr-connections.md) | 中文

## 问题

每个 WebUI 标签页即使没有构建更新，也持续占用一个 HTTP/1 EventSource。重复启动本地页面可能占满浏览器同源连接池，使普通页面读取排队。关闭多余测试标签页后，这些读取恢复。

## 决策

[HMR 浏览器插件](../../../../packages/client/hmr/src/client/index.ts) 在隐藏时关闭 EventSource，可见时重新打开。已退休连接不能提交帧。首个 graph 帧建立基线；后续连接比较原有条目的修订，通过已有重载路径补收错过的构建。重载成功后更新观察到的修订，避免重复执行。在改变基线前验证已知帧。卸载关闭连接并移除可见性监听器。

## 替代方案

**保留全部后台连接。** 这会保留 WebUI 测试中观察到的连接池压力。

**关闭连接但不核对错过的更新。** 返回的标签页可能长期保留过期 bundle。重连 graph 已提供当前修订，无需新增 Host 协议。

**返回时重载整个页面。** 这会丢弃无关的内存 UI 状态；已有条目重载路径影响更小。

## 后果

此行为处理普通隐藏标签页，不解决任意多个同时可见的窗口。插件自身重载后，首个 graph 重新建立基线，避免把替换后的 HMR bundle 与不可变启动清单反复比较造成循环。首个基线前已有的竞争及图成员变化仍需单独处理。

## 验证

[组装浏览器快照](../../../../apps/web/tests/hmr-visibility.snapshot.ts) 启动真实构建插件，验证隐藏连接关闭、退休连接消息拒绝、错过的自身构建补收，以及替换后不会循环。浏览器连接暂停时，Simulation 仍由 Host 独立推进。

# Agent Note：部署所有者提供的执行配置选择

状态：已实施

[English](2026-09-28-team-execution-profile-selection.md) | 中文

## 问题

成员登记接受执行描述，但活跃成员身份不能证明存在匹配的部署路由。操作者需要选择当前配置，同时不应获取启动路径或凭据。

## 决策

Placement 通过自身插件上下文向 Team runtime 注册公开配置。每个路由角色提供 local-agent 和 remote-agent 描述。可用性检查实际 runtime provider 及其声明的成员类型。卸载 placement 插件会移除注册；移除 provider 会更新可用性，而不改变描述标识。

配置 ID 只对公开的 kind、role、provider、preset 和 model 求哈希。它标识描述，不代表不可变的启动规格或执行预留。工作目录、token 限制、凭据和可执行选项不公开。服务成员保留手动登记，其生命周期由对应服务拥有。

`getExecutionProfiles()` 要求绑定请求内容的活跃人工成员读取证明。缺少邀请权限、Team 非活跃、达到成员限制或由 Simulation 管理时，不返回配置数据。分页同时受行数和字节限制。续页绑定 Team、成员类型和注册版本；已选描述独立于当前页返回。每次读取重新计算可用性。

邀请操作将已选 ID 和完整描述绑定到人工命令证明。Hub 在授权策略执行前和提交成员前分别验证精确匹配及可用性。配置撤销会拒绝命令，不写入成员记录。配置 ID 是命令元数据，不保存到成员。手动描述仍经过普通邀请和 placement 检查。

浏览器 runtime 拥有目录读取、轮询和取消。表单拥有已选 ID、页游标和输入字段。选择配置后锁定执行字段。加载、传输失败、权限失效或所选配置不可用时暂停提交，并保留输入。目录变化后刷新返回首批。登记不会启动 actor。成员管理会刷新当前成员列表窗口，让已完成命令可见，同时不重置分页位置。

## 考虑过的替代方案

**在 UI 根据 provider 名称推断路由。** 名称不能证明当前注册、支持的成员类型或精确描述匹配。

**把完整启动配置保存到目录。** 启动路径与凭据属于部署所有者，公开选项只需要成员描述。

**只在列举时验证选择。** 策略执行是异步的，邀请提交前插件可能卸载。提交前复查能拒绝过期选择。

## 影响

登记后的当前执行观测仍由[成员就绪状态](2026-09-28-team-member-execution-readiness.zh.md)负责。配置可用不保证 preset 加载、模型访问、容量或最终任务成功。[产品提案](../../proposed/architecture/2026-09-28-web-team-simulation-product-integration.zh.md)继续拥有更广泛的身份、草稿和 Simulation 要求。

## 验证

注册表测试覆盖生命周期卸载、精确描述匹配、独立的已选项、续页和字节边界。Runtime 与组件测试覆盖过期响应、权限失效、类型切换和被拒后的草稿保留。真实 Host 测试在邀请策略执行期间卸载 placement，验证不会提交成员。浏览器场景选择注册配置，并使用生产调度器和任务报告工具完成任务。

# Agent Note: Team 任务表单草稿生命周期

Status: implemented

[English](2026-09-29-team-form-draft-lifetime.md) | 中文

## 问题

任务表单把输入和创建重试身份保存在组件状态中。关闭或更换 Team 会丢失两者；基于新任务重新打开时，也可能替换用户开始编辑时的 revision。传输失败可能隐藏已经接纳的创建结果，丢失原身份会允许重复工作。

## 决策

注册拥有的查看 store 按精确 Team、操作和任务身份保留任务表单字段。创建、编辑、审核和整合各有独立位置。原始文本、依赖及成员 ID、执行选择、审核理由、整合来源与目标，以及创建 fingerprint/key 都是输入。初始可编辑字段和已核对 revision 支持关闭及过期编辑检测；当前任务记录、历史、权限和能力观察仍由 runtime 拥有。

任务表单共享频道／人工答复草稿的数量和完整 UTF-8 额度。更新被拒绝时，所有原草稿保持不变；重试身份未保存时不能发送命令。带草稿的视图在既有视图额度内保持固定。关闭保留注册拥有的输入，明确丢弃确认实际丢失，提交确认后释放位置。有任务输入时离开页面会警告；重载和账号／权限替换会清除这些只在内存中的表单草稿。

URL 只包含操作和对象身份。恢复时先通过 Host 读取精确任务，再显示保留输入。关闭和导航保留原草稿 revision；任务变化后，提交保持禁用，直到用户明确确认当前版本。空白表单等待首次 runtime 记录，不把未加载字段当作空任务。相同语义 payload 的创建重试保留同一 key；Host 授权与幂等机制仍是权威。

任务 inspector 独立于新编辑菜单打开保留输入，包括删除 tombstone 和有活动执行的任务。Team 页面操作资格另行控制提交与原请求重试，要求修改所有者已执行的 active Team 阶段。Stalled、quiescing 与终态 Team 保留输入和原结果查询，并明确说明只读。规范父团队只读检查、终态 Team 和没有管理回调的部署可以检查原结果而不写入。对话框仍要求精确授权任务记录；过期或断线事实不能启用提交。版本读取失败时禁用确认与写入，待进行中的 IO 结束后仍保留刷新入口，避免错误阻止自身恢复。

## 考虑过的替代方案

**始终挂载全部表单。** 后台观察生命周期会持续存在，输入保留依赖布局。

**将草稿写入 localStorage。** 这需要额外决定敏感数据位置、配额、过期和授权清理，本内存功能不承诺这些能力。

**把完整任务快照作为草稿保存。** 历史和权限事实会成为第二份 UI 业务状态。

## 影响

重新打开表单需要当前授权检查；读取失败时仍保留输入。共享额度可能拒绝另一个表单，直到用户丢弃不再需要的输入。[更新受理决策](2026-09-29-task-update-command-admission.zh.md)负责持久编辑身份和原受理查询；[引用／冲突决策](2026-09-29-task-reference-status-and-conflict-review.zh.md)负责当前字段比较。[工作区决策](2026-09-11-team-workspace-ui.zh.md) 继续负责组装与导航归属。

## 验证

组件测试覆盖创建原始字段、关闭后的同 key 重试、独立 Team／操作位置、审核和整合输入、来源尝试、过期 revision 确认、容量拒绝、明确丢弃及首次检查。真实 Host/keyless 任务草稿场景覆盖模块、Team、历史、重连、创建已接纳但响应丢失、离开页面、凭据替换及窄屏布局。其生产调度器使用配置的等待阈值，没有启动任务 attempt 或模型请求。

# Agent Note: Bounded Team control-plane read pages

Status: implemented

English | [中文](2026-09-01-bounded-team-control-plane-pages.zh.md)

## Problem

The Team provider already read channel WALs in storage-sized pages, but its product-facing channel, Team, participant, and task reads could still return an entire logical result. Host, SDK, Python, and Web consumers therefore had no shared continuation contract, and a long-lived Team could turn a management request into an unnecessarily large response. Internal scheduler and recovery scans still need complete projections, so changing every existing full-read caller would mix product pagination with provider-owned replay.

## Decision

`clocky-team` defines separate bounded read seams: `listTeamsPage()`, `listParticipantsPage()`, `listTasksPage()`, and `readChannelPage()`. Collection requests carry an exclusive `afterCursor` and positive `limit`. Numeric collection pages use bounded look-ahead; Team discovery continuations account for scanned entries and can follow empty pages.

Team-list cursors are opaque positions in a bounded provider scan; archived and unrelated names consume scan work without becoming visible items. Participant and task cursors address stable provider order retained by their durable projection maps. Channel cursors are channel-WAL sequences. The local Hub caps requested pages by `recoveryPageSize`, validates channel record continuity, and applies view policies only to the records in the bounded page. Its existing full `listTeams()`, `listTasks()`, and `readChannel()` methods remain provider-owned seams for scheduler, recovery, and finalization scans.

Recovery Consumers commit a Team discovery cursor only after hydrating every summary in that page. Channel-admission and human-delivery queues reinsert the selected channel before propagating a transient Team, channel, storage, or admission failure, so the next bounded pass retries the same work instead of advancing past it.

The Host `team.list`, `team.member.list`, `team.task.list`, and `team.channel.read` routes accept optional cursor/limit fields and forward resolved defaults to the page seams. The TypeScript SDK protocol and high-level API expose the same fields and continuation results. The Python SDK forwards snake-case cursor/limit arguments to the same wire fields. The browser Team refresh follows Team-list continuation pages and exposes channel-page continuation through its runtime contract.

The existing `readAudit()` page now reads one bounded look-ahead record as well, so an exactly-full final audit page omits `nextCursor` instead of advertising an empty continuation.

Existing unpaged product callers receive the server's bounded default page; callers needing more data must continue explicitly.

Team discovery uses bounded backend name iterators rather than array ordinals or complete stream listings. SQLite seeks the name index; JSON examines directory entries without parsing bodies. Local opaque cursors retain at most a configured number of scans and one retry page per scan. `scanned` bounds actual discovery work even when no visible Team is returned. Expiration requests an explicit fresh scan. Scheduler discovery advances one page per pulse, and coalesced Team work returns to the event loop after one bounded round. Delegation also applies `maxOperationsPerDrive` to the entire returned round: self-generated WAL events cannot reset its budget, and continuing work is coalesced into one later event-loop turn per parent. Its routing caches retain unresolved child relations rather than lifetime child history: terminal snapshots discard routes but pass ancestry directly to the parent wake, and cold discovery does not reinsert them. Admissions pin every Team/channel projection they read. An archived Team and its audit handles release after its last admitted reader, and terminal channels release without waiting for unrelated watches. Reopening waits for the prior stream close. Completed admission scopes clear their reference sets so inherited async contexts cannot retain discarded projections. Discovery reads a tail summary committed atomically with each Team journal batch: JSON keeps it in the first line of the same atomic document, and SQLite updates its metadata row in the same transaction. `maxDiscoveryBytes` caps reads and rejects oversized metadata before append. Missing or mismatched summaries fail without full-replay fallback. A separate asynchronously maintained index is excluded because a crash could expose stale lifecycle state. Team journal format 33 requires these summaries; SQLite physical schema 3 stores them. Explicit hydration still owns full history validation.

`getTeamSelection()` exposes bounded identity, lifecycle, display prefixes, collection counts and an exact coordinator binding without materializing history arrays. The Host and SDK transports preserve this independent projection. The browser fixture and Hub share the pure `@clocky/clocky-team/selection` projector; it returns size failures as data, while each caller owns its transport error. The browser allowlist admits only that subpath, not the Team runtime entry. Pending startup yields `starting`; ambiguous or missing coordinators yield explicit unavailability. UTF-8 text truncation preserves complete code points, while routing metadata exceeding the configured total byte allowance rejects. Cold selection still hydrates the authoritative Team internally. `includeMetadata: true` adds exact goal, budgets and usage only when the complete response fits the same byte allowance; an explicit unavailable result preserves the lightweight selection on overflow. Pending human-action counts and cancellation text remain bounded display data.

`getMemberSession()` returns one retained member’s latest published activation/Session/provider tuple, including offline history. It never starts or resumes an Agent. The Hub caps this response with `maxSelectionBytes`; missing membership, missing binding and oversized identities fail explicitly. Host `team.member.session` and SDK `team/member-session` preserve the exact Team/member selection, and browser/SDK consumers reject mismatched response identities. Browser member inspection uses this point read without loading a complete Team.

`getHumanAction()` reads one current durable action by Team/action identity under `maxSelectionBytes`. Missing and oversized actions fail without a full-state fallback. Host `team.action.read` and SDK `team/action-read` preserve that selection; reading never admits an answer.

Team, channel and inbox lists, channel records and audit views each retain one provider page. Continuation replaces that window; failures preserve it. Team/channel list refresh rereads the current start cursor, and explicit first-page actions restart traversal. The selected Team, task and channel remain independent of list membership. Inbox paging uses the existing unsent-answer confirmation. Consent retry identity derives from the channel, participant, invitation revision and manifest fingerprint, so it needs no historical key cache.

The visible selection contains bounded scalar metadata and counts; execution records remain in independent collection windows and the task inspector. Initial and background reads use `getTeamSelection()`. Session summaries carry the immutable Team/Participant header identity. Coordinator input checks that pair against bounded selection on demand; only the current channel admission avoids a redundant ownership read. Historical routes have no independent cache. Draft entry releases selection and windows. The GC regression checks that previous selections and page windows release while coordinator routing remains usable.

`browse()` reads task, member and workflow list summaries. It preserves exact ids, protocol roles, revisions and counts while omitting instructions, grants, attempt/review arrays, DAG templates and result bodies. `maxSelectionBytes` caps each page, `maxSelectionTextBytes` caps text prefixes, and `recoveryPageSize` supplies the default and maximum row count. The page budget counts each row’s encoded bytes once, including JSON escapes and separators, instead of re-encoding the growing page. A byte-limited page resumes before its first unread row; an indivisible oversized row rejects. `scanned` includes ordinal-prefix traversal, so this API bounds response size without claiming bounded prefix-scan work or cold hydration. Host `team.browse` and SDK `team/browse` reject response scope mismatches.

`inspectTask()` separates editable current fields from settled attempts and review decisions. Indexed history windows avoid traversing the preceding prefix; `expectedRevision` prevents combining windows from different task revisions. Counts, ownership, attempt ordinals and continuation are validated across Core/Host/TS/Python. Capacity applies to the complete response before detachment; an oversized individual record rejects without preventing another section read. Child results retain their admission data without inventing Participant attempts; admission already prohibits private artifact references. The shared result projector removes private artifact references, including integration proposals, for both inspection and existing Host task/workflow reads.

Workflow inspection projects lifecycle/bounds and one task/dependency window from the serialized plan. It never copies the complete DAG or task results. Byte capacity includes lookup accounting, and continuation pins the plan revision. The browser lists workflow summaries and retains one independently cancellable inspection; failed and stale reads preserve the previous page.

The browser task workspace consumes task browse rows and independent inspection parts. Its latest-result reference is separate from the chronological history window, so paging cannot relabel an older result as latest. Current fields survive a failed refresh; revision changes retain visible data with a newer marker and disable mutations. A refresh replaces the record and invalidates histories from another revision. Off-page dependencies open the inspector without synthesizing a list row. Stop settlement reads only the inspected record; dismissal cancels reads, and module navigation retains the single bounded inspection.

Task Session navigation uses the existing bounded member binding read. A Participant retains its Session id across activation epochs, so the task view needs only the recorded participant identity and no activation-history array. Missing bindings fail without substituting another participant or resuming an Agent.

Pending-action previews are derived only from the current principal inbox page. Transient approval/question events mark new data available; they do not retain request bodies or replace the page. Durable updates reconcile matching visible actions by revision, and off-page updates only mark availability. Page changes release previews and question bodies. Channel retry fingerprints retain only a SHA-256 digest of canonical content, audience and delivery; the encoded media body is not duplicated in fingerprint state. Unchanged retries reuse their key, including edits reverted before resubmission. A confirmed send clears its inline text, media and retry state before awaiting channel refresh. Refresh failure does not turn accepted content back into a pending draft; an unconfirmed send retains its original error and retry state even when refresh also fails. The inbox’s existing unsent-answer confirmation governs explicit navigation; no automatic refresh discards drafts.

`inspectMember()` reads exact non-secret member identity and placement metadata with one indexed capability page. It does not copy other members, grants, startup reservations or derived attempt statistics. Capabilities retain exact strings and the entire response must fit `maxSelectionBytes`; oversized metadata or a single capability rejects explicitly. Continuation pins `expectedTeamCursor`, so membership changes require refresh. Host, TS/Python SDK, fixture and browser detail use the same data contract. The dialog replaces pages, retains a failed page, and aborts on close.

Browser draft retention uses validated public deployment limits: count and total serialized bytes across all channels, with per-draft byte accounting updated atomically. Overflow refuses the proposed edit without evicting another draft or admitting a send whose retry state could not be saved. Confirmed sends and explicit discard release slots. Clean view preferences have a separate count limit; draft-bearing views stay pinned. `client-modules.browserConfig` publishes only explicit JSON options for declared browser plugins, and the web Loader passes them through each plugin’s schema on page boot. Host configurations are never copied implicitly; deployment changes require a page reload.

## Alternatives considered

**Change the existing full-read methods in place.** Rejected because scheduler, recovery, finalization, and test-only authoritative scans intentionally need complete data. Mixing their contracts with product pages would either break recovery or force provider internals to reconstruct a full result from an API-shaped page.

**Let Host slice `getTeam()` or an already materialized full result.** Rejected because it leaves the provider and transport boundary unbounded and still makes channel reads reconstruct the entire WAL before slicing. The provider-owned page seams bound the response at the storage/projection boundary.

**Use a string token or a Team journal cursor for every list.** Rejected because participant/task list positions are projection-order cursors rather than journal positions, and introducing opaque token persistence would add state without improving the local pre-release contract. The distinct numeric cursor semantics are documented per list family.

**Return `nextCursor` whenever a page is exactly full without look-ahead.** Rejected because an exactly-full final page would advertise a phantom continuation and cause an avoidable empty request. One bounded look-ahead record makes exhaustion explicit while keeping memory bounded.

## Consequences

The management plane has one page vocabulary across local Hub, Host, TypeScript SDK, Python SDK, and Web refreshes. A response is bounded by the caller's limit and the Hub's configured recovery size; channel view projection no longer requires a complete WAL in the product read path. The trade-off is that list traversal is a caller responsibility, and concurrent insertions can be observed according to the documented provider-order traversal semantics. Full provider scans remain available only to code that owns replay or repair.

Core schema, JSON/SQLite Hub restart, Host fetch, SDK server forwarding, Web refresh, and Python wire tests cover page limits, cursor advancement, final-page exhaustion, channel look-ahead, and restart reconstruction. Property/model-based, real-model, distributed, browser/GIF, and load/retention evidence remains pending under the [native multi-agent work-system proposal](../../proposed/architecture/2026-08-27-native-multi-agent-work-system.md).

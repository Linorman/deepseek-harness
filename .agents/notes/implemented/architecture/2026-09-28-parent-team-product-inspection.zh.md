# Agent Note: 父团队授权的 Team 产品检查

Status: implemented

[English](2026-09-28-parent-team-product-inspection.md) | 中文

## Problem

委派子团队使用父服务端点，不包含父用户的人工成员。每次名称查询都要求目标团队内的人工成员，会阻止用户检查已委派工作。未保护的集合读取会向其他已认证主体暴露无关团队；创建虚拟子团队人工成员又会暗示未获支持的修改和同意权限。

## Decision

`resolveHumanReadAuthority()` 沿规范委派选择最近的 active、由当前主体拥有的人工成员。每条父关系必须匹配子团队深度和父任务、任务保留的子团队 ID 与创建身份，以及任何已发布的子团队绑定。Hub 加载有限祖先链，再按祖先优先顺序加锁重新检查。缺少成员资格与缺少 Team 返回同一检查拒绝；成员资格有歧义时直接拒绝，不改选其他祖先。

人工 binder 将身份、就绪度、频道列表和频道内容读取 proof 锚定到该成员所属 Team。Fingerprint 保留完整目标 payload。Hub 解析 proof 时重新检查当前成员资格、唯一性、保留的委派链和准确操作／payload。修改、执行配置、任务能力和邀请同意 proof 仍要求目标 Team 内的成员资格。父团队检查不授予这些操作。

Host 的选中 Team 元数据、成员绑定、任务／工作流检查、集合、人工事项、审计与静止状态读取，在读取期间保留 active proof，并在返回成功或失败前重新验证。产品选择返回 Host 计算的 `readAccess`，拒绝调用者自报的访问元数据。Provider 将该字段计入完整选择响应字节额度。工作区标明父团队只读检查，移除修改、取消与恢复回调，并保留身份及执行检查。

[身份缓存决策](2026-09-28-team-identity-resolution.zh.md) 继续拥有缓存生命周期和主体代际规则。[关闭决策](2026-08-31-team-closure-authority-and-detail-inspection.zh.md) 继续拥有取消准入与静止状态。Host 仅针对已知的待清理错误，核对准确的持久 TeamRun 取消 key 并重新检查读取权限；返回观察到的 phase，不承诺清理已经进入终态。缺少取消意图或无关实现错误仍会拒绝。

## Alternatives considered

**将父用户的人工成员加入每个子团队。** 这会增加检查不需要的端点、同意与修改责任。

**接受任意声明的父 ID。** 单个父字段不能证明规范任务 reservation 或委派身份，不能授予数据访问。

**对子团队页面采用未保护的读取。** 这会绕过当前主体成员资格并允许读取无关对象。

## Consequences

检查遵循持久委派归属，执行仍由现有所有者管理。产品目录、原始频道和产物读取遵循[主体目录决策](2026-09-28-principal-team-directory-and-readers.zh.md)。全局事件广播、Session API 和 SDK 管理读取仍需各自的授权审计。

## Verification

JSON 与 SQLite 委派测试覆盖父团队检查、准确目标 fingerprint、已撤销 proof、禁止子团队修改，以及无法区分的缺失／私有 Team。Host 测试在存储读取之前拒绝未认证或其他主体，拒绝自报访问元数据并保留撤销检查。选择投影测试覆盖准确字节额度。真实 Host 浏览器场景提供可取消的子模型，检查运行中的子团队及成员，恢复深链并观察父／子团队取消，不伪造执行事实。

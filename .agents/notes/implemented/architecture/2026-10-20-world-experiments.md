# Agent Note: Isolated world experiments

Status: implemented

English | [中文](2026-10-20-world-experiments.zh.md)

## Problem

Changing IDs in historical proofs would transfer authority across experiments. A portable cut needs a new execution identity and an explicit record of inherited facts and model input.

## Decision

[Branch initialization](../../../../packages/simulation/simulation-team/src/experiments.ts) creates new writable owners rather than modifying identifiers inside historical evidence. The Native `run/branch-init` retains the exact source cut, original command namespace, memory policy and budget before ordinary entity, Team, Participant and Channel creation. Initial-world and settled-world cuts are supported seed formats. Settled cuts preserve current entities, relations, balances and simulated time; new text facts cite the branch-init event, and inherited private statements become explicitly new beliefs. Pending obligations, events and unknown effects reject rather than lose their original owners. The installed Native provider replays the immutable prefix in memory with the same projection invariants as ordinary inspection, without accessing original storage; archive closure hashes alone cannot validate a snapshot projection. A separate storage owner retains the exact parent archive, and branch exports recursively carry read-only provenance under complete byte, aggregate entry and eight-parent depth limits.

Both memory policies retain authored profiles and scenario facts. Public-facts omits initial private knowledge and Session histories; authorized-memory derives each actor's actual original model history through detached `Session.create(...).deriveMessages()` and records its text in the new Session; raw internal proofs, billing and non-surface metadata remain solely in provenance audit, with source hash and policy. Inherited Sessions are persisted detached; seed actors resume those actual logs on first activation, while later generated actors retain normal fresh startup. Neither policy transfers a signature, receipt or original execution authority. Real effects remain disabled. Exact command retries reopen the original namespace and reconcile original identity reservations and already persisted inherited input; a changed source or payload rejects.

[Causal queries](../../../../packages/simulation/simulation-team/src/experiment-query.ts) derive edges directly from explicit Native record references, ignoring snapshot relationships. The manifest uses B1's complete-prefix hashing convention. Current source permissions apply on every read; denied nodes do not contribute edges or existence counts. Complete result bounds apply after metadata wrapping. Comparisons require the same parent cut, normalize explicit lineage identity fields, preserve ordinary text, and distinguish unavailable quality/cost evidence and nondeterminism from recorded factual differences.

## Alternatives considered

Rewriting parent logs would invalidate evidence. Copying the current snapshot wholesale would retain old executable identities and approvals. Fresh owner commands instead establish every supported new fact, with the original history held separately as provenance.

## Consequences

[Owner tests](../../../../packages/simulation/simulation-team/tests/experiments.spec.ts) cover JSON and SQLite Loader compositions, partial initialization retries, dynamic cut time, fresh canonical identities, public/private memory isolation, actual inherited Session input, writable branch facts and original-run preservation, exact Native reopen, permission fences, tiny byte limits and snapshot-forgery-resistant causal indexing. The [two-process snapshot](../../../../examples/simulation-company/tests/world-experiments.snapshot.ts) exits after durable partial allocation and resumes the original namespace in another process.

Seed owners for federation sources/provenance, institutions/committees, external identities, environment/evolution state, pending obligations and future events remain unsupported, as do other intervention variables, total lifetime token budgets, model-judge quality integration and automatic history merges. The declared token budget is the Native interval budget. The supported dynamic seed format refuses unrepresentable duties; Product retains original acceptance and completion in its own branch command journal, preflights before acceptance, and creates a new `world/1` checkpoint, WorldOwner and paused directory entry; cold restore supports explicit start/pause. V0 sources require a current Host catalog whose pure compilation exactly reproduces the original resolved semantics; that complete catalog is retained at acceptance and all retries use the frozen original. V1 retains its self-contained compiler input. Host, Client and both SDKs use the same branch/read/compare/causal owners with independently checked private full-record grants. Branch backups carry readonly parent provenance; see [Product experiment tests](../../../../packages/simulation/simulation-product/tests/experiments.spec.ts) and [README](../../../../packages/simulation/simulation-product/README.md). Authorized-memory currently accepts textual Session history only and rejects media/nontext blocks in pure preflight; public-facts can omit those private media inputs.

Initialization and inherited-input payloads use version 2; Native replay rejects the version 1 raw-event memory format without conversion or rewriting originals. Ordinary journal-101 runs without branch initialization remain readable. Remapping follows declared Entity references; resources, facts, knowledge, relations and templates keep their own run-local IDs, and text/Persona names remain unchanged. Missing declared Entity owners reject during pure preflight.

Branch preflight requires a one-to-one Entity mapping: a long source ID and a short ID equal to its shortened digest reject before target allocation. The existing mapping remains stable for accepted commands. Inherited Session recovery distinguishes a lazy in-process reservation from a durable header through the persistence inventory. A failed first append can resume that reservation; a committed append with a lost reply is verified and never repeated. Current authorization is checked again after lazy header creation and before the inherited input append. JSON and SQLite tests exercise both failure boundaries and reject colliding identities before creating a target.

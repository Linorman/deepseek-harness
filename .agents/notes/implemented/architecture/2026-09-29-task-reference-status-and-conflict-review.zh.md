# Agent Note: 任务引用状态与冲突核对

Status: implemented

[English](2026-09-29-task-reference-status-and-conflict-review.md) | 中文

## 问题

候选页缺少的依赖可能离页、已删除或不属于所检查的 Team，编辑器不能按页面成员关系区分。只显示当前说明的 revision 提示，也会隐藏待提交名称或依赖的覆盖。

## 决策

Hub 在 Team 串行队列中只解析明确请求的任务 ID。`team.task.references` 返回有界标题、revision 和生命周期状态，包括保留的删除 tombstone；未知和其他 Team 的 ID 使用相同不可用结果。条目不包含说明、结果或历史。请求 ID 唯一，offset 指向该输入向量，续页固定 Team cursor。查询使用既有 provider 行数、文本、输入和完整 JSON 字节额度。

原生受信消费者与任务检查一样负责自身授权。Host 在 provider 工作前及成功／失败返回后检查直接或规范父团队读取权限。可读依赖和状态提示不授予修改权限。

一个 runtime 读取器拥有表单当前及待提交引用的并集。公开浏览器容量、批量和刷新额度约束观察。完整同 revision 结果原子发布；旧或不匹配页面被拒绝，替换读取会取消，普通失败／断线保留内容，权限收回则清除。它不遍历候选页来推断引用。

当前任务刷新后，冲突核对比较 `taskUpdate` 接收的全部字段：去除首尾空白的名称、完整说明和精确的待提交依赖列表。过期记录在刷新前继续标明。用户明确确认当前 revision 之前，可看到将覆盖的字段。已删除／不可用依赖保持已选且可移除；只有用户明确移除并取得当前引用状态后，提交才可用。候选、草稿和精确引用事实分别归属不同 owner。

## 考虑过的替代方案

**把候选缺席当成删除。** 分页和标题筛选会从该窗口移除合法依赖。

**加载全部候选页。** 会绕过额度并混合不同 revision。

**为每个依赖读取完整任务历史。** 显示／状态查询会取得无关 payload，并争用所选任务检查。

**自动移除拒绝的依赖。** 会未经确认修改用户的依赖图。

## 影响

引用未知或读取失败时可能暂缓提交，同时保留输入与移除控件。超出容量时拒绝，不截断已选集合。读取投影没有增加任务更新命令 receipt 或未知结果恢复；该协议仍是独立工作。[草稿生命周期决策](2026-09-29-team-form-draft-lifetime.zh.md) 继续负责保留、额度与关闭。

## 验证

Core 测试覆盖请求顺序、tombstone、不可用 ID、UTF-8 响应额度、精确 offset 和 wire 拒绝。JSON／SQLite 测试保持原 Team 状态。Host 测试在 provider 前拒绝未授权读取，并在认证退役后扣留成功／失败结果。Runtime 测试覆盖原子分页、过期 revision、容量、替换、轮询、取消与重连。组件测试比较三个可编辑字段，要求明确移除已删除／不可用 ID。真实 Host/keyless 任务草稿场景覆盖当前比较与删除流程。

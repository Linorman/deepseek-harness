# Agent Note: Independent Simulation browser viewing

Status: implemented

English | [中文](2026-09-29-simulation-browser-viewing.zh.md)

## Problem

Simulation metadata APIs need a browser entry that neither masquerades as a Team workspace nor starts execution. Browser disconnection, authorization replacement and late responses must retain or clear content according to their actual meaning. Business state cannot migrate into React viewing stores.

## Decision

The opt-in [Simulation UI](../../../../packages/client/ui-simulation/README.md) contributes a navigation entry and a layout-owned `simulation.workspace` slot. Its Host entry requires the product directory; absent composition advertises no navigation. Shared layout viewing state chooses Team or Simulation through `showWorkspace()`, preserving the established Team/Session subtree. Product selection appears in the URL, and an unavailable Simulation deep link retains a return action.

Read-only Team selection does not require a bound coordinator. Coordinator-free Simulation Teams expose their authorized modules and exact member Sessions without inventing a transcript. Explicit Team open/start/resume retain a required coordinator result, and the coordinator action is absent until bound. Destination restoration clears an earlier Session inspector before validation, so a refused exact reference leaves its error and recovery action reachable.

Cross-product inspection uses the shared layout navigation service and exact Team viewing URLs. It pushes history without reloading retained drafts, restores product visibility on Back/Forward and notifies route owners on same-document transitions. Team URL keys have one owner; read links remove inherited mutation forms. The destination owns authentication, object membership and exact participant/Session validation. Historical Session references never redirect to a replacement binding, and unmaterialized references remain inert. Product registration ownership supplies no Team access. Simulation source and object panels share the same semantic read-link component.

Client runtime owns `simulationRuns`, with one response page per directory/status/run/collection/object/template/control family. Each request has a cancellation lifetime and captured authorization generation. Completed handshakes enable reads; account replacement and explicit denial clear business content, while ordinary network loss retains marked stale pages. Viewing stores contain navigation, committed search, scroll position and bounded raw creation input. Business receipts and immutable submitted requests stay in runtime. UI hooks arrive through the framework's existing inject binding; components receive no Context or service objects.

Committed collection status/cognition filters, related entity/decision IDs and operation sections live in view-only URL state. Unsupported selectors are removed before bounded Host queries. Publication attempts and checkpoint references page independently of the collection; continuation fences the observed revision, while first-page refresh clears that fence. Failed reads retain content and disable next-page actions. Switching runs retires both the browsing inspector and recovery-source requests before clearing their responses.

Retired Simulation actors can retain Team-bound Session logs without a filesystem cwd. Product listing and cold history/media inspection accept that persisted provenance only after current Team read and exact member/Session checks. Read-only source inspection compares returned header identity and lineage and rechecks authority after IO; ordinary locationless roots and generic Agent recovery remain restricted. It creates no Agent or run owner.

Team selection and directory summaries expose only a `simulation-managed` execution marker derived from immutable native rules, without publishing the run identity. The browser removes ordinary Team lifecycle, mutation, send and answer actions for these Teams; bound Session inspection omits composer/queue/approval controls while retaining the input owner and its draft. Hub and Host independently reject ordinary human writes and return a known policy refusal, including callers bypassing UI hints. Simulation-scoped proof owners retain their original operations. Reading permission remains separate and is not implied by run ownership.

The page uses shared controls and workspace tokens. Simulation time and IDs stay strings. Saved running scheduling, observed ownership, accepted decisions, applied effects, publication and recipient facts retain independent meanings. Object details are non-modal, and narrow layouts provide one primary surface with a visible return action. Neither navigation nor reading has an execution command.

Original command ownership is independent of navigation and transport waiters. The registering UI plugin creates a bounded runtime owner that captures the authoring authorization version, retains the complete original input before IO and queries or retries only that identity. Count and full UTF-8 byte limits preserve prior records on refusal. Unknown or in-progress originals cannot be released; `not-found` neither establishes failure nor permits automatic replacement. Account retirement clears private originals and drafts before late response publication. Ordinary disconnect preserves them. Creation uses installed templates, keeps raw later edits separate, and guards reload/input discard. A valid transport with insufficient administrative permission does not imply loss of separately authorized viewing permission.

Scenario task review has a separate overview page and form; ordinary Team writes remain closed. The Host exposes only fixed inventory-transfer/report-publication evidence and exact operation/attempt/reviewer/revision metadata. Runtime retains one cancellable page, treats review-read refusal independently from metadata viewing and compares recovered original selectors and canonical reason before admitting a query result. Private drafts use run/operation/attempt slots under the shared input count/UTF-8 allowance. Closing or disconnection retains input; authorization replacement clears it. An unknown command only queries/retries its original payload, commands normalize reason whitespace while retaining raw submitted input, and completed results clear only that unchanged raw draft, including preserving later whitespace edits. Terminal failure requires a semantic edit or explicit revision confirmation before another command. Review-write refusal preserves authored input and independent viewing; actual authentication retirement still clears them. Explicit revision confirmation can update only the same attempt; replacement attempts cannot silently inherit an old review. Review originals never enter maintenance forms. The [native review authority](2026-10-01-simulation-task-review-authority.md) owns dormant-reviewer admission and durable retry attribution.

Directory status has its own exact ordered-ID read family, restricted to the current bounded name page. Names and operational observations settle independently; replaced names retire old status IO, ordinary failures preserve visibly stale status and known denial clears protected metadata. The Native batch and administrative enrichment expose safe current clock/version/usage, scheduling-stop and scenario facts without opening a writer or publishing action grants. Unknown or failed observations never become zero, and scenario identity never comes from a display name. One persistent status/control header owns explicit actions in every module; compact maintenance opens the same retained dialogs. Native budget charges include reservations and unresolved inference; real-time Host-wide model permits and queue occupancy remain a separate observation.

Directory selection reserves its own ordinal before status publication and retirement callbacks. Reentrant subscriptions or abort listeners selecting another directory/run invalidate the old continuation before IO; response publication accepts only that original ordinal and generation. Simulation directory, overview and request history use workspace scrolling; collection tables and non-modal details own their reading regions. A natural-height header and module navigation remain outside the collection scroll region. Scroll ownership moves with the retained directory/collection viewing context, while dialog scroll stays local.

External retry permission and target reconciliation have separate owners. A bounded unknown-operation preview locates exact metadata without scanning native histories. Its form captures the current original attempt-count fence and Host allowability; immutable normalized commands live in runtime and raw later reason text stays in the shared-capacity viewing store. Original lookup checks every selector and canonical reason. A completed grant records permission only, and target retry requires an explicit scheduling action. Changed intent cannot overwrite an uncertain original, and terminal refusals need a semantic edit or deliberate current-fence verification. Structured checkpoint/restore diagnostics render only fixed stage/code and canonical run/entity/checkpoint/Team/channel/Session subjects; complete ownership references navigate through the existing read owner. Private errors remain backend-only, and cleanup uncertainty never becomes proof of quiescence.

Control polling observes the product scheduler without opening a writer. Host hints and immutable budget/model limits govern start confirmation; native writes recheck admission. Valid existing controls remain usable during background refresh. Unknown original intents block another identical new intent. Pause and in-flight cleanup remain separate observations, and newer control revisions mark metadata counts for explicit refresh.

The gateway's Service facade forwards the complete Simulation namespace. Browser config is explicitly supplied through the modules plugin's `browserConfig`; Host plugin configuration does not implicitly become browser configuration.

The [Team workspace decision](2026-09-11-team-workspace-ui.md) remains active for its own domain. The [product directory decision](2026-09-29-simulation-product-directory.md) retains persistence, authority, projections and metadata limitations; this record owns browser composition. Neither is fully superseded.


The [workspace hierarchy decision](2026-10-01-webui-workspace-hierarchy.md) owns presentation hierarchy, source-return feedback and request reconciliation. This record retains its independent composition, authorization and lifetime contracts.

## Alternatives considered

**Present Simulation as a Team tab.** Team control semantics do not own simulation scheduling, preparation or cross-owner recovery.

**Keep API responses in the UI store.** It duplicates the business owner and allows component lifetimes to alter authority and request cancellation.

**Open native runs from the browser page.** It turns browsing into execution ownership and conflicts with held coordinators.

Journal metadata and original text use separate runtime windows. The plugin-owned record exporter retains only bounded transient text outside React, validates contiguous original parts and record totals across one revision, and rechecks policy before synchronous file delivery. It discards bytes on cancellation, authority/selection changes and failed reads; completed downloads become user-owned files. Browser limits cap complete UTF-8 output and pagination work.

Source selection retains only a decision ordinal in view state; the original page and its Team-dependent permission belong to runtime. A bounded post-read poll covers independent Team membership changes, while known revocation frames immediately retire the single page, including canonical-parent dependencies. Policy and connection retirement reject old replies; ordinary network loss remains visibly stale. Source continuation binds the frozen decision and exact original identity rather than the advancing world tail, so live runs do not repeatedly reset historical text.

Creation accepts only Host-advertised editable allowances and retains their raw overrides in bounded memory. Runtime-owned preflight allocates no command and displays fixed Host concurrency; actual creation repeats the check before minting an original. Draft edits, dismissal, view pause, connection and authorization replacement retire old validation, so a late success cannot create a run. Field rejection preserves input and focuses its first error. Tick horizons retain decimal strings; integer capacity and token controls refuse unsafe Number values.

Request history under More reads receipt-only administrative history after renewed authentication, independently of cleared private authoring input. Its cursor/revision belongs to the command journal, so Native world progress cannot invalidate it. Cold original selectors retain only runId/commandId; explicit retry invokes the Host-retained semantic payload, and terminal receipts never execute again. Warm commands keep their original payload family. Metadata queries do not resume work; cold review/grant still requires an explicit restored owner. Navigation retires old response and refresh callbacks, while accepted Host work survives.

Task cancellation retains a separate run/operation draft and required nullable attempt fence. The bounded task window belongs to runtime, while raw reasons share the existing draft allowance. Original selectors reopen only their cancellation form; unknown results query/retry the immutable original. Native cancellation is durable before physical drain, so late work rejects while cleanup responsibility remains visible. Existing applied effects are retained.

## Consequences

Installed administrative compositions expose creation, explicit scheduling, checkpoints, recovery and entity input. Separate grants govern frozen context, knowledge, source originals and journal export; metadata references grant no Team/Session content access. Full language/theme/accessibility/recovery matrices and additional reviewed automatic scenes remain separately tracked in the [implementation plan](../../../../design/webui-team-simulation-2026-09-28/implementation-plan.md).

## Verification

Runtime tests cover query replacement, late responses, view pause, disconnection, authority replacement, stale pages and denial. Layout/Team/sidebar regression preserves existing navigation. A real Loader/Host browser scenario uses a held native run, reads bounded registered/Entity pages, reloads object deep links and checks desktop/narrow rendering, clean console, unchanged phase/revision and no model flow. This evidence does not establish creation, checkpoints, restoration or automatic execution.

The [administrative browser scenario](../../../../apps/web/tests/simulation-administration.snapshot.ts) drives real JSON/SQLite Loader, HTTP/WebSocket, native actor/tool and inventory paths with only external inference scripted. It verifies creation response loss and same original retry, paused creation/reload without inference, budget confirmation, in-flight pause, explicit continuation, current inventory, native three-tool requests, credential replacement and draft clearing. Scoped persona output is pinned in the browser snapshot. Focused runtime command/read tests exercise cancellation, stale authoring, complete-byte refusal and account retirement. This evidence does not establish Web maintenance or automatic task execution.

The [metadata browser scenario](../../../../apps/web/tests/simulation-workspace.snapshot.ts) checks committed status/cognition filters, successful empty results, URL reload, related-entity scope and browser Back. The [maintenance browser scenario](../../../../apps/web/tests/simulation-maintenance.snapshot.ts) reads actual JSON/SQLite production publication attempts, preserves them after a lost read, follows decision/operation links and pages full checkpoint sources without changing world state or inference count. Component cases cover both locales and continuation refusal; runtime regression retires a pending recovery-source response when selecting another run. These checks do not establish private-body reads, event export or the full acceptance matrix.

The journal browser scenario validates JSON/SQLite metadata and original downloads against native records, cancellation without a file, failed-page retention, source sequence reload, policy revocation and narrow original-part continuation. Runtime tests cover byte/page bounds, incomplete/repeated parts, final verification, old responses and authority/selection retirement. These checks do not establish the remaining full language/theme/keyboard matrix.

The [external-operation retry browser scenario](../../../../apps/web/tests/simulation-operation-retry.snapshot.ts) verifies JSON/SQLite production target publication followed by response loss and exhausted original allowance. Grant, original lookup and exact retry leave phase/model dispatch unchanged; explicit scheduling returns the same Envelope ID with exactly one target WAL record. Original sender decision/inference and its complete decision-correlated token reservations remain unchanged, and each captured model attempt resolves to the persisted Session context-input ID and reconstructed request-header route. Three tool rounds are separate model attempts within one decision, not three replayed decisions. A real canonical Session read failure after a successful checkpoint produces only structured collection/source-unavailable diagnosis, with its exact Session/Team binding, no private error strings and the same diagnostic on original lookup after administrative cold reload.

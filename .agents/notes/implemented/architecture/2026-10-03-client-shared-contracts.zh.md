# Agent Note: Client 共享契约与 Team 读取所有权

Status: implemented

[English](2026-10-03-client-shared-contracts.md) | 中文

## Problem

Client 契约导入了实现这些契约的领域；兄弟 UI 领域直接导入彼此的输入类型、渲染指令与会话读取器，因此领域依赖门禁拒绝这些边。Team 读取器还重复实现了取消、已授权窗口发布与日志水位处理，使同步 abort 回调所需的顺序分散在多份代码中。

## Decision

运行时 `contract/` 层拥有共享会话快照、待响应载体、上下文来源、Agent 上下文类型、Session 服务类型、Team 读取类型、Workspace 列表类型及通用通知器。实际作用域创建留在生产所有者 `sessions/` 中。共享声明包含自身定义，不能重新导出领域实现。

会话 `contract/` 层拥有多个领域使用的输入数据、输入阻塞器、队列投影、装饰指令、引用图标、会话读取器及数值展示辅助逻辑。输入状态机与阻塞器注册表留在 `input/`，聊天渲染留在 `chat/`。Workspace 浏览器和行组件共同归属 `rows/` 领域。现有包导出与行为保持稳定。

Team 读取器各自拥有独立的 `ReadRequest` 实例。取消先推进代次，再停止定时器或执行 abort 回调，并在取消前清除旧请求载体。完成操作只释放自己的载体，且只有该载体仍是当前请求时才安排轮询。`ReadPageRevision` 保留当前选择的最低日志游标；对应 Team 的更新将较旧的已加载页标记为过时。每个读取器仍负责自身端点的身份与分页校验。授权拒绝先撤销私有数据，再通知 Team 所有者；普通失败保留已授权内容。

Team 选择、归档、任务变更协调及重连复用现有清理和发布操作。会话中的 Team 频道来源通过会话表面的 `deriveEventMessage` 推导，使持久化事件的模型和 UI 来源投影一致。

## Alternatives considered

**通过契约重新导出的外观。** 经 `contract/` 重新导出实现类型仍使共享层依赖其领域，只隐藏所有权问题。共享定义应实际位于契约层。

**将所有实现移入契约。** 状态机、端点检查器和注册表保留领域所有权。公共层只承担共享数据、响应载体、可观察投影及纯展示操作。

**共用一个 Team 请求控制器。** 读取器需要独立选择和取消。通过独立实例复用生命周期规则，可以防止一个视图的导航取消另一个视图的请求。

## Consequences

Client 领域依赖门禁通过，无需例外。Team 读取器的共同规则只有一份实现，各读取器仍负责自身保留数据、轮询及版本校验。包内部被移动文件的导入指向当前路径，对外包 API 继续可用。

## Testing

运行时、会话与 Workspace 测试通过：92 个文件、1,260 项测试。现有读取器测试覆盖过期响应、授权撤销、精确分页，以及替换或关闭选择的重入 abort 回调。运行时与会话的定向重复代码扫描报告零处重复，Client 领域依赖门禁报告零项违规。

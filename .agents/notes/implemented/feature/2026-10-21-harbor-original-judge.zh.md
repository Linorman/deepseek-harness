# Agent Note: 河港原始裁判接入

Status: implemented

[English](2026-10-21-harbor-original-judge.md) | 中文

## 问题

独立河港裁判不能直接导入为 World 定义。接入和恢复必须保留其私有角色视图、独立身份与原始日志，不能替代自主动作。

## 决策

可选的[河港 provider](../../../../packages/simulation/simulation-world/src/harbor.ts) 通过已有 Native 领域和 World execution 扩展点注册原独立案例裁判。它校验固定源文件清单，并隔离每个运行的裁判日志。原始角色的独立 Session 选择业务动作，发起者 Session 选择实验控制。技术 director 必须保留提交载荷，由 Host 提供规范 Team/Session 来源。

适配器在模型消费前记录公共观察和独立授权的角色视图。原始裁判的视图身份绑定具体修订，因此交易串行结算后才准入下一位角色。初始机会和后续响应展示当前信息，不选择动作。显式唤醒批次的全部角色结算后才再次提供发起者机会，否则不完整批次可能被误认成已完成跟进。交替安排其他响应和发起者机会，避免对话流量无限延迟日期与检查点决策。发起者唤醒要求采用有界多日规划，按证据选择跟进对象，避免默认每日轮询全部角色；每个日期与角色仍由模型选择。进度统计来自已记录的接受回执，只有原始审计决定机械完成。

## 替代方案

**固定事件日历。** 把案例改成固定事件日历会用脚本历史替代自主选择。

**单一共享角色。** 将全部私有视图交给单一 Session 会破坏独立身份和信息限制。

**合成裁决证明。** 伪造模型消费证明来自动裁决会绕过 Native 权限。因此 provider 对全部十四个原始技术及案例角色使用正常观察和提交的模型决策。

## 后果

未修改的原始 CLI 负责业务有效性与守恒。Native 记录包括裁判拒绝在内的类型化回执；回执提交本身不代表业务接受。缓存执行身份用于中断对账，已有 Native 观察必须保有原案例日志。结果不明时保留对账责任。恢复或无效模型提交都不授权改写原始历史。

新增案例角色仍由其创始人的 Session 代表，不声称它们具有独立生成的认知。模型不能选择源文件和 provider 凭据，案例子进程不接收 provider 凭据。部署必须将案例目录与 Native、Team 存储一起保留。

全年安装提供有限的长程额度（每七日区间一亿 token、每 Team 沿用字段的二十亿模型输出 token 上限）。发起部署必须允许相同的 Team 上限。初始真实试运行到第 1 日已消耗超过六百万额度计量 token，包含缓存读取；短场景额度会在形成有效跨期覆盖前中断实验。单次请求额度显式设为 262,144 token；原 65,536 token 默认额度在第 2 日即使压缩成功仍拒绝请求。案例指令优先使用有界观察回执，避免重复当前视图。Team 信封和计划字节额度也容纳原请求及其路由元数据。这些是准入上限，不是要求模型生成的数量，也不承诺完成。已有运行保留原冻结额度。

原始裁判给报价 ID 添加 `order-` 或 `loan-` 前缀，因此生成引用可能超过输入身份长度上限。第 2 版在命令和审计回执中允许这些精确引用。第 1 版为保留上下文证明维持原解析器对象及序列化 schema 哈希；provider 注册两个精确版本，新创作选择第 3 版。即使历史值同时满足新旧长度限制，直接替换 v1 schema 也会破坏已消费 Native 上下文哈希。

第 3 版区分角色请求与 director 计划：apply 计划仅携带 `{forwardOriginal:true}`，其 Native 请求身份绑定完整的原角色载荷。真实 director 仍观察并提交带理由的模型决策，不合成消费证明或业务动作。执行器读取已绑定请求，原始裁判继续负责判定。早期转抄版本为保留证据维持原样。真实转抄试运行反复改动长请求正文，使合法原动作也无法继续，因此不再要求模型逐字转抄。

## 验证

[可运行 Loader 场景](../../../../examples/simulation-company/tests/harbor.snapshot.ts) 在 JSON 和 SQLite 上覆盖四个独立角色提交的五次实质决策、推进日期后的新视图、完整的多角色唤醒批次、多收件人交易、全部十四个绑定 Session、空闲结算和新进程恢复。案例单元测试覆盖固定清单完整性、幂等、原日志缺失、私有角色权限、插件卸载、最长生成引用以及不可变 v1 schema 哈希。真实 WebUI 完成属于独立验收要求：这些短测试不能证明 365 日覆盖或最终审计成功。

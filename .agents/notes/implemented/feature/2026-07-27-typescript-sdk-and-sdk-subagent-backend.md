# Agent Note: TypeScript SDK client and the SDK subagent backend

Status: implemented

English | [中文](2026-07-27-typescript-sdk-and-sdk-subagent-backend.zh.md)

## Problem

The stdio JSON-RPC serving surface (`@clocky/clocky-sdk-jsonrpc-server`, the [single-exe Agent Note](../architecture/2026-07-10-single-file-executable-sdk-runtime-distribution.md)) had exactly one client: the Python SDK. TypeScript consumers wanting the same drive-a-harness-as-a-subprocess capability — repo tests, automation, and above all a subagent backend whose child is a *complete harness runtime* rather than a generic ACP agent — had nothing to import: the request/notification payload shapes existed only as anonymous object literals inside the server, and the transport class lived inside the server plugin package.

## Decision

Three packages, layered exactly like the existing Python stack, plus one Service Provider registration:

- **`@clocky/clocky-sdk-protocol`** (`packages/sdk/protocol/`) — the wire made shared and nominal. `JsonRpcLineTransport` moves here verbatim from `clocky-sdk-jsonrpc-server` (which now imports it), and `types.ts` names every payload the server speaks: `InitializeParams/Result`, `TeamCreateParams/Result`, `TeamWaitFinalParams/Result`, `TeamCancelParams/Result`, the notification payloads, and the `HarnessSdkRequestMap`/`HarnessSdkNotificationMap` indexes. The package root explicitly exports that complete interface and provides no source-module deep imports. The server's `notify()` call sites are typed against these named payloads, so server drift breaks compilation, not clients. An error response rejects with `JsonRpcResponseError` carrying the wire `code`/`data`.
- **`@clocky/clocky-sdk-client`** (`packages/sdk/client/`) — the TypeScript twin of `python/sdk`: `HarnessClient` (spawn, frame, fan out notifications, typed error surfaces, close-to-quiescence via the shared dispose ladder) under `Clocky`/`HarnessTeam` (lazy start, memoized `initialize`, default-Team creation, explicit final waits, and Team cancellation). Its package-root consumer interface explicitly exports both client layers, caller-facing types, and the protocol-owned `JsonRpcResponseError`; source modules, normalization helpers, and the notification producer stay internal. `RunResult.events` contains only the coordinator Session's typed events, while `notifications` retains session ids across that coordinator and descendants discovered from `subagent.started`; session-tree scoping is client-side, mirroring `client.py`. Deliberate asymmetries with Python: the launch spec is explicit `command`/`args` (no bundled-runtime resolution — that is a distribution concern with no TS consumer yet); `env` replaces rather than merges (callers own credential policy; `scrubbedParentEnv` from the subprocess seam is one import away); `RunResult` carries an explicit Team final receipt; teardown walks a private stdin-EOF → SIGTERM → SIGKILL ladder to actual exit (the client runs outside any harness context, so it cannot ride `ctx.subprocess`).
- **`@clocky/clocky-subagent-clocky-sdk`** (`packages/subagent/subagent-clocky-sdk/`) — the second out-of-process `SubagentProvider`, structured as `subagent-acp`'s sibling: same all-false capabilities and `inheritsParentContext: false`, same publish-after-handshake ownership transaction, same result-never-rejects flattening through an `onError` sink, and same parent-namespace run id. It creates a default child Team through `Clocky.createTeam()`, waits with `HarnessTeam.waitForFinal()`, and reads streamed coordinator `session.event`s: the last complete `assistant/message`, else accumulated `text-delta` chunks, with explicit Team final text as the fallback when no output committed. A successful Team final maps to `completed` regardless of a coordinator turn reason; local cancellation requests `HarnessTeam.cancel()` and maps to `aborted`; failed Team operations and transport faults map to `error`. Its `provider`/`model` config feeds the child's `initialize`; `env` is where deployments pass the child's own key and `CLOCKY_CORDIS_CONFIG`.
- **The subagent seam grows `out-of-process.ts`**: the provider-side vocabulary both out-of-process backends share — `NO_START_CAPABILITIES`, timing-bound validation, child cwd resolution (config override, else the delegating parent session's workspace), the never-reject `settleRunResult`, and the `subprocessRunHandle` publication. Process mechanics (spawn, env scrub, tree-scoped teardown) live in the `clocky-subprocess` seam; `subagent-acp` spawns through `ctx.subprocess`, while this backend spawns through the SDK client (the subprocess README's documented exception for SDK-managed transports) and applies the seam's `scrubbedParentEnv()` itself.

`clocky-sdk-jsonrpc-server` serves the Team product methods; `clocky-jsonrpc-agent-pkg` (the Python runtime closure) carries the `clocky-sdk-protocol` dependency.

## Testing

Four tiers, per [testing policy](../../../../docs/testing.md):

- **Keyless unit** — `sdk-client` drives a scripted fake runtime (`tests/fake-runtime.ts`, env-scripted, protocol-only — the Python `test_client.py` pattern) over real stdio; `subagent-clocky-sdk` drives the same fake through the real provider. 100% per-file coverage on all three packages.
- **Keyless Loader composition** — `subagent-clocky-sdk/tests/loader-composition.e2e.ts` boots a test-only cordis.yml (`examples/jsonrpc-agent/tests/fixtures/subagent/subagent-clocky-sdk/`) where the child is a real second harness runtime with its own Team composition; it asserts that the parent tool result and the child's coordinator transcript both carry the parent session's cwd. The child launch resolves through `resolveExampleLaunch`, so src/lib modes both hold.
- **Keyless snapshot** — `examples/jsonrpc-agent/tests/sdk.snapshot.ts` exercises the real `clocky-jsonrpc-agent` runtime through the real `clocky-sdk-client`; `examples/jsonrpc-agent/tests/subagent-clocky-sdk-team.snapshot.ts` starts a real child Team through the SDK subagent provider and pins the parent-visible `SubagentRun` result plus its durable `team_final` Envelope. These snapshots cover the Team product boundary without an API key.
- **With-key e2e** — the snapshot suite's `CLOCKY_SNAPSHOT=record` mode is the live-API path (it produced the committed fixtures); the composition e2e needs no key by design.

## Alternatives considered

**Import wire types from `clocky-sdk-jsonrpc-server` instead of extracting a protocol package.** Makes every SDK consumer (including `subagent-clocky-sdk`, which must not serve JSON-RPC) depend on the server plugin and its serving-runtime peer set, and leaves the notification payloads anonymous. The capability-seam rule (Service Definition / Service Provider / Consumer as separate packages) already names this shape; the transport is genuinely two-sided.

**Have `subagent-clocky-sdk` speak raw JSON-RPC without the client SDK.** Duplicates the request/notification pairing, subscription fan-out, timeout, and teardown logic the SDK exists to own; the user's ask was explicitly a backend that *uses* the SDK, and the layering earns its keep by making the backend ~200 lines of policy over a reusable client.

**Fold the SDK backend into `subagent-acp` with a transport switch.** The two backends share the subprocess lifecycle but nothing about the wire (ACP SDK connection vs harness JSON-RPC), the child contract (any ACP agent vs a harness runtime), or the result extraction (`agent_message_chunk` accumulation vs session-event reading). A config discriminant would bury two protocols in one package; the genuinely shared provider-side parts moved into the subagent seam's `out-of-process.ts`, and the process mechanics live in the `clocky-subprocess` seam.

**Give the TS SDK bundled-runtime resolution parity with Python.** Python's carrier resolution exists to ship wheels to users without Node. A TypeScript consumer definitionally has Node and (in-repo) the workspace; inventing a distribution story with no consumer violates the require-current-need rule. Deferred until a real npm-distribution consumer appears.

**Export source modules, normalization helpers, and subscription producer operations.** These are implementation details with no caller need; exposing them would make callers learn how the client validates and distributes wire input. The package roots instead enumerate the supported client and protocol interfaces, and the client re-exports the one protocol error callers must distinguish.

**Reuse `clocky-acp-snapshot`'s `runScenario` for the SDK snapshots.** That harness speaks ACP (`ClientSideConnection`, `InputStep` scripts). The SDK suite's whole point is to drive the *SDK client* as the entry surface; it reuses the normalize/refresh library layer (`normalizeSessionLog`, `refreshFixtureReplacements`, …) and leaves the ACP driver alone.

## Consequences

**Bought**: the SDK runtime protocol has named, compiler-checked types shared by its server and both client SDKs; TypeScript consumers get the same subprocess-driving capability Python has, with typed errors, explicit Team finals, and package roots that expose only caller-owned operations; the subagent seam gains a harness-native out-of-process backend whose children are full peers (own config, persistence, tools) — the recursive-composition story the seam note anticipated; the Team final path has runnable snapshot coverage through the SDK provider itself.

**Paid**: a third package in the `sdk/` group and a fourth subagent backend to keep current; the SDK backend boots a complete plugin tree per child (heavier per-run than an ACP child; pooling remains future work, same as ACP); Team cancellation is cooperative and process close remains the final teardown authority; replay fixtures re-record on model-behavior drift like every other recorded corpus.

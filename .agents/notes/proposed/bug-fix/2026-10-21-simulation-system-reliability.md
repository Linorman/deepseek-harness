**F2 / P1: Paged journal reads are not incremental detail projections.** `inspectPaged()` folds pages within one consistent SQLite prefix and avoids a second complete entries/index array, but each detail read still replays from creation to tail; returned state and business payloads can also be large. JSON still decodes the full document, and raw SQLite archives collect all bounded records before base64/JSON encoding. Small control DTOs avoid deep copies of all bodies but still traverse decisions, operations, entities and other relationships; they are not constant-time reads. Complete the capacity matrix first. Introduce a source-hash/version-validated incremental derived projection and writer-owned counters only where measurement justifies them. Measure page bytes, source bytes, serialization peaks and total state separately; response pagination does not establish bounded disk IO. This belongs to W6 items one through five and eight.

## Proposal

### Ownership and invariants

Native owns durable control facts and admission; Product owns authentication, idempotent commands, observations and scheduling lifecycle; World providers interpret case clocks, external execution and domain outcomes; Team/Session own real input-consumption and usage evidence. Extend existing plugin capabilities rather than hard-coding Harbor policy into the generic agent loop.

Separate stop targets from the scenario's intrinsic horizon. Paused does not mean business success; Native `running` does not establish an active driver; checkpoint admission does not establish a complete backup; a stored Native result does not establish judge acceptance. UI connections, prompts, caches and old batch results cannot override control facts. Any new model-visible stopping information, preflight hints or summaries must derive from replayable Session events.

### D1: Durable stop targets and two-clock boundaries (W1)

Add an independent run-control command/event serialized by Native. Product uses the authenticated principal; callers retain an idempotent commandId without selecting actor authority. Target updates, pause and execution admission share an ordered control revision. Proposed fields below enter strict schemas during implementation:

| Field | Meaning and rules |
|---|---|
| `targetId` / `revision` | Current target identity and monotonic control version; the same command/input returns its original result, while changed input rejects. |
| `clock` | `native` or an exactly versioned domain clock such as `harbor-day`; never derived from browser dates or wall-clock time. |
| `boundary` | Canonical time preserving Native SimTime precision or the judge's Harbor day. Cannot precede confirmed current time. |
| `mode` | `at-boundary` closes new business admission on arrival; `drain-admitted` completes only the work admitted at arrival and its necessary protocol settlement. |
| `state` | `armed → draining → paused`, with checkpoint pending/completed/failed tracked separately; save failure must not imply continued running. |
| `cut` | Native revision, domain revision, time and admitted work identities at arrival, freezing the settlement scope. |
| `checkpointPolicy` | Whether and how to save; pause completion and recoverability require distinct evidence. |

Domain providers declare pure interpretation interfaces for clock observations and action time effects. Harbor covers at least `advance`, future work from wakes/message deliveries, and actions that implicitly advance dates. The interpreter answers whether a boundary would be crossed and against which revision; it does not rewrite actions. Native events remain subject to their own boundary; domain time and Native time are not assumed equal. Refuse target installation explicitly when a multi-clock scenario lacks a reliable mapping rather than claiming protection.

Execution order is: persist target → correctable stage preflight → Native submission/admission checks → recheck immediately before external execution → persist judge receipt and reconcile Native → detect arrival → close new business admission, settle, pause and save. Checking only staging or the outer driver loop permits bypasses. Host management, retries, cold recovery and targeted execution also check; reconciliation first reads retained execution receipts so a new target cannot discard effects that already happened.

Target updates and external dispatch share a serialized authorization boundary. An already-dispatched crossing request cannot be promised withdrawn: the update first closes subsequent admission and waits for confirmation, returning pending or outcome-unknown. Confirm target activation only after proving that current position and executable remaining work cannot cross it; reject an already-passed target while retaining pause. Recovery from a crash between external execution and Native recording reconciles first, without redispatching or rewinding the judge.

`at-boundary` does not revoke existing business responsibility: dispatched actions must reconcile, and undispatched work remains paused. `drain-admitted` freezes a set at the cut and permits only that set's adjudication, result recording and necessary notifications. Notifications cannot generate arbitrary new business requests or unbounded discussion. Settlement cannot cross the date and has step, token and real-time budgets; exhaustion pauses and lists remaining responsibilities instead of claiming completion. Orders requiring later dates remain outstanding.

Reaching day 12 does not complete the 365-day case or justify a fabricated `finish`. With target 12, 11→13 returns a correctable boundary refusal rather than silently becoming 12; 11→12 is allowed, after which no crossing work is generated. Ordinary start cannot bypass a reached target: explicitly change/remove it, then separately resume. With no advancing events, the run may remain idle before the boundary rather than inventing model decisions to reach it.

Stop targets enter Native replay and checkpoint references. The existing [manifest](../../../../packages/simulation/simulation/src/checkpoint.ts) retains the full Native prefix and Team/Channel/Session references; it cannot be assumed to include external Harbor files. Complete recovery delivery requires a provider-owned backup manifest binding the judge source manifest, original journal, bridge receipts and a consistent Native/Team/Session cut. Until supported, expose `external-state-required` and claim only pause or partial saving. Save failures retain pause; retry the same save identity without inference.

### D2: Safe failure categories and consistent observations (W2)

Reuse [LlmFailure](../../../../packages/llm/llm/src/types.ts) `code/status/providerRetryAfterMs`. Preserve structured causes at adapter/Team/driver boundaries while attribution remains known; Product exposes only a whitelist. New observations carry `category`, `retryDisposition`, `actionCode`, `failureId`, occurrence time and associated Native revision. Generic exceptions become unknown; matching the text “insufficient balance” alone cannot confer business or retry authority.

| Category | Handling semantics |
|---|---|
| payment-required / insufficient-balance | HTTP 402 establishes a payment block; only a reliable provider code refines this to insufficient balance. Account action and explicit recovery are required. |
| rate-limited / network / provider-unavailable | Describe retry eligibility and bounded retry-after; preserve explicit owner recovery instead of adding an automatic retry loop. |
| context-limit / request-budget / token-overrun | Separate model window, per-request admission and interval usage; preserve existing recovery/allowance acknowledgement paths. |
| protocol-unavailable / history-limit / storage / integrity / unknown | Direct handling toward installed versions, read allowances, saving or integrity; repeated inference is not a repair. |

Bind safe failure records to driver instance/batch identity. A new successful batch clears only its own prior failure while retaining audit facts. Cold recovery of historical running without a live owner returns owner-unavailable/recovery-required rather than stale failed/advancing. Keep phase, driver, inFlight, stop and checkpoint independent, with source revision/observedAt for each; observations from different cuts must not masquerade as an atomic snapshot.

Directory, details and export reuse one safe mapping. Raw message, paths, HTTP bodies, credentials and provider requestId do not enter ordinary DTOs; authorized diagnostics use a controlled correlation ID. Current [observe/runStatuses](../../../../packages/simulation/simulation-product/src/index.ts) collapses several read failures into unavailable. Preserve safe missing, unsupported-version, history-limit and corrupt-history distinctions while retaining whole-batch rejection on revocation and isolating one broken run from other authorized runs.

### D3: Domain summaries and layered success (W3)

Add registered pure domain projectors selected by exact domain/operation/version. They read only validated Native results or recorded original-judge evidence, invoke no model, acquire no execution owner and run no world-mutating CLI. Host supplies disclosure permission and rechecks it after asynchronous reads; projectors cannot enlarge grants. Missing projectors return unsupported rather than interpreting absence as zero responsibility.

Expose three layers: `submission` (submitted/admitted/rejected), `execution` (pending/judge-accepted/judge-rejected/unknown), and `businessOutcome` (achieved/not-achieved/unknown/not-applicable). Harbor `receipt.ok` proves only command acceptance; delivery or goal achievement requires corresponding judge facts. Conclusions include request/result/source revision, evidence references and coverage; lists, details and export share the same converter.

Each summary field reports allowed/withheld/not-applicable/unknown. Public labels, private bodies, business keys and role views have separate grants; a public summary does not authorize full payload disclosure. Harbor companies, alliances and employment relationships come from domain evidence. Count original-role Sessions, business entities and founder-represented entities separately rather than treating technical bindings as organizational scale. This plan defines backend DTOs only; UI implementation is separate.

### D4: Correctable protocol preflight (W4)

Extend staging with side-effect-free preflight against current prepared context and the exact domain schema version, returning bounded `path/code/expected/allowedValues`. It must not allocate requests, run the judge, rewrite payloads or disclose another request's context. Failure preserves prior valid staged content and explicitly reports that the replacement was not accepted. Corrected submission still undergoes Native authority, timing and full validation.

Minimal examples belong to the versioned domain description that owns the schema and cover `after`, `action.kind`, `resolution.kind` and Harbor forwarding. Generic tools must not invent unvalidated business actions. Include examples/hints in frozen replayable context. Retain separate regressions for final prose, repeated staging, stale requestId, unknown fields, cross-request authority, Unicode and long bodies. Never silently strip fields from model input; explicit public-field projection of judge output has a separate contract and must not become full disclosure.

### D5: Compaction suppression and usage attribution (W5)

First classify existing [token reservations](../../../../packages/simulation/simulation/src/tokens.ts) using `decisionId/compactionId/sessionSequence`, [compactionStream](../../../../packages/simulation/simulation-team/src/compaction.ts) and Session request facts: business choice, director adjudication, result notification/settlement, ordinary communication, compaction, and unattributed. Categories must be exclusive and reconcile to totals; uncertainty enters unknown. Messages can share a request with decisions, so do not mechanically split or double-charge them. Expose input/output/cache read/cache write and reserved/unknown/settled separately; tokens are not money and requests are not business decisions.

Separate fixed system/tool context, compactable history, retained tail and output reservation first. If fixed context already fills the window, report the pressure cause rather than repeatedly summarizing a tiny history. Measure gains with the same token meter while retaining source evidence, tool pairing, surface generation, cancellation and pre-commit validation.

Introduce a typed no-gain result. Its fingerprint covers selected surface node identities/content, replacement generation, input that actually affects summarization, target model, resolved policy and meter/algorithm version. Unrelated log sequences, wall-clock values and new failure records must not change it. Identical input gets no further paid ordinary-pressure attempt; small changes coalesce through a minimum new compactable-token threshold and bounded cooldown. Real policy/model changes trigger reevaluation. Thresholds are validated Cordis Config; defaults require fixed-sample comparison rather than invented savings claims.

Retain only bounded recent suppression state per Session/policy and persist the minimum replayable facts needed after restart, without duplicating private bodies. Restart must not pay again for the same unproductive summary. Manual compaction may explicitly override suppression once, without background retry. Context overflow may select a more aggressive legal range, but must not repeat the same unproductive input indefinitely. Retry the original request only after durable surface reduction and within `maxOverflowRetries`. New event types update Session decoding and both SDKs.

### D6: Bounded reads and creation checks (W6)

[inspectExisting](../../../../packages/simulation/simulation-local/src/index.ts) reads the complete journal first, and [snapshot](../../../../packages/simulation/simulation-local/src/run.ts) produces detached copies; smaller pages or larger caches do not prove bounded disk IO and memory. ## Alternatives considered

**Prompts or browser-timed pause alone.** They cannot enforce boundaries across disconnection, date jumps, cold recovery and background dispatch. Keep the model-visible goal but enforce execution in Native/provider admission.

**Only pass `until` to the existing driver.** It is a batch-level Native time limit, not a judge-date or durable-target constraint. It can support the implementation, but cannot constitute the whole design.

**Only increase allowances, read limits and retries.** This can unblock a run without eliminating complete-history reads, unproductive paid requests or uncertain stopping. Configuration remains useful but does not replace structural fixes.

**Automatically repair model parameters, synthesize empty decisions or equate judge acceptance with business success.** This alters model choices or fabricates completion evidence. Use exact preflight, correctable refusals and layered outcomes instead.

**Replace the entire memory/compaction architecture immediately.** The [recallable compaction proposal](../feature/2026-07-06-recallable-compaction.md) has broader memory goals and is not a prerequisite for suppressing repeated unproductive requests. This round first delivers bounded suppression and reconciled measurements.

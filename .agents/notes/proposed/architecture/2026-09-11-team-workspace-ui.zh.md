# Agent Note: Team 工作台概览与按需 Session 检查

Status: proposed

[English](2026-09-11-team-workspace-ui.md) | 中文

## Problem

选择 Team 会打开协调者 Session，而一个 360×520 的详情浮窗承载了成员、任务、预算、工作流、频道、产物、人工操作和审计记录。大集合把可处理的工作推到首屏以下；频道按钮在窄列中换行，中间对话却可能保持空白。用户要求以仪表盘为中心的 Team 工作台、简短任务摘要，以及按需打开的页内 Session 子页面。

[设计方案和本次截图证据](../../../../design/team-workspace-2026-09-11/design-proposal.md) 记录当前浏览器流程、拟议布局、信息上限、数据定义、动效、组件归属与实施顺序。本任务交付设计提案，不是产品实现。

## Proposal

选择 Team 后默认显示团队概览。任务、频道、成员和产物拥有独立视图；工作流和审计通过次级导航访问。优先展示等待人工决策的事项和当前执行。任务检查栏显示单个任务的目标、负责人、状态、最近结果及下一步；完整历史和编辑位于更深层视图。

选中的 Session 在一个宽幅页内子页面中打开，并提供明确返回路径。保留来源 Team、模块、筛选、选择、滚动位置和 Session 草稿。关闭检查视图不会取消工作。协调者输入继续经过 Hub；打开工作成员的执行记录不会授予直接 prompt 或模型修改权限。

复用现有 `ui-layout`、`ui-team`、`ui-conversation`、`runtime`、`ui-primitives`、`ui-theme` 和 locale 的职责。不为仪表盘、任务检查栏或 Session 子页面创建 UI 插件。拟议组件保持包内私有，插件通过 slot 和服务组合。

### 组合与数据

在现有布局注册中增加 root scope 的 Team 工作区 slot。保留 `conversation` 注册及其子 slot 声明，供 Session 渲染和首次输入使用；不能用 Team 组件替换该 single slot。分离 Team 选择与 Session 打开状态，只渲染一个可见会话实例。把会话移动到模态容器前，验证 React 挂载、IME、草稿、附件、工具详情和观察者的生命周期。

概览事实从选中 Team 的完整快照派生；长列表通过有界集合读取。任务完成数量表达任务完成，不表达目标进度。用量覆盖 Team 子树，必须区分输入、输出、缓存和提供方成本单位。现有 `team.metrics` 请求属于 Host 范围，不能提供当前 Team 的指标。不能从已加载页推断全量总数，也不能编造未读数量、历史趋势、货币或 ETA。

[当前设计上下文](../../../../DESIGN.md) 明确以对话为中心，并禁止 Team 仪表盘。本次用户需求选择相反的产品方向。实施时必须同步更新设计上下文和运行时 token 消费方；本提案保持二者不变。

### 与已有决策的关系

[紧凑详情决策](../../implemented/feature/2026-09-07-team-detail-compact-delete.zh.md) 继续拥有任务修改授权、停止/删除语义及负责人归属规则。本提案实施后可替换其中的浮窗呈现选择。[Team 收尾决策](../../implemented/architecture/2026-08-31-team-closure-authority-and-detail-inspection.zh.md) 继续拥有生命周期、来源追溯和权威职责。[P1 产品提案](2026-09-04-native-multi-agent-p1-product-convergence.zh.md) 保留其更广的协议和产品范围。

本次限定范围的替代关系检查没有发现被这份未实施设计完全取代的已实现决策。保留这些记录为活跃状态；归档、合并或生命周期变更不属于本任务。

## Alternatives considered

**给浮窗增加更多折叠。** 这会隐藏内容，却没有为任务、频道和成员提供适当工作空间，也没有纠正默认导航。

**保留大 Session 并配一个小仪表盘。** 这保留了用户明确要求改变的中心区域优先级，并把运行概览挤在剩余窄空间里。

**默认使用可拖拽任务看板。** 任务阶段受调度器和审核控制。自由拖拽会暗示不受支持的修改能力，卡片也降低并排比较效率。

**新建仪表盘和检查栏插件。** 这些呈现已有对应的 UI 归属。增加插件会扩大组合工作，却没有独立演进的能力作为依据。

## Acceptance criteria

- 在 1440×900 下，无需打开 Session 或滚动长成员列表，即可看到 Team 目标、生命周期、任务分布和人工待处理入口。
- 一次点击打开任务摘要或成员 Session。关闭 Session 恢复来源选择、筛选、滚动和焦点，不丢草稿，也不停止执行。
- 频道阅读、邀请同意、输入、配置和诊断具有独立展示区域，保留协议限制和经过认证的修改操作。
- 完整快照指标与已加载页数量、Host 级遥测保持区分；不可用数据不能显示成编造的零或趋势。
- 现有 UI 包保持职责；所有注册和响应式数据路径遵循客户端 slot/store 规则，不跨插件导入组件。
- 实施通过有针对性的 keyless 行为快照及浏览器检查，覆盖错误、分页、版本冲突、迟到响应、子 Team 导航、工作成员只读语义和 Session 返回。验证两种语言/主题、键盘、390px 布局、200% 缩放及减少动态效果；实施 PR 录制真实流程 GIF。

## Risks

偏好持续对话的用户会多一次打开动作，因此保留稳定的协调会话入口和展开阅读模式。仪表盘内容可能继续增长，成为另一个臃肿详情页，因此方案中的信息上限属于验收要求。若不先解决状态和 slot 归属，移动 Session 渲染可能重置 React 局部状态或使工具详情位置错误。模态焦点和嵌套确认需要共享基础组件保持一致行为。完整 Team 快照当前能支持准确计数，但不能替代超大部署未来需要的有界聚合契约。

本次调查重新运行了现有 Team 集合和频道的两个浏览器测试文件，五个测试通过。运行使用真实隔离 Host 和回放模型输出，验证的是现有产品，不是拟议 UI 的实现。严格 premium 静态检查报告零问题；运行时可访问性和性能仍需实施验证。

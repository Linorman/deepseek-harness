# Agent Note: Durable simulation coordination

Status: proposed

English | [中文](2026-09-17-durable-simulation-coordination.zh.md)

## Problem

Long-running social, organizational, and resource simulations need durable identities, responsibilities, beliefs, and simulation time beyond one Agent activation. Chat history cannot establish whether a request was accepted, whether a promise was fulfilled, or whether an action changed the world. Thousands of entities must not require thousands of resident model loops.

Clocky's Team already owns reliable collaboration. A simulation must preserve its authority and Session reconstruction rules while adding business state, delayed perception, deterministic commit ordering, and restart recovery. It must not turn an execution parent into a manager, a delivery receipt into acceptance, or a model's assertion into world truth.

## Proposal

Add an opt-in Simulation composition above Team. Keep Entity, Interaction, World, Knowledge, and scheduling as distinct logical owners, with one Simulation journal and one serialized writer per run in the first provider. This gives Decision acceptance and its outbox a real atomic write without requiring cross-stream transactions. Split storage or packages only when independent evolution requires it.

The local JSON/SQLite implementation includes the keyless two-entity request/resource and five-role procurement scenarios, bounded cognition, knowledge isolation and checkpoint recovery. Measured capacity remains qualified by the recorded hardware and workload limits. Multi-Hub federation, world partitioning, physical deletion of history, production branch execution, and real external effects remain proposed or deferred.

The [development plan](../../../plans/2026-09-18-durable-simulation-coordination/development-plan.md) owns work-package status and verification evidence. Its candidate manifest fixes the delivered local scope. Benchmark source hashes exclude temporary Loader configurations and data trees. Journal folding owns persisted checkpoint and decision validation; live methods use those validated records without repeating unreachable checks. This broader design remains proposed for the capabilities outside that scope; local completion does not certify them.

The local run foundation uses the existing JSON/SQLite Storage backends and a separate lifetime SQLite exclusive transaction per run for same-host coordinator ownership. A CAS-only writer or expiring lease would permit a second coordinator between appends or during a pause; the OS lock instead releases on process exit. No Team effects or model decisions are authorized by the foundation's administrative phase.

Cognition coordination uses the canonical Team's immutable `activationLifecycleOwner` rule. The controller invokes the registered owner at startup, durable binding, retirement and recovery; domain writer records share the Team startup reservation id. Pinning the actual in-process provider closes the implementation-replacement race. A run cannot release coordinator ownership while a writer lacks confirmed retirement.

Decision slots fix the entity, writer epoch and input revision before inference. One acceptance batch retains every operation intent, while local settlement records atomically derive conserved resources, grants and commitment evidence. Results survive writer retirement and restart. A live admission callback runs inside the same run queue as revocation and checks current Team/Agent authority before new acceptance.

Scheduled keys and counters are journal facts, not wall-clock timers. Wake/deadline creation shares the originating business batch; consumption atomically transfers responsibility into a durable wake or deadline outcome. A microstep stall retains pending work until an explicit cancellation and resume, rather than silently moving the clock past it.

Outbox attempts retain the exact accepted channel and payload fingerprint. Transport IO does not hold the run serializer; terminal receipts or uncertain attempts return through that serializer. A retry budget limits automatic technical retries, while an explicit recovery record permits further idempotent reconciliation. Sender retirement cannot remove the accepted operation, and permission loss only permits reconciliation of an already committed target result.

## Identity, organization, and cognition

Every persistent simulation object is scoped by `runId`; branches receive a distinct run namespace. New cross-package identifiers use `Branded<B>` from `@clocky/clocky-brand`, with validation at persisted, tool, and wire inputs. EntityId, ParticipantId, SessionId, ActivationId, DecisionId, OperationId, and EnvelopeId are never interchangeable.

Entity owns its kind, lifecycle, profile revision, and JSON metadata. Person and organization are simulation kinds, not Team participant kinds: a simulated person remains an Agent-backed entity, while a Team human represents a real user. Entities without cognition need no Participant or Session.

An organization edge names `subjectId`, `relation`, `objectId`, optional organization scope, validity interval, and revision. `reports-to` targets a person, `member-of` targets an organization, and `part-of` connects organizations; schema validation checks endpoint kinds and configured cycle rules. Scoped relations require configured `scopeKinds`; temporal cycles and explicit organization queries stay within that scope. Employment and membership have one owner, Entity; World may refer to those records but cannot independently mutate a second employment table.

MVP binds each cognitive Entity to one canonical `{teamId, participantId, sessionId}`. Organization hierarchy lives outside that Team. The general mapping may later support multiple membership-specific Participant/Session pairs, but cannot share a Session header across Teams. Multi-membership cognition requires an explicit primary owner and mediation of other Sessions; it is not an implied feature of the mapping.

Simulation writer state records `{runId, entityId, writerEpoch, binding, cognitionRevision}`. Reserve an epoch durably before activation; attach the exact controller binding before admitting a decision. Every decision validates that epoch and revision in the same Simulation append that accepts it. Recovery must prove old activation termination through the controller before granting a successor, including across future membership bindings. A timeout, idle status, or missing in-memory handle alone cannot release ownership.

All Simulation activation retirement/replacement paths, including recovery and administrative cancellation, must serialize with decision admission through the run coordinator. Revoke the writer epoch durably before asking the controller to fence or dispose; only then may a successor be admitted. A snapshot check followed by an uncoordinated append is insufficient. Generic controller/recovery entry paths for simulation-owned bindings need this integration before being enabled. A crash between revocation and controller cleanup leaves the entity blocked for recovery, never writable by both epochs.

Subagents may compute auxiliary results, but cannot directly write the owner's cognition or impersonate its authority. Reports cross the same logged, authorized input path as other observations. Single cognition writer governs model decisions, not reception: new messages can be recorded while a decision runs, but become eligible only for a later fixed input snapshot.

## Interaction, task execution, and commitment

Interaction is a business object carried by Team, not a replacement message bus. The first protocol supports single-assignee request, accept, reject, defer, and result. Inform, proposal/counteroffer, escalation, and multi-recipient negotiation are later protocols with their own state machines. Natural language is evidence; only a validated structured operation changes business state.

A request stores requester, assignee, objective, revision, creation time, optional response/completion deadlines, and scoped transport references. A reference identifies run, Team, channel, Envelope, recipient, and sequence rather than an unqualified EnvelopeId. Resolve a role address to an Entity when accepting the request. A later manager change does not silently retarget it; reassignment is a revision-checked event.

Keep three independent projections: per-recipient transport delivery; business response (`pending`, `accepted`, `rejected`, `deferred`); and execution. Transport state is read from Team receipts/expiry, not maintained as a second mutable Interaction queue. Execution is read from linked TeamTask records when present; local execution without a task is owned by the Interaction protocol. Do not store one combined state enum that can contradict these projections.

Accept/reject/defer require the exact assignee, current revision, and pending or eligible deferred response. Accept creates one Commitment in the same Simulation batch. Defer records a next-response event; response expiry, completion deadline, withdrawal, and cancellation each have explicit actor and revision rules. Concurrent accept and cancel serialize: only one expected revision wins. Cancellation after a world effect requires settlement or compensation, not erasure of that effect.

Commitment records debtor, creditor, objective, deadline, revision, fulfillment policy, and evidence. TeamTask completion is execution evidence, not automatic fulfillment. Only a declared `task-completed` policy may derive fulfillment directly from a terminal task revision; delivery, inventory transfer, or creditor acceptance require their own authoritative evidence. A deadline may record breach while later fulfillment remains possible. Task retry/review, commitment breach, cancellation, and accepted completion remain distinguishable.

Status reports carry changes, blocked dependencies, risks, required decisions, next update time, and evidence. Delegated objectives carry expected outcome, allowed capabilities, budget, deadline, and escalation policy. Upward reporting does not forward all private conversation history. Simulation authority never grants Harness administration, filesystem, network, or real payment permissions.

## Atomic decisions, world effects, and outbox

Use a versioned JSON journal entry or atomic batch for `DecisionAccepted` plus all initial operation intents. The run writer checks expected journal tail, entity state, writer epoch, input snapshot, and decision slot before append. An append conflict requires rereading; it must not regenerate operation identities. A crash cannot leave an accepted decision without its pending operations.

World resource facts, Entity relations, Interaction transitions, Knowledge records, scheduler events, and decision/outbox projections share this first-provider journal. Logical ownership remains distinct: only World validators authorize resource changes, and only Entity validators authorize relation changes. A local world transaction records preconditions, all resource changes, operation result, and resulting events atomically. Competing purchases cannot independently debit money and reserve the last unit.

Operations have stable keys `(runId, decisionId, operationIndex)` and canonical payload fingerprints. A retry with the same key and payload returns the recorded result before evaluating stale business preconditions; a changed payload rejects. Authentication still protects reading that result. A genuinely new action carries a new key and validates its expected resource revisions. Multi-stage plans persist dependency order: a result claiming success cannot publish before the corresponding world operation succeeds.

Decision acceptance means responsibility to process its operations, not that every effect succeeded. Operation projections distinguish `pending`, `applied`, `rejected`, `blocked-authority`, and `outcome-unknown`; attempts and durable destination receipts are retained. A failed prerequisite blocks dependents. Compensation is an explicit new operation and cannot roll back an already delivered message or arbitrary external effect.

Team remains a separate authority. Its posts run from the outbox after local acceptance, use stable destination idempotency keys, and retain the destination's durable Envelope reference. A crash after destination append but before local acknowledgement retries or reconciles the same operation. At-least-once delivery plus atomic destination deduplication prevents duplicate business effects; expected revision alone does not provide that guarantee.

The existing `TeamSystemEnvelopePostScope` has no generic simulation case. Implementation must add a narrow Simulation post scope or an equivalently reviewed bridge API, with exact accepted decision, run, sender binding attribution, resolved audience, channel, payload fingerprint, and operation key. The Hub revalidates it under its Team/channel locks. A registered source name by itself is insufficient. Persisted decision evidence is not a runtime proof; recovery obtains a fresh opaque proof from the trusted executor. A stopped originating activation may have its already accepted operation completed, but may not authorize a new decision. Revoked membership, closed channels, or denied current policy produce a durable blocked/rejected result, never impersonation of a new sender. Task outbox admission also requires an active Team without a cancellation or closure intent: it rejects new tasks while preserving idempotent reconciliation of committed tasks. Journal replay validates the Team state at task creation.

General shell, network, and live world-mutation tools are absent from the simulation decision preset. Read-only tools query the pinned authorized snapshot; proposal tools stage operations and expose their pending status in logged tool results. One explicit submit finalizes the slot. World effects execute only at the ordered commit point. Truly external tools require reconciliation or idempotency support; an applied request with a lost response is `outcome-unknown` and is not blindly retried. They are outside MVP.

## Time, visibility, and decision windows

Persist SimTime and large slot counters as canonical nonnegative decimal strings. Validate their syntax and configured range; compare numerically, using transient bigint arithmetic if needed, never lexical string order. Raw bigint is not JSON. Run configuration freezes tick unit, origin, clock/ruleset versions, and scheduling policy. Team leases, delivery TTLs, model timeouts, and process supervision retain wall-clock semantics; simulation deadlines use scheduled events.

Event order is `(time, microstep, phase, slot)`. The policy defines phase order and allocates stable slots before inference. New same-time consequences enter a later microstep and cannot jump ahead of already committed events. Persist event acceptance, cancellation, consumption, slot allocation, and clock advancement. Reject schedules into the committed past. Exceeding configured microstep limits stalls the run; advancing time is allowed only through an explicit logged policy decision, not an invisible fallback.

A DecisionWindow freezes world/entity/knowledge/interaction revisions, visibility policy, authorized inputs, and one slot per cognitive entity. Concurrent model requests use that snapshot. Results commit in slot order; a missing result cannot be bypassed because another model is faster. Each slot records completion, failure, cancellation, or configured timeout. Timeout outcomes are part of the trace and can vary with real latency; the deterministic guarantee applies to the same persisted trace, not merely the same seed or prompts.

At commit, revalidate resource read sets and live authority. Unrelated world changes need not invalidate a decision; conflicting preconditions produce a logged conflict and a new decision at a later microstep. Bound these retries. Knowledge selection also uses the pinned observation cursor, so a world value becoming committed does not make it visible to every Entity.

Communication latency is simulation policy. Before `deliverAt`, an outbox communication intent may be durable but no recipient Session, channel view, summary, search tool, or context may expose its content. MVP delays Team posting until that time and processes the post result before opening the recipient window. After posting, the exact recipient delivery still needs claim, Session persistence, and receipt. Transport TTL expiry is a delivery failure; it does not expire the business commitment automatically.

Live external inputs and human interventions receive durable ingress order and an assigned simulation event key; they do not mutate an already frozen window. The deterministic replay guarantee includes those recorded choices. Paused runs continue required runtime supervision, but admit no new simulation decisions until resumed.

## Knowledge and model context

World facts, reported claims, inferences, and beliefs remain distinct. Knowledge stores owner, kind, statement, revision, provenance, `observedAt`, `availableAt`, optional validity interval, and visibility basis. Future plans may describe a later effective date while being knowable now; the anti-leak rule checks availability/observation at the admitted snapshot, not every timestamp inside the statement. A forecast is not a future observed fact.

Provenance is mandatory: observations name world events and visibility decisions; reports name recipient-specific transport evidence; inference names premises and its producing decision; initial persona/beliefs name versioned configuration. Belief confidence is policy data, not proof of truth. Commitments and task state are authoritative references in context, not duplicated mutable knowledge facts.

Revoking access stops future retrieval. It cannot erase information already logged in a Session or a derived summary. A scenario that requires forgetting must explicitly replace the model context/Session generation and address all derived memory; source logs remain auditable under their own access policy. Role changes alone do not promise machine-level forgetting.

Context prioritizes identity, effective permissions, current input, active objective, open commitments/deadlines, direct evidence, authorized observations, relevant knowledge, and optional history. Required information exceeding the configured budget produces `SIM_CONTEXT_REQUIRED_ITEM_OVERFLOW` and stalls admission. Indexes and vector retrieval are rebuildable selectors; final content is materialized and logged before inference. Simulation presets restrict filesystem, Session search, Team history, and tool access so other paths cannot reveal the full world or another role's private context.

Add required Session event `simulation/context-view` with run/entity/window/slot identity, writer epoch, scoped durable input references, projection revisions, policy/persona/model configuration versions, and exact ordered content. The Session surface projector derives the model input only from that stored content. Use a deterministic input id; append and flush behind a pre-step barrier, then acknowledge delivery. Recovery distinguishes logged view, queued input, and durable consumption; a view alone does not prove the model consumed it. It neither duplicates consumed input nor drops a flushed but unconsumed input.

Context refresh specifies which prior simulation context view it replaces, while retaining the event log and unrelated conversation history. Appending a full current view on every decision forever is not bounded memory. Compaction protects required current facts and pending obligations; it does not replace the World journal. A semantic or decision summary remains derived and retains per-viewer provenance; current channel-wide summaries cannot summarize a private subset.

The new Session event must update projection, validation, persistence readers, and relevant SDK/ACP transports together, including both SDK snapshot owners. It is required-on-read, not `ignorable`. Follow the [Session format mechanism](../../implemented/architecture/2026-08-10-session-log-version-mechanism.md): `SESSION_FORMAT_VERSION` stays zero unless the structural format changes; a new event type alone does not bump it.

## Delivery ownership and residency

The ordinary Agent Client maps `context` to non-waking inject, `turn` to followup, and `steer` to steer. Non-waking injection is already information exposure and can be consumed by an unrelated wake. A Simulation run therefore needs exclusive delivery ownership for its bindings and a scheduler-controlled path; mounting the ordinary client alongside another competing consumer is forbidden.

Implement the smallest explicit integration: a simulation delivery policy/consumer reuses exact claim, invitation validation, frozen Hub-rendered view where required, deduplication, persistence barrier, receipt, and reconnect semantics. Scheduler admission controls when input can reach a step; the consumer cannot invent another participant or regenerate a channel view. Direct v4 transports text/image messages, not arbitrary structured JSON: persist business operations in the Simulation journal and render referenced communication for Team. A custom structured channel requires its own exact adapter and consumer protocol.

Opening a new channel needs endpoint consent. For a dormant recipient, temporarily establish its exact activation endpoint to validate the invitation without requesting a model turn, or retain the operation pending until that can occur. Never synthesize invitation consent from Entity membership. Already admitted channels may hold pending delivery for a nonresident recipient. Cross-organization gateways and autonomous system actors need their own authority design before implementation.

A general delivery-handler registry is deferred until a second consumer actually needs independently replaceable handlers. If introduced, it retains common claim/persistence/receipt ownership, exact version/schema validation, effect-scoped registration, implementation leases, and bounded teardown; handlers cannot override authority or acknowledge before durability. Merely registering an adapter cannot enable model execution.

Sleep requires a finished owned turn, flushed Session inputs/results, durable responsibilities and operations, and controller-confirmed quiescence before writer release. Close delivery admission and drain accepted work before disposing. `whenIdle()` alone is insufficient. A blocked or unknown operation remains owned by the durable run executor and may stall its causal dependents; it need not retain an idle Agent process forever. Task-bound activations additionally settle or preserve workspace and task ownership through their existing owners.

Capacity separately bounds entity count, resident activations, concurrent model requests, pending interactions/events, messages and tokens per simulation interval, and retries. All deployment-varying limits are validated plugin Config fields. Combine Simulation limits with Team `maxLiveActivations`; reserve startup capacity before placement and release it only after confirmed cleanup. Deterministic actors use the same authorization, event, and commit protocol without a model call. Fair dispatch uses configured priority/deadline/aging rules and persists slot assignment; dispatch fairness cannot reorder accepted commits. TeamDagScheduler continues to own task assignment and wall-clock leases.

## Checkpoint, recovery, replay, and retention

MVP recovery replays the Simulation journal from its valid checkpoint, then reconciles pending operations against Team and Session logs. A full cross-owner checkpoint is an optimization and portable recovery reference, not the first source of crash safety. Sharing one storage backend or collecting latest revisions does not establish a consistent cut.

A full manifest names run identity, exact stream ids and durable cursors for Simulation, Team journals, channel WALs, and Sessions; entity/knowledge/world projections; window/slot state; writer epochs; ingress cursor; pending events and operations; immutable content fingerprints; RNG algorithm/seed/stream position; and code, schema, ruleset, persona, model, and policy versions. Pending lists must agree with the state folded at those cursors, not snapshots taken later.

Its barrier pauses simulation admission, decision commits, and outbox dispatch; drains admitted cross-owner operations to durable results or explicitly recorded uncertainty; closes simulation delivery admission and waits for accepted Session appends/receipts; flushes all included owners; then writes and pins a complete manifest atomically. Use participating-owner barriers or validate unchanged cursors and causal dependencies before publishing. An advanced owner cursor invalidates that attempt. External ingress may continue only into a durable post-cut queue excluded from the manifest. A crash leaves the previous complete manifest usable. Retention holds are acquired before collection and remain until publication or abort.

Replay folds recorded events with pinned implementations without model calls or external effects. Resume validates formats, retained references, configuration compatibility, controller fences, and operation deduplication before admitting new work. It must not resume from an arbitrary mixture of latest owner states and old manifest cursors. A missing referenced prefix or incompatible format fails loudly. The repository is pre-release: backends reject unsupported stored formats; schema versioning does not promise months of backward-compatible execution.

Branching requires a new run namespace and cloned World/Knowledge/Interaction/scheduler projections plus remapped Team/Participant/Session/channel identities. Clear activation ownership and prove new bindings; preserve ancestry references without writing to parent logs. Never replay parent pending external effects in a branch. Copying a Simulation manifest or forking a Session alone is insufficient; branch execution stays deferred until this mapping is implemented and tested.

Logical Topic rollover opens and admits the next channel, atomically changes the Simulation routing pointer, and records previous/next references. Old channels drain pending delivery and closure under Team rules. Changing topic membership does not mutate immutable channel manifests. Do not forward pending messages blindly into a new segment. Segmentation bounds active segments, not total retained history.

Retention protects pending delivery, open interaction/commitment evidence, checkpoints, branch ancestry, Session model views, and summary provenance across all owners. Current Team retention does not know Simulation pins. Before enabling physical deletion, add a cross-owner pin protocol enforced by every compactor, or use dedicated simulation storage with destructive retention disabled. MVP chooses the latter. Session context compaction and projection checkpoints remain allowed when their source preservation rules hold. Archive/index changes must preserve addressable evidence. Operation deduplication keys and payload/result fingerprints remain retained for the entire retry/replay horizon; deleting them while an old intent can return would permit duplicate effects.

## Plugin composition and implementation order

The initial packages should express three roles: `packages/simulation/simulation` (`@clocky/clocky-simulation`) declares services/types; `packages/simulation/simulation-local` implements the run journal, domain validators and scheduler; `packages/simulation/simulation-team` consumes Simulation, Team Link, Activation Controller, and Session. Add `tool-simulation` only with the real decision preset. Logical domains may be modules in one provider; avoid a speculative package for every noun.

Public operations separate observed snapshots, validated requests, resolved specifications, and effectful execution. Tools cannot supply trusted run/entity identity or raw runtime proofs. World reads are authorized/pinned observations; proposals are staged; executor commit is not a model-facing capability. Tools declare their generic render intent and meaningful locations before implementation. Every registry/policy/handler contribution uses `ctx.effect()` or `ctx.on()` with reversible disposal; durable records survive plugin unload.

| Stage | Deliverable | Required evidence before expanding |
|---|---|---|
| 0 | Entity binding, JSON-safe ids/time, one-stream append/fold, writer epochs | Invalid durable input rejects; duplicate/conflicting operations and restart projections agree |
| 1 | Keyless two-entity request/accept, resource operation, Decision/outbox, exclusive Team delivery, logged context | Crash before/after each acceptance, delayed visibility, stale activation, and no duplicate resource effect |
| 2 | Decision windows, deadlines, bounded retries, sleep/wake and quotas | Reversed model response order preserves commits; last-unit contention; dormant invitation and capacity recovery |
| 3 | Five-role procurement: CEO, warehouse, purchasing, finance, supplier | Request, consent, funds reservation, supplier response, recovery and evidence-backed upward report |
| 4 | Task linkage, richer knowledge, summaries, full manifests, scale measurements | Task review versus fulfillment, private knowledge isolation, checkpoint cut and pinned history validation |
| 5 | Optional branch execution, segmentation/retention, federation, partitions | Separate designs and tests for identity remapping, reference pins, or distributed authority |

No standalone type-only foundation with no running consumer is accepted as a finished capability. Recovery, authorization, and minimal logged context are part of stage 1, not postponed until after large-scale activation work.

## Alternatives considered

**Add another message bus or restore implicit-Lead Teams.** Rejected because Team already owns reliable delivery, identities, task attempts, and activation fences. Simulation adds business meaning and time eligibility above those owners.

**Treat Subagent lineage as organization hierarchy.** Rejected because execution ownership and live-parent report availability do not represent durable employment, multiple roles, or offline managers.

**One Session shared across every Entity membership.** Rejected because Session headers and controller epochs bind one Team/Participant pair. MVP uses one canonical execution Team; future memberships require separate Sessions and explicit cognition mediation.

**Independent journals and a later outbox write for every domain.** Rejected for MVP because Storage exposes no multi-stream transaction. One provider stream can atomically record decisions and operation intents while preserving logical domain ownership; separate providers later require explicit sagas.

**Let tools mutate the live world during parallel inference.** Rejected because response timing would determine effects before deterministic commit order. Staged operations keep inference speculative until accepted.

**Use summaries as truth or ship all world state to every role.** Rejected because summaries are lossy, visibility is recipient-specific, and a claim is not an objective fact. Authorized views retain their exact model-visible contents and sources.

**Generalize handlers and split all domain packages immediately.** Deferred because the first integration needs a concrete delivery owner, not a registry that still omits persistence and fencing responsibilities. Package splits follow independent implementations or consumers.

## Acceptance criteria

| Failure or scenario | Observable required result |
|---|---|
| Decision append interrupted | Neither acceptance nor intents exist, or both exist atomically |
| World effect applied; response/local acknowledgement lost | Same operation returns original result; no second debit/reservation |
| Operation key reused with changed payload | Explicit conflict; no mutated existing result |
| Sender disposed after decision acceptance | Narrow executor scope completes the accepted post or records denial; no forged activation |
| Activation replaced while an old result arrives | New decision rejects on writer epoch/binding; accepted older operations retain their recorded ownership |
| Envelope arrives or is searched before deliverAt | No content in recipient views, tools, summaries, or model requests |
| Session flushed; receipt or consumption absent | Retry reconstructs one pending input; already consumed input is not duplicated |
| Recipient dormant or startup cleanup uncertain | No fabricated consent, lost delivery, capacity release, or second writer |
| Acceptance races cancellation or deadline | One revision-checked outcome; any prior effect remains auditable |
| Task completes without required fulfillment evidence | Execution may finish; commitment remains unsettled |
| Models return in opposite order | Slots commit identically for identical proposals and recorded timeout outcomes |
| Two actors purchase the last unit | One successful atomic resource transaction; conflict is logged and bounded |
| Future-dated plan versus secret future fact | Known plan is allowed; unavailable observation is denied |
| Role loses access or required context overflows | Future retrieval denies; logged knowledge is not falsely erased; overflow stalls |
| Checkpoint publication interrupted or owner moves | Prior checkpoint survives; inconsistent candidate is not published |
| Retention attempts to remove referenced evidence | Pin-aware owner denies, or destructive retention is disabled |
| Restart/replay on identical logs and versions | Identical authoritative projections without new model calls/effects during replay |

Use unit/property tests for pure ordering and state transitions, real-provider crash injection for persistence/claims/fences, and a keyless runnable-example snapshot for every new model/protocol-visible path. Session lifecycle/event changes update both SDK snapshot owners under the [testing policy](../../../../docs/testing.md). Runtime invariants compare authoritative event/state relationships such as accepted decisions versus operation intents; branded-type distinctions belong in type/schema tests, not a vacuous runtime service-presence check.

Measure entity count, resident activations, model concurrency, pending queue sizes, journal/Session growth, messages and world events per simulation hour, model tokens/cost, replay time, checkpoint duration, and starvation. Trace each world event through context view, Session turn, decision, operation result, and outbound Envelope. Stalls carry typed reasons for authority, budget, capacity, conflict, unknown outcome, microstep overflow, or context overflow. Benchmark targets include 1,000 entities/20 resident/10 model calls/100k messages and 10,000 entities/100 resident/20 calls/1M world events, then 500 employees across 20 departments and 50 managers for 30 simulated days. These are experiments, not demonstrated capacity.

## Risks

The single journal serializes writes and retains growing history; it is a deliberate MVP limit requiring measured throughput and recovery costs before partitioning. Fixed decision slots can block behind a slow model; explicit timeouts trade progress for trace-dependent outcomes. One canonical Team limits topology while avoiding unsupported Session sharing.

Model outputs are not deterministic, and safe-looking summaries can still contain false claims or instruction injection. Treat reports as data, enforce tools and visibility independently of prompts, and retain exact inputs and provenance. External-effect uncertainty, authority revocation during an outbox retry, and incompatible old formats may require operator action; they must remain visible rather than being silently converted into success.

The local integration enforces Team proof admission, exclusive delivery, Session reconstruction and full-history retention. Publication receipts retain their complete target scope and channel position; checkpoint collection and recovery verify corresponding Envelope and task-creation records. Multi-Team cognition, portable branches and the deferred distributed capabilities remain outside the current plan; scale measurements retain their reported limits.

The Session vocabulary includes required `simulation/context-view` records with ordered sections, scoped evidence, versioned projections and exact single-view replacement. Session replay and both SDK wire validators recognize this event. Context selection is journaled under an explicit byte budget; required overflow stalls the run. The pre-step owner flushes the selected Session view and rechecks live authority before inference. The model-stream owner checkpoints consumed input and the request header before dispatch, and rejects conversation/view mismatches. Decision input uses a fixed identity and payload. Its queue insertion is flushed before the Agent wakes it without another splice; retries distinguish queued, in-flight and consumed input. Writer replacement retires the interrupted slot, preserves its wake responsibility and can drive a fresh slot in the same Session.

The execution Team is bound by immutable `simulationRunId` and `activationLifecycleOwner` rules. Accepted due communication uses a journal-derived `simulation-operation` proof, with exact direct-v4 content and target idempotency. Activation proofs cannot bypass this ordinary-post path. Target response loss is reconciled to the original Envelope; resident recipient delivery retains the Session input, wake and target receipt.

The Hub requires a dedicated delivery-owner proof in addition to activation authority for Simulation claims and receipts, including after awaited policy. Generic Agent Client discovery skips these Teams. The resident-recipient consumer flushes input, journals its wake, acknowledges the Hub and records the receipt. The run holds time at an unfinished delivery, and restores admitted input locally before a new decision.

# Agent Note: 持久模拟协同

Status: proposed

[English](2026-09-17-durable-simulation-coordination.md) | 中文

## Problem

长期社会、组织与资源模拟需要超越单次 Agent 激活的持久身份、责任、信念和模拟时间。聊天历史无法确定请求是否已接受、承诺是否已兑现、行动是否改变了世界。数千个实体不应要求数千个常驻模型循环。

Clocky 的 Team 已经拥有可靠协作能力。模拟需要保留其权限与 Session 重建规则，同时补充业务状态、延迟感知、确定的提交顺序和重启恢复。执行父节点不能等同于上级，投递回执不能等同于业务接受，模型的断言不能等同于世界事实。

## Proposal

在 Team 之上新增显式启用的 Simulation 组合。Entity、Interaction、World、Knowledge 与调度保持各自的逻辑归属，首个提供方对每个 run 使用一条 Simulation 日志和一个串行写入者。这让 Decision 接受与其 outbox 真正原子写入，无需跨日志事务。只有独立演进需要时才拆分存储或包。

本地 JSON/SQLite 实现包含无需密钥的双实体请求／资源和五角色采购场景、有界认知、知识隔离与检查点恢复。测得容量仍受记录的硬件与工作负载限制。多 Hub 联邦、世界分区、历史物理删除、生产分支执行和真实外部副作用仍为提案或延后范围。

[开发计划](../../../plans/2026-09-18-durable-simulation-coordination/development-plan.md)拥有工作包状态与验证证据，其候选摘要固定已交付的本地范围。基准源码哈希排除临时 Loader 配置与数据目录。日志折叠负责持久检查点与决策的校验；实时方法使用已验证的记录，不重复不可达检查。本设计仍为范围之外的能力保留 proposed 状态；本地交付完成不证明这些能力已完成。

本地 run 基础复用现有 JSON/SQLite Storage 后端，并为每个 run 持有独立的 SQLite 排他事务，建立同宿主协调器所有权。只有 CAS 的写入者或带过期时间的租约会允许第二个协调器在追加之间或暂停期间进入；操作系统锁则在进程退出时释放。基础层的管理状态不授权 Team 效果或模型决策。

认知协调使用规范 Team 不可变的 `activationLifecycleOwner` 规则。控制器在启动、持久绑定、退役与恢复时调用注册所有者；领域 writer 记录与 Team 共用启动预留 id。固定实际 in-process 提供方可关闭实现替换的竞争窗口。writer 尚未确认退役时，run 不得释放协调器所有权。

决策 slot 在推理前固定实体、writer epoch 和输入 revision。一次接受批次保留全部操作意图，本地结算记录原子派生守恒资源、授权与承诺证据。结果跨 writer 退役和重启保留。实时准入回调与撤销共用 run 队列，在新接受前检查当前 Team/Agent 权限。

调度键和计数器是日志事实，不是现实时间定时器。wake/期限事件的创建与来源业务操作共用批次；消费原子转移责任为持久 wake 或期限结果。microstep 停滞保留待处理工作，直到显式取消并恢复，而不是静默越过它推进时钟。

Outbox 尝试保留精确的已接受频道与 payload 指纹。传输 IO 不持有 run 串行队列；终态回执或不确定尝试通过该队列写回。重试预算限制自动技术重试，显式恢复记录允许继续幂等对账。发送者退役不能删除已接受操作；权限丢失后只允许对账目标已提交的既有结果。

## 身份、组织与认知

每个持久模拟对象均以 `runId` 为作用域；分支使用独立的 run 命名空间。新增跨包标识使用 `@clocky/clocky-brand` 的 `Branded<B>`，在持久化、工具和协议输入处验证。EntityId、ParticipantId、SessionId、ActivationId、DecisionId、OperationId 与 EnvelopeId 不可互换。

Entity 拥有种类、生命周期、profile revision 与 JSON 元数据。person 和 organization 是模拟种类，不是 Team participant 种类：模拟人物仍是 Agent 支持的实体，Team human 则表示真实用户。无认知能力的实体不需要 Participant 或 Session。

组织关系边包含 `subjectId`、`relation`、`objectId`、可选组织作用域、有效区间与 revision。`reports-to` 指向人物，`member-of` 指向组织，`part-of` 连接组织；schema 验证端点种类和配置的环约束。带作用域的关系要求配置 `scopeKinds`；时态环与显式组织查询均限定在该作用域。雇佣与成员关系只由 Entity 拥有；World 可以引用这些记录，不能独立修改第二张雇佣表。

MVP 为每个认知 Entity 绑定唯一的 `{teamId, participantId, sessionId}`。组织层级在该 Team 之外建模。通用映射未来可以支持多组成员身份专属的 Participant/Session，但不能让一个 Session header 跨 Team 共享。多成员身份认知需要明确的主所有者与其他 Session 的协调机制，并非映射天然具备的能力。

Simulation 写入者状态记录 `{runId, entityId, writerEpoch, binding, cognitionRevision}`。先持久预留 epoch，再激活；绑定控制器返回的精确身份后才允许决策。每次决策在接受它的同一次 Simulation 追加中验证 epoch 和 revision。恢复必须通过控制器证实旧激活已终止，才能授权继任者，未来跨成员身份也遵守此规则。超时、idle 状态或内存句柄不存在都不足以释放写入权。

所有 Simulation 激活退役与替换路径，包括恢复和管理取消，都必须通过 run 协调器与决策准入串行化。先持久撤销 writer epoch，再请求控制器 fence 或销毁，之后才能准入继任者。读取快照后无协调地追加不足以保证此规则。针对模拟绑定的通用控制器与恢复入口在启用前必须接入这项协调。撤销与控制器清理之间崩溃时，实体保持阻塞并等待恢复，不能由两个 epoch 同时写入。

Subagent 可以计算辅助结果，但不能直接写入所有者的认知或冒用其权限。报告通过与其他观察相同的已记录、已授权输入路径。单认知写入者约束模型决策，不禁止接收：决策期间可以记录新消息，但只能在之后固定的输入快照中成为可用信息。

## 交互、任务执行与承诺

Interaction 是由 Team 承载的业务对象，不是替代消息总线。首个协议支持单受理者的 request、accept、reject、defer 与 result。inform、proposal/counteroffer、escalation 和多接收者协商留给后续独立状态机。自然语言是证据；只有通过验证的结构化操作才能改变业务状态。

请求记录请求者、受理者、目标、revision、创建时间、可选回复与完成期限，以及带作用域的传输引用。引用包含 run、Team、channel、Envelope、recipient 和 sequence，而非裸 EnvelopeId。创建请求获准时把角色地址解析为 Entity。之后更换经理不能静默改投；重新分配必须是经过 revision 检查的事件。

保留三个独立投影：逐接收者的传输投递、业务回复（`pending`、`accepted`、`rejected`、`deferred`）和执行。传输状态从 Team 回执与过期事实读取，不另建可变的 Interaction 投递队列。有 TeamTask 时执行状态从其记录投影；无任务的本地执行由 Interaction 协议拥有。不能用一个混合状态枚举制造相互矛盾的投影。

accept/reject/defer 要求精确受理者、当前 revision，以及 pending 或可处理的 deferred 回复。accept 在同一 Simulation 批次创建唯一 Commitment。defer 记录下次回复事件；回复过期、完成期限、撤回和取消各自定义执行者与 revision 规则。并发 accept 与 cancel 串行化：仅一个预期 revision 成功。世界效果发生后的取消需要结算或补偿，不能抹掉已发生效果。

Commitment 记录债务方、债权方、目标、期限、revision、兑现策略与证据。TeamTask 完成是执行证据，不自动表示承诺兑现。只有显式声明 `task-completed` 策略时，才能从终态任务 revision 直接派生兑现；交货、库存转移或债权方验收需要各自的权威证据。截止时间可以记录违约，同时仍允许之后履行。任务重试与评审、承诺违约、取消和获接受的完成保持可区分。

状态报告包含变化、阻塞依赖、风险、待决策事项、下次更新时间和证据。委派目标包含预期成果、允许的能力、预算、期限和升级报告策略。向上汇报不转发全部私有聊天历史。模拟权限不授予 Harness 管理、文件系统、网络或真实付款权限。

## 原子决策、世界效果与 Outbox

用版本化 JSON 日志条目或原子批次写入 `DecisionAccepted` 及全部初始操作意图。run 写入者在追加前检查预期日志尾、实体状态、writer epoch、输入快照与 decision slot。追加冲突必须重新读取，不能重新生成操作身份。崩溃不能留下一个没有待处理操作的已接受决策。

World 资源事实、Entity 关系、Interaction 转移、Knowledge 记录、调度事件和 decision/outbox 投影共用首个提供方的日志。逻辑归属仍独立：只有 World 验证器可授权资源变化，只有 Entity 验证器可授权关系变化。本地世界事务原子记录前置条件、全部资源变化、操作结果和后续事件。争抢最后一件商品时，扣款与预留库存不能分别提交。

操作使用稳定键 `(runId, decisionId, operationIndex)` 和规范化 payload 指纹。同键同 payload 重试先返回已记录结果，不再因业务前置 revision 已变化而失败；payload 改变则拒绝。读取旧结果仍须鉴权。真正的新动作使用新键并验证预期资源 revision。多阶段计划持久化依赖顺序：对应世界操作成功之前，不得发布声称成功的结果。

决策被接受意味着系统负责处理其操作，不代表全部效果成功。操作投影区分 `pending`、`applied`、`rejected`、`blocked-authority` 与 `outcome-unknown`，保留尝试记录与目标端持久回执。前置操作失败会阻塞依赖者。补偿是显式新操作，不能回滚已经投递的消息或任意外部效果。

Team 仍是独立权威域。对其发布在本地接受后由 outbox 执行，使用稳定的目标端幂等键，保留目标端持久 Envelope 引用。在目标追加成功、本地确认前崩溃时，重试或对账同一操作。至少一次投递配合目标端原子去重才能防止重复业务效果；仅预期 revision 不提供该保证。

现有 `TeamSystemEnvelopePostScope` 没有通用 simulation 分支。实现必须新增受限 Simulation post scope，或经同等审查的桥接 API，包含精确的已接受决策、run、发送者绑定归属、解析后的接收者、channel、payload 指纹与 operation key。Hub 在 Team/channel 锁内重新验证。仅注册 source 名称不足以获得权限。持久决策证据不是运行时 proof；恢复由可信执行器获取新的不透明 proof。来源激活停止后，可以完成其已经接受的操作，但不能授权新决策。成员权限撤销、频道关闭或当前策略拒绝时，记录 blocked/rejected 结果，不能冒用新发送者。 任务 outbox 同样受 Team 准入约束：Team 非 active 或保留取消／关闭意图时拒绝新任务，但保留已提交任务的幂等对账；日志重放也校验创建时的 Team 状态。

模拟决策 preset 不提供通用 shell、网络或直接修改实时世界的工具。只读工具查询固定且已授权的快照；提案工具暂存操作，在已记录的工具结果中显示 pending 状态。一次显式 submit 完成 slot。世界效果仅在有序提交点执行。真实外部工具必须有对账或幂等支持；请求已执行但响应丢失时标记 `outcome-unknown`，不能盲目重试。MVP 不包含此类工具。

## 时间、可见性与决策窗口

SimTime 和大型 slot 计数器以规范的非负十进制字符串持久化。验证语法与配置范围，按数值比较；必要时临时使用 bigint 运算，不能按字符串字典序排列。原生 bigint 不是 JSON。run 配置固定 tick 单位、原点、时钟与规则版本和调度策略。Team 租约、投递 TTL、模型超时和进程监督仍使用现实时间；模拟期限使用调度事件。

事件顺序为 `(time, microstep, phase, slot)`。策略定义 phase 次序，并在推理前分配稳定 slot。同一时间产生的新后果进入后续 microstep，不能插到已提交事件之前。事件接受、取消、消费、slot 分配和时钟推进均持久化。拒绝调度到已提交的过去。超过配置的 microstep 限制时暂停为 stalled；只有显式记录的策略决策才可推进时间，不能隐式回退处理。

DecisionWindow 固定 world/entity/knowledge/interaction revision、可见性策略、已授权输入，以及每个认知实体的一个 slot。并发模型请求使用这个快照。结果按 slot 提交；不能因为另一个模型更快就越过缺失结果。每个 slot 记录完成、失败、取消或配置的超时。超时结果属于轨迹，可能随真实延迟变化；确定性保证适用于相同持久轨迹，而不只是相同 seed 或提示词。

提交时重新检查资源读取集与当前权限。无关世界变化无需使决策失效；前置条件冲突则记录 conflict，在后续 microstep 重新决策，并限制重试次数。知识选择同样使用固定的观察游标，因此世界值提交成功不会让所有 Entity 立即知晓。

通信延迟属于模拟策略。在 `deliverAt` 之前，outbox 通信意图可以持久存在，但接收者 Session、channel view、summary、搜索工具和上下文均不得暴露内容。MVP 延迟到该时刻才向 Team 发布，并在开启接收者窗口前处理发布结果。发布后，精确接收者投递仍须经过 claim、Session 持久化与回执。传输 TTL 过期表示投递失败，不自动终止业务承诺。

实时外部输入和人工干预获得持久 ingress 次序及分配的模拟事件键，不能修改已固定窗口。确定性回放保证包含这些已记录选择。暂停中的 run 继续必要的运行时监督，但恢复前不接受新模拟决策。

## 知识与模型上下文

世界事实、他人报告、推断与信念分别建模。Knowledge 保存 owner、kind、statement、revision、来源、`observedAt`、`availableAt`、可选有效区间和可见性依据。未来计划可以描述更晚生效日期而现在就可知；防泄露检查针对准入快照下的可用与观察时间，不是禁止 statement 内出现任何未来时间。预测不是已观察的未来事实。

来源必须保留：观察引用世界事件与可见性决策；报告引用特定接收者的传输证据；推断引用前提与产生它的决策；初始 persona 与信念引用版本化配置。信念置信度是策略数据，不是真实性的证明。承诺和任务状态在上下文中是权威引用，不是重复存储的可变知识事实。

撤销权限会阻止之后的检索，不能删除已记录到 Session 或派生摘要的信息。要求遗忘的场景必须显式替换模型上下文或 Session generation，并处理全部派生记忆；源日志仍在自己的访问策略下可审计。仅角色变化不承诺机器层面的遗忘。

上下文依次优先身份、生效权限、当前输入、活动目标、未完成承诺与期限、直接证据、授权观察、相关知识和可选历史。必需信息超过配置预算时产生 `SIM_CONTEXT_REQUIRED_ITEM_OVERFLOW`，阻止准入并 stalled。索引与向量检索是可重建的选择器；最终内容在推理前物化并记录。Simulation preset 限制文件系统、Session 搜索、Team 历史和工具访问，防止其他路径泄露完整世界或其他角色的私有上下文。

新增必读 Session 事件 `simulation/context-view`，包含 run/entity/window/slot 身份、writer epoch、带作用域的持久输入引用、投影 revision、策略/persona/模型配置版本和精确有序内容。Session surface 投影器仅从已记录内容派生模型输入。使用确定的 input id；在 pre-step 持久化屏障后完成 append 与 flush，随后才确认投递。恢复区分已记录 view、已排队输入和持久消费；仅有 view 不证明模型已消费。既不能重复已消费输入，也不能丢掉已 flush 但未消费的输入。

上下文刷新要明确替换哪一个旧 simulation context view，同时保留事件日志和无关对话历史。每次决策永久追加完整当前 view 不构成有界记忆。压缩保护必需的当前事实与待履行责任，不替代 World 日志。语义或决策摘要仍是派生数据，保留逐查看者来源；现有频道级摘要不能用于私有子集。

新增 Session 事件必须同步更新投影、验证、持久化读取器以及相关 SDK/ACP 传输，包括两个 SDK 的快照所有者。该事件 required-on-read，不能标记 `ignorable`。遵循 [Session 格式机制](../../implemented/architecture/2026-08-10-session-log-version-mechanism.zh.md)：结构格式未变化时 `SESSION_FORMAT_VERSION` 保持零；仅新增事件类型不会提升它。

## 投递所有权与驻留管理

普通 Agent Client 将 `context` 映射到非唤醒 inject，`turn` 映射到 followup，`steer` 映射到 steer。非唤醒注入已经暴露信息，也可能被无关唤醒消费。因此 Simulation run 需要对其绑定独占投递所有权，并使用受调度器控制的路径；禁止同时挂载普通 client 与另一个竞争消费方。

实现最小的显式集成：simulation 投递策略或消费方复用精确 claim、邀请验证、必要时冻结的 Hub-rendered view、去重、持久化屏障、回执与重连语义。调度准入控制输入何时可进入步骤；消费方不能虚构其他 participant 或重新生成频道 view。direct v4 传输文本与图片消息，不接受任意结构化 JSON：业务操作持久化在 Simulation 日志中，为 Team 渲染带引用的通信。自定义结构化频道需要独立的精确适配器和消费方协议。

新建频道需要端点同意。对休眠接收者，可临时建立其精确激活端点以验证邀请而不请求模型轮次，或将操作保持 pending 直到能够完成该步骤。不能从 Entity 成员关系伪造邀请同意。已获准的频道可为非驻留接收者保留待投递消息。跨组织网关与自治系统角色须在实现前明确各自授权设计。

通用 delivery-handler 注册表推迟到第二个消费方确实需要独立可替换处理器时。如果引入，保留公共 claim/persistence/receipt 所有者、精确版本与 schema 验证、effect 作用域注册、实现租约和有界卸载；处理器不能覆写权限或在持久化前确认。仅注册适配器不获得模型执行能力。

休眠要求所属轮次结束、Session 输入与结果已 flush、责任与操作已持久化，并在释放写入权前获得控制器确认的完全停稳。先关闭投递准入并排空已接受工作，再销毁。仅 `whenIdle()` 不足以证明安全。blocked 或 unknown 操作继续由持久 run 执行器拥有，可阻塞其因果依赖，但不必永久保留空闲 Agent 进程。任务绑定激活还须通过现有所有者结算或保留工作区与任务所有权。

容量分别限制实体数、驻留激活、并发模型请求、待处理交互与事件、每个模拟区间的消息与 token，以及重试次数。部署可变限制均为经过验证的插件 Config 字段。Simulation 限制与 Team `maxLiveActivations` 共同生效；placement 前预留启动容量，确认清理后才释放。确定性角色通过相同授权、事件和提交协议执行，无需模型调用。公平派发使用配置的优先级、期限和等待时长策略，持久化 slot 分配；派发公平性不能重排已接受提交。TeamDagScheduler 继续拥有任务分配与现实时间租约。

## 检查点、恢复、回放与保留

MVP 从有效检查点回放 Simulation 日志，再对照 Team 与 Session 日志协调待处理操作。完整跨所有者检查点是优化与可携带恢复引用，不是崩溃安全的初始来源。共用存储后端或收集最新 revision 都不构成一致切点。

完整 manifest 指定 run 身份，Simulation、Team journal、channel WAL 和 Session 的精确流 id 与持久游标，entity/knowledge/world 投影，window/slot 状态，writer epoch，ingress 游标，待处理事件与操作，不可变内容指纹，RNG 算法/seed/stream position，以及代码、schema、ruleset、persona、model 和 policy 版本。pending 清单必须符合这些游标处折叠出的状态，不能采用更晚快照。

其屏障暂停模拟准入、决策提交与 outbox 派发；将已准入的跨所有者操作排空到持久结果或明确记录的不确定状态；关闭模拟投递准入并等待已接受的 Session append/receipt；flush 全部涉及所有者；最后原子写入并固定完整 manifest。使用各所有者参与的屏障，或在发布前验证游标未变化且因果依赖完整。所有者游标推进会使本次尝试失效。外部输入仅可继续进入 manifest 排除的持久 post-cut 队列。崩溃后上一个完整 manifest 仍可用。收集前取得保留引用，发布或中止后才结束该保留过程。

回放使用固定实现折叠记录事件，不调用模型或执行外部效果。恢复在准入新工作前验证格式、保留引用、配置兼容性、控制器 fence 与操作去重。不得任意混合所有者最新状态与旧 manifest 游标后继续。引用前缀缺失或格式不兼容须明确失败。项目尚未发布：后端拒绝不支持的磁盘格式；schema 版本化不承诺数月的向后兼容执行。

分支要求新的 run 命名空间，复制 World/Knowledge/Interaction/调度投影，并重新映射 Team/Participant/Session/channel 身份。清除激活所有权，证实新的绑定；保留祖先引用但不写入父日志。不能在分支重放父级待执行的外部效果。仅复制 Simulation manifest 或 fork Session 不足够；身份映射实现并验证前暂不提供分支执行。

Logical Topic rollover 先打开并获准下一个频道，原子切换 Simulation 路由指针，记录前后引用。旧频道按 Team 规则排空待投递消息并关闭。主题成员变更不修改不可变频道 manifest。不得将待投递消息盲目转发进新段。分段限制活动段大小，不限制全部保留历史。

保留策略跨所有者保护待投递消息、未完成交互与承诺证据、检查点、分支祖先、Session 模型 view 和摘要来源。现有 Team retention 不认识 Simulation 引用。在启用物理删除前，须增加所有压缩器共同执行的跨所有者引用固定协议，或使用关闭破坏性 retention 的专用模拟存储。MVP 选择后者。Session 上下文压缩与投影检查点在满足源数据保留规则时仍允许。归档和索引变化必须保持证据可寻址。操作去重键及 payload/结果指纹在整个可重试与回放期间保留；旧意图仍可能重新到达时删除它们，会允许重复效果。

## 插件组合与实施次序

初始包应表达三种角色：`packages/simulation/simulation`（`@clocky/clocky-simulation`）声明服务与类型；`packages/simulation/simulation-local` 实现 run 日志、领域验证器与调度器；`packages/simulation/simulation-team` 消费 Simulation、Team Link、Activation Controller 和 Session。真正实现决策 preset 时再添加 `tool-simulation`。逻辑领域可以是同一提供方中的模块，不要为每个名词预建一个包。

公开操作区分观察快照、经过验证的请求、已解析规格和有副作用执行。工具不能提供可信 run/entity 身份或原始运行时 proof。World 读取是授权且固定的观察；proposal 暂存；执行器 commit 不向模型开放。实现前确定工具的 generic 渲染意图与有意义的 locations。所有注册表、策略和处理器贡献都通过 `ctx.effect()` 或 `ctx.on()` 注册并可撤销；持久记录在插件卸载后保留。

| 阶段 | 交付物 | 扩展前必须具备的证据 |
|---|---|---|
| 0 | Entity 绑定、JSON 安全的 id/时间、单流追加与折叠、writer epoch | 拒绝非法持久输入；重复与冲突操作及重启投影符合预期 |
| 1 | 无密钥双实体请求/接受、资源操作、Decision/outbox、独占 Team 投递、已记录上下文 | 每个接受点前后崩溃、延迟可见性、陈旧激活、无重复资源效果 |
| 2 | 决策窗口、期限、有界重试、休眠/唤醒与配额 | 反转模型返回顺序不改变提交；最后一件资源争抢；休眠邀请与容量恢复 |
| 3 | 五角色采购：CEO、仓库、采购、财务、供应商 | 请求、同意、资金预留、供应商回复、恢复与有证据的向上汇报 |
| 4 | 任务关联、更丰富知识、摘要、完整 manifest、规模测量 | 任务评审与承诺兑现区分、私有知识隔离、检查点切点及历史引用验证 |
| 5 | 可选分支执行、分段/保留、联邦、分区 | 分别设计并测试身份重映射、引用固定或分布式权限 |

只有类型而无可运行消费方的独立基础层不视为完整能力。恢复、授权与最小已记录上下文属于阶段 1，不能推迟到大规模激活之后。

## Alternatives considered

**新增消息总线或恢复隐式 Lead Teams。** 拒绝，因为 Team 已拥有可靠投递、身份、任务 attempt 与激活 fence。Simulation 在这些所有者之上增加业务意义和时间准入。

**将 Subagent 血缘作为组织层级。** 拒绝，因为执行所有权与父节点在线才可报告的条件，不能表示持久雇佣、多重角色或离线上级。

**Entity 全部成员身份共享一个 Session。** 拒绝，因为 Session header 与控制器 epoch 绑定一组 Team/Participant。MVP 使用一个规范执行 Team；未来成员身份需要独立 Session 和显式认知协调。

**每个领域使用独立日志，之后再写 outbox。** MVP 拒绝，因为 Storage 没有多流事务。一个提供方流可以在保持逻辑领域归属的同时原子记录决策与操作意图；未来独立提供方需要显式 saga。

**让工具在并行推理期间修改实时世界。** 拒绝，因为响应时间会在确定的提交次序之前决定效果。暂存操作让推理结果在接受前保持未生效。

**将摘要作为真源，或向每个角色发送完整世界状态。** 拒绝，因为摘要有损、可见性针对接收者，而主张不是客观事实。授权 view 保留精确的模型可见内容与来源。

**立即泛化 handler 并拆分所有领域包。** 暂缓，因为首个集成需要具体投递所有者，而非仍缺少持久化与 fence 职责的注册表。包拆分应跟随独立实现或消费方需求。

## Acceptance criteria

| 故障或场景 | 必须可观察的结果 |
|---|---|
| Decision 追加被中断 | 接受与意图均不存在，或同时原子存在 |
| World 效果已执行，响应或本地确认丢失 | 同一操作返回原结果；不二次扣款或预留 |
| operation key 复用但 payload 改变 | 明确冲突；不修改原结果 |
| 决策接受后发送者销毁 | 受限执行器 scope 完成已接受发布或记录拒绝；不伪造激活 |
| 替换激活后旧结果到达 | 新决策因 writer epoch/binding 拒绝；此前已接受操作保留已记录所有权 |
| deliverAt 前 Envelope 到达或被搜索 | 接收者 view、工具、摘要和模型请求均不包含内容 |
| Session 已 flush，回执或消费尚未发生 | 重试恢复一个待处理输入；不重复已消费输入 |
| 接收者休眠或启动清理不确定 | 不伪造同意、不丢投递、不释放容量、不产生第二写入者 |
| 接受与取消或期限竞争 | 一个经过 revision 检查的结果；先前效果仍可审计 |
| 任务完成但缺少所需兑现证据 | 执行可以结束；承诺仍未结算 |
| 模型以相反顺序返回 | 对相同提案与已记录超时结果，slot 提交一致 |
| 两个角色购买最后一件资源 | 一次原子资源事务成功；冲突有记录且重试有界 |
| 未来日期计划与秘密未来事实 | 已知计划允许；尚不可用的观察拒绝 |
| 角色失去权限或必需上下文溢出 | 拒绝后续检索；不虚称已删除已记录知识；溢出时 stalled |
| 检查点发布中断或所有者推进 | 上一个检查点有效；不发布不一致候选 |
| retention 试图移除被引用证据 | 支持引用固定的所有者拒绝，或已禁用破坏性 retention |
| 相同日志与版本下重启/回放 | 权威投影一致；回放期间无新模型调用或效果 |

纯排序与状态转移采用单元或属性测试，持久化/claim/fence 采用真实提供方的崩溃注入；每条新增模型或协议可见路径具有无需密钥的可运行示例快照。Session 生命周期或事件变更按[测试策略](../../../../docs/testing.zh.md)更新两个 SDK 的快照所有者。运行时不变量比较权威事件与状态关系，例如已接受决策与操作意图；品牌类型区分属于类型与 schema 测试，不能用空洞的服务存在性检查冒充运行时不变量。

测量实体数、驻留激活、模型并发、待处理队列、日志与 Session 增长、每模拟小时的消息与世界事件、模型 token/成本、回放时间、检查点耗时和饥饿情况。跟踪世界事件到 context view、Session turn、decision、操作结果和出站 Envelope 的完整链。stalled 使用类型化原因区分权限、预算、容量、冲突、未知结果、microstep 溢出或上下文溢出。基准目标包括 1,000 实体/20 驻留/10 模型调用/100k 消息，以及 10,000 实体/100 驻留/20 调用/1M 世界事件，随后是 20 部门、50 经理、500 员工运行 30 个模拟日。这些是实验目标，不是已证明容量。

## Risks

单日志串行写入且保留历史持续增长，是有意选择的 MVP 限制；分区前必须测量吞吐与恢复成本。固定决策 slot 可能被慢模型阻塞；显式超时以轨迹相关结果换取进展。单一规范 Team 限制拓扑，同时避免不受支持的 Session 共享。

模型输出不确定，看似安全的摘要仍可能包含错误主张或指令注入。将报告作为数据，在提示词之外独立执行工具与可见性约束，保留精确输入和来源。外部效果不确定、outbox 重试时撤销权限以及旧格式不兼容可能需要运维介入；必须显式可见，不能静默转为成功。

本地集成已执行 Team proof 准入、独占投递、Session 重建与全历史保留。发布回执保存完整目标作用域和频道位置；检查点收集与恢复核对对应的 Envelope 与任务创建记录。多 Team 认知、可携带分支及延期的分布式能力仍在当前计划之外；规模测量保留其已报告的限制。

Session 已加入必读的 `simulation/context-view` 事件，保存有序分节、带作用域的证据、版本化投影，并限制为精确替换一个旧 view。Session 重放与两个 SDK 的 wire 校验已识别该事件；上下文选择按显式字节预算写入 run 日志，必需内容超限会停滞。pre-step 所有者在推理前 flush 选中的 Session view 并复核实时权限。模型 stream 所有者在派发前 checkpoint 已消费输入与请求头，并拒绝对话或 view 不一致。决策输入使用固定身份与载荷，队列插入先 flush，再由 Agent 原位唤醒；重试区分排队中、执行中和已消费。writer 替换会退役中断 slot，保留 wake 责任，并能在同一 Session 驱动新 slot。

执行 Team 由不可变 `simulationRunId` 与 `activationLifecycleOwner` 规则绑定。已接受且到期的通信使用日志派生的 `simulation-operation` proof，固定 direct-v4 内容与目标幂等身份。activation proof 不能绕过该普通发布入口。目标响应丢失时对账原 Envelope；驻留接收者投递保留 Session 输入、wake 与目标回执。

Simulation 的 Hub claim 与 receipt 还要求专用 delivery-owner proof，并在等待策略后复核；通用 Agent Client 发现路径跳过这些 Team。驻留接收者消费者先 flush 输入、记录 wake、确认 Hub，再记录回执；未完成投递会阻止时钟前进，新决策前可本地恢复已准入输入。有界连接驱动自动推进发布与接收，在决策需求、驻留需求或技术重试处返回明确状态。休眠邀约在激活前冻结规范 Session，通过精确、可撤销的所有者权限确认，并保留既有过期检查。即使没有驻留 Agent，邀约所有者也须排空已受理确认后才释放协调者。目标放弃投递被保留为停滞事实；接收者对账保留持久输入或确认输入缺失后，才能显式恢复，业务承诺独立处理。

Outbox 重放与实时派发执行相同的窗口和依赖准入检查。冻结决策窗口期间不得开始尝试；派发前拒绝等待全部前置操作终结，并保持依赖失败优先于来源不可用的分类。已受理传输的结果在暂停后仍可持久记录。

模型决策准入仅用决策字典自身的键区分首次执行与重试，`constructor` 等不透明 id 不会继承 JavaScript 对象成员。重试复用同一准备输入，仍检查归属、wake 身份与最终 Session 持久化。

参与者邀请与阶段转换的响应必须保持 run 预留身份，才能继续授予拓扑权限或完成永久绑定。目标写入成功但返回外来身份时，仅保留可重试预留，不能据此确认原预留成员已激活。

排队或预留中的提名独占其待处理 wake，直到分配或取消。手动决策／窗口不能换一个 id 消费该 wake，否则保留的提名会失去派发资格，却继续阻塞时钟。确定性决策查询仅使用字典自身的键，保留不透明身份，不继承 JavaScript 对象属性。

真实模型基准要求显式提供端点、思考强度、协议格式与 token／调用限制，记录报告用量，并验证不推理的冷恢复。本地 HTTP 夹具检查思考请求参数与准入失败。SQLite 的 `deepseek-flash`／high 样本以 3 次调用、8,042 token 完成观察决策；重复决策不再次推理，检查点冷恢复一致且无模型调用／发布。规模结论仍为需要调优，原始报告与限制见[测量基线](../../../plans/2026-09-18-durable-simulation-coordination/current-scale-baseline.json)。

服务关闭立即停止所有已连接 run 的新准入，并开始关闭这些连接，同时排空已受理的引导工作。连接退出在注销生命周期所有权前排空输入持久化、直接 outbox 派发、收件查询与失败对账、休眠、恢复查询和模型决策完成，以及普通及自动驻留驱动。已受理驱动保留成功或失败结果；关闭不会在已受理的存储操作结束前返回。输入派发在持久化后、唤醒 Agent 前复核连接准入。

关闭在模型决策完成前保持 Session 存活。检查点收集在角色退役前取消规范本地角色并排空已受理工作；控制器释放会移除 Session，不能代替操作的最终持久化屏障。

对话推理要求准备输入属于当前活动的 Agent 回合；已结束回合中的消费事实不能授权另一请求。token 预留后的最终复核比较已记录的请求头、对话与 view。不一致会阻止模型 IO，并将 token 预留记录为未派发。

绑定所有者仅在持久绑定校验成功后发布 Agent 与激活身份。失败的重试不能覆盖已建立的身份，导致后续合法决策失效。

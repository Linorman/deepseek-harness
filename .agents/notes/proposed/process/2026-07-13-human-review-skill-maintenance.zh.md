# Agent Note: 定期用人工审查维护 dsh-code-review

Status: proposed

[English](2026-07-13-human-review-skill-maintenance.md) | 中文

## Problem

[dsh-code-review skill（技能）](../../../skills/dsh-code-review/SKILL.md)需要从人工审查提炼可复用经验。评论、已合并 PR（Pull Request）、已解决讨论或作者的“已修复”回复都不能证明采纳。把每条评论都变成规则会使 skill 膨胀；维护需要最终代码证据和独立判断。

## Proposal

维护者的私有工具每日扫描已刷新、干净且具有完整历史的 `origin/master` 检出，窗口重叠两个 UTC 日。手动运行接受其他 `--since` 时长或重复的 `--pr` 选择。根据当前 skill 判断已覆盖内容，使重叠扫描保持幂等，不存储仓库游标。这是未完成提案，不是仓库支持的命令或已运行的调度服务。

### Acquisition and adoption

只接受合并提交已进入 master 的 PR，包括已落地的堆叠 PR。重建落地合并的目标父提交；记录并跳过无法重建的 PR 和单次采集失败。搜索超过 GitHub 的 1,000 条结果上限时拒绝继续。完整分页获取审查评论、审查提交和代码提交。排除普通会话评论，因为历史重写后无法为它们确定仍存在的反馈前提交。

合格反馈由 GitHub `User` 账号提交，创建和最后编辑时间均严格早于合并；审查提交使用 GraphQL `lastEditedAt`。排除 PR 作者自己的评论。如果审查引用的提交仍存在，则选择严格早于反馈的最新 PR 提交作为基准 `B`。令 `T` 为落地合并的目标父提交，`M` 为落地合并：比较反馈时补丁 `merge-base(B, T)..B` 和最终 PR 补丁 `T..M`，排除仅目标分支引入的变化。强制推送后失效的审查、早于所有存续提交的反馈和无法重建的落地均归为 `unclear`。

两个独立适配器必须一致认定反馈为人工撰写且已采纳，再对照当前 skill 分类为候选、已覆盖、实现特有或非反馈。单条反馈也可成为候选。分歧只复评一次，并保留未解决证据。两个非候选结论即使理由不同，也排除该项。无效批次输出排除整个批次；若某适配器在一次操作的所有非空批次中都没有有效结果，则操作失败，不能报告“无候选”。

### Candidate and promotion

只根据双方认可的结构化指导起草。适配器不使用工具、不写仓库，只返回完整候选文本；双方在有界修订循环中审查同一份差异。工具只写目标 skill，在检查前后拒绝暂存或无关变化，并对写入和回滚执行比较并交换，避免覆盖并发编辑。失败回滚还要取消目标文件暂存。

成功产物记录源 master 提交和 skill blob、完整候选及差异、反馈 ID 和链接、落地证据、审查结论和检查结果。适配器原始输入输出保持私有。分析不提交、不推送，也不创建 PR。经维护者授权的集成助手从干净且已刷新的 master 启动，拒绝源 skill 漂移，并创建草稿 PR，附上证据、来源运行、检查和运维方编辑，接受常规审查。

### Isolation and ownership

适配器使用有版本、受字节限制且经过 schema 校验的 JSON。拒绝字节完全相同的审查器可执行文件；运维方仍须保证不同提供方或模型。子进程使用清理后的环境、私有工作目录、支持中止的进程树清理，并用 128 位随机 nonce 标记不可信反馈。这些控制不是操作系统沙箱；只读推理仍是适配器约定。生产 Git、GitHub 和检查命令使用相同的环境清理。

工具源码、适配器、凭据和调度仍是单维护者的私有基础设施。交接第二位维护者时，须通过后续决策确定仓库归属或新的私有配置。

## Alternatives considered

- **提交私有工具。** 仓库维护成本高于当前单维护者用途的收益；交接时可重新考虑。
- **观察每个反馈时刻的 head。** 更强因果证据需要持久事件状态、重试和历史重写协调。
- **存储已处理 PR 游标。** 重叠扫描与当前 skill 比较避免恢复和漏事件状态。
- **每条评论都触发运行。** 审查波次缺少证明采纳所需的最终产物。
- **把合并或讨论解决当作采纳。** 反馈可能在合并前被否决或替代。
- **自动集成。** 发布仓库变更前，工作流需要有效产物和维护者审查。
- **学习已修复的机器人发现。** 本提案只接受人工反馈，排除转发的自动化发现。
- **只使用一位作者兼审查者。** 独立结论检查缺乏依据的泛化。

## Acceptance criteria

记录中的 2026-07-15 运行扫描 62 个已合并 PR、跳过 5 个、考虑 426 条反馈，没有产出候选。不同适配器用约八分钟完成采纳与分类；一个无效批次失败关闭。这不能证明调度交付、成功集成或仅目标分支变化的负例已通过。

标记为 implemented 前，须观察到以下全部结果：

- 干净的 detached master 运行产出有效的无候选记录，或仅涉及目标 skill 的差异。
- 独立适配器无需干预即可完成采纳、分类和候选审查。
- 非交互调度交付持久的运维通知。
- 受控测试排除仅目标分支变化，同时保留后续 PR 自有变化的采纳证据。
- 集成拒绝 skill 漂移，并为当前候选创建带记录证据的草稿 PR。
- 运维方通过常规 PR 审查检查并合入至少一份生成的候选。

## Risks

提交者时间戳仍有时钟偏差或重写导致误判采纳的窗口。适配器字节不同不能证明提供方独立。POSIX 文件比较并交换只是尽力而为，不适合真正并发编辑。非候选理由分歧仍被排除，不再增加争议轮次。私有基础设施会停止维护，直到唯一运维方恢复服务或记录交接。

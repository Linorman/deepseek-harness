# Agent Note: Web UI 信息架构、视觉系统与交互重构

Status: proposed

[English](2026-10-02-web-ui-redesign.md) | 中文

## 问题

Web 客户端把 Clocky 呈现成"带一个 Team 页面的聊天应用"，但产品实际正相反：持久的多智能体 Team 工作才是主对象，会话只是深入查看某个参与者的入口。当前 UI 没有传达这个模型，用户无法一眼看出 Team 在做什么、谁被阻塞、哪里需要自己决策。

以下发现来自 [packages/client](../../../../packages/client/README.zh.md) 的已发布源码、一次实际 `clocky --profile web` 启动，以及 `.artifacts/` 中的端到端截图。

### 信息架构

- **空状态是死胡同。** 中央 hero 的输入框占位符写着"从侧边栏开始新任务"，发送按钮处于禁用状态，唯一真正的入口是侧边栏按钮。
- **导航文案不一致。** 同一概念分别显示为"New team work / New Task""Team work / Tasks""Working folders / Workspaces"；侧边栏还在 Team 列表旁保留了旧版 `sidebar.workspaces` 会话树。
- **侧边栏 Team 列表拥挤。** 每行只把目标截成几个字符（"Write a fil…"），状态文字与标题争抢空间，关闭按钮悬在行外，Inbox 按钮孤零零地位于文件夹标题上方。
- **协调者会话是覆盖在 Team 页面上的模态框。** `SessionStage` 打开 88dvh 的对话框，叠加了三层标题：对话框标题、会话标题、Chat/Trajectory 标签。"Back to team"折成三行，而对话框遮住了对话所讨论的 Team 状态。
- **Team 页面标题就是原始提示词。** h1 是 24px、两行的完整目标；面包屑显示内部工作目录名；失败以原始诊断信息呈现，例如"coordinator turn ended completed before an explicit final Envelope"。
- **概览以全尺寸展示"空"。** KPI 卡片显示 `0 / 0`；"Task execution"卡片约 400px 高，只有一句"No execution tasks"。待处理项和成员挤在窄栏中，并使用内部词汇（"Allowed to participate""Execution: Resident"）。
- **数据新鲜度靠手动。** 概览卡片暴露"刷新待处理预览""更新动态""刷新记录"等按钮；`ui-team` locales 中有 41 条刷新文案，而运行时本来就会推送 Team 变更。
- **传输错误泄露到内容区。** 产品凭据失效时，侧边栏用红字打印"transport failure for /api/team.list: HTTP 401"，设置页的 Agent 预设行再重复一次；没有重新认证的界面。
- **聊天展示协议文本。** Team 投递的用户轮次以"Direct message from participant-<uuid>:"开头，因为 [team-agent-client](../../../../packages/team/team-agent-client/README.zh.md) 把该前缀写进了模型可见文本。Think 行、上下文注入行和工具行视觉权重完全相同。输入框下方始终显示一行遥测（"1 turns · 2 steps | LLM 6.7s | TTFT … | Cache hit 98% | Input 15.8K tok …"）。

### 视觉系统

- **两套并行色板。** [design-platform.css](../../../../packages/client/ui-theme/src/styles/design-platform.css) 为 Team 页面定义 `--clocky-workspace-*`，其余部分使用 `--clocky-alias-*`；`[data-team-workspace-page]` 作用域重映射 alias，导致 Team 页面与会话页面的画布、文字、边框和强调色各不相同。品牌强调色同时存在 `#315fcc`、`accent-500`（`rgb(65,118,230)`）和 `blue-600` 三种。
- **侧边栏像另一个产品。** `[data-clocky-navigation]` 在浅色模式下仍保持石墨色导航，与白色画布形成生硬分界，使应用看起来像两个产品。
- **token 有不少冗余。** 深色块逐字重复了静态色板；`brand-primary-new-colorprimary-new-color`、`accent-700-delete` 等名称是导出残留。没有间距、圆角、层级或 z-index 刻度。
- **功能 CSS 绕过 token。** 99 个 CSS Module 中：字面 `font-size` 声明 361 处，字体 token 使用仅 89 处；字面内边距 442 处；字面圆角 8 种（1–999px）；z-index 取值从 0 到 1100。
- **排版没有角色。** 字体 token 按尺寸命名（`xs-13`，`m-18` 实为 16px），功能 CSS 因此直接挑像素值而非角色，造成卡片和列表行中层级扁平。

### 动效与交互

- 24 个 keyframes 和 56 个 transition 使用 80ms 到 3000ms 不等的时长；其中 43 处进入和离开都用 `--ds-ease-in-out`。退出没有独立曲线，也没有任何交互使用弹簧式落定。
- 共有 23 个减少动效（reduced motion）块，但覆盖按组件零散实现，而非系统级。
- 缺少全局键盘导航：没有命令面板、快捷键清单或列表键盘分拣；只有输入框和两个对话框读取修饰键。
- 产品的核心差异点——实时智能体活动——只以一个彩色圆点和状态词呈现。

### 仿真工作区

[ui-simulation](../../../../packages/client/ui-simulation/README.zh.md) 呈现持久的仿真运行：带认知与写入者的实体、按槽位排序且位于精确模拟时间的决策、发布与投递证据相互独立的操作、检查点、原生日志以及管理请求。以下发现来自源码，以及仿真快照测试写入 `.tmp-simulation-plan/` 的运行截图。

- **世界不可见。** 每个模块都是标签/值列表或表格。用户看不到谁与谁有关系、模拟时间里发生了什么，也看不到一个决策如何引发对其他实体的效果。部分数据其实已经存在：实体 `relationships` 带半开有效区间，决策带 `time`/`slot`/`entityId`，操作带发布与投递阶段。
- **目录是一串"未知"。** 每行运行都把场景、调度、时间和已受理工作重复显示为"不可用"。每行下方挂着两个展开项（"运行详情""技术详情"），"刷新运行状态"作为裸文本按钮悬在列表上方，分页位于右下角最远处。
- **运行头部的事实读起来像一句话。** 已保存阶段、驱动器进度、模拟时间、已受理工作和连接状态挤在一行小号标签/值中。开始与暂停并排显示，其中一个处于禁用状态。模拟时钟直接打印 `9007199254740993 minute` 这样的原始值，没有分组、本地化或相对刻度。
- **概览只有计数器和折叠项。** 四个 KPI 卡片（实体、token 占用、待决策、未结算操作）之后是折叠的"额度与对象详情"和"主机资源"。额度以 `180000 / 1000000` 文本显示，没有区间、预留或未知尝试的结构。
- **人工事项被埋没且过于技术化。** 任务审核位于页面下方，主要内容是 `task-8e41…` 和 `simulation-operation:5c51…` 这类哈希。任务控制与未知操作重试是彼此独立的区块，各有自己的刷新按钮（"刷新审核目标""核对当前任务"）。
- **过期以红字句子呈现。** "观察已变化，请刷新首页"和"保留的观察可能已过期，请刷新核对"以错误色显示在标签上方。绑定版本的游标确实需要显式刷新，但这种呈现让常规状态看起来像故障。
- **表格撑不住名称和数字。** 长实体名在单元格中折成十行；类别原样打印（`org`、`person`）；写入者状态只是小号副标题；检查器的分区切换（身份、关系、知识）是未加样式的文本按钮。
- **对话框是朴素的定义列表。** 开始确认以缩进的 `dt/dd` 文本列出模型、每次请求预留、区间额度、驻留上限和主机并发上限。创建对话框的页脚有四个同等权重的操作（"放弃输入""关闭并保留输入""检查配置""创建暂停的运行"）。
- **各种真实性状态长得一样。** 领域区分不可用与零、未知结果、过期观察、已隐藏内容、已截断文本、已占用与实际 token、发布回执与业务接受。在 UI 中，它们都渲染为同一种灰色文字。
- **仿真使用独立色板。** `.root` 直接消费 `--clocky-workspace-*`，`.reference` 使用了未定义的 `--clocky-alias-text-primary`。

## 提案

分十一个可堆叠阶段重构 Web 客户端。每个阶段独立交付，遵守 [packages/client/AGENTS.md](../../../../packages/client/AGENTS.md) 的 slot 与 props 纪律，按 [web-styling.md](../../../../docs/web-styling.zh.md) 使用 CSS Modules 和语义 token，不引入组件库或 Tailwind。产品文案以中文为先，并保留现有英文 locale。

### 设计原则

1. **Team 优先，会话其次。** Team 是页面，会话是页面中的一个面板。
2. **先关注事项，后清单。** 需要用户处理的内容排在最前；数量为零的模块折叠。
3. **默认实时。** 推送状态随变化渲染。手动刷新是放在溢出菜单中的恢复操作，而非主控件。
4. **表面用人话，协议细节按需展开。** ID、envelope、执行模式移到详情入口之后。
5. **一套系统。** 一套色板、一套字号阶梯，以及统一的间距、圆角、层级和动效刻度。功能 CSS 只消费角色，从不写像素值。
6. **键盘完整。** 每个主要流程都能脱离指针完成。
7. **说明事实从何而知。** 不可用、未知、过期、已隐藏、已截断、已占用、已回执是彼此不同的视觉状态，绝不退化为零或普通灰字。

### 目标信息架构

```text
┌───────────────┬──────────────────────────────────────────────────────────────┐
│ ◎ Clocky   ⌘K │  Folder › Team title                    ● Running  [⋯] [▶]   │
│ [+ New team]  │  Overview  Tasks 4  Channels  Members 3  Artifacts 2  ⋯      │
│               ├──────────────────────────────────────┬───────────────────────┤
│ Inbox      3  │  ⚠ Needs you (2)  approve · answer   │  Conversation pane    │
│               │  ────────────────────────────────    │  (coordinator or      │
│ ▾ ~/repo-a    │  Member lanes (live)                 │  selected member)     │
│   ● Team A    │  coordinator ▮▮▮▯ bash · 12s         │                       │
│   ◐ Team B    │  worker-1    ▮▮▯▯ waiting on review  │  …chat…               │
│ ▾ ~/repo-b    │  ────────────────────────────────    │                       │
│   ✓ Team C    │  Task board  [Board | Graph]         │  [composer]           │
│               │  Activity feed (streaming)           │                       │
│ ⚙ Settings    │                                      │                       │
└───────────────┴──────────────────────────────────────┴───────────────────────┘
```

- **侧边栏**由 [ui-sidebar](../../../../packages/client/ui-sidebar/README.zh.md) 与 [ui-team](../../../../packages/client/ui-team/README.zh.md) 负责：品牌与搜索触发器；唯一主操作"新建团队任务"；带计数徽标的收件箱；按工作文件夹分组的 Team，每项包含状态图形、两行标题（派生短标题与相对时间）和悬停操作。旧版 `sidebar.workspaces` 树移出产品组合。部署了 `simulationProducts` 时，仿真分组列出各运行及其阶段图形和当前模拟时钟，行结构与 Team 相同。
- **页面头部**：面包屑（文件夹 › Team）；由目标派生的短标题，完整目标放在可展开区块；一个状态徽标；随阶段变化的主操作（恢复、取消、打开对话）；溢出菜单。原始诊断移入状态弹层，提供人话摘要和"复制详情"。
- **对话面板取代模态框。** [ui-layout](../../../../packages/client/ui-layout/README.zh.md) 在可调宽度的右侧面板中渲染协调者或所选成员的会话，复用现有 `DragHandle` 与让位求解器，"展开"可将其提升为全宽。窄视口以全屏 sheet 呈现。由此移除 `SessionStage[data-inspecting]` 以及三层叠加的标题。
- **空状态变为启动器。** hero 输入框直接创建 Team 任务，附带文件夹选择 chip、预设 chip 和三个建议起点，去掉禁用的占位输入框。

### 阶段 0：基线与护栏

- 新增确定性视觉基线：在 `apps/web/tests` 下用 Playwright 从回放会话中捕获固定状态矩阵（空状态、Team 运行中/停滞/完成、含工具的对话、审批、提问、计划评审、设置、窄视口），覆盖浅色与深色。
- 在 `scripts/` 新增 lint 门禁，拒绝功能 `*.module.css` 中的字面 `font-size`、`border-radius`、`z-index`、时长和颜色。它以带白名单的棘轮方式起步：现存违规按文件列出，列表只能缩小。这是在落实根规则："可机械检查的规则要在执行的门禁中强制"。

### 阶段 1：设计基础（`ui-theme`）

用基于角色的刻度替换 [ui-theme](../../../../packages/client/ui-theme/README.zh.md) 的 token 层。保留角色正确的 `--clocky-alias-*` 名称，其余名称连同所有消费方在同一变更中删除（符合预发布立场）。

| 刻度 | 提案 |
|---|---|
| 颜色 | 一条中性色阶加一条强调色阶；删除 `workspace-*`/`navigation-*` 色板及重复的深色静态块。角色：`bg/{canvas,surface,raised,sunken,overlay}`、`fg/{primary,secondary,tertiary,disabled,on-accent}`、`border/{subtle,default,strong,focus}`、`accent/{fg,bg,bg-hover,subtle}`。 |
| 状态 | 一等公民的智能体状态，每个带 `fg`、`bg`、`border`：`running`、`waiting`、`needs-you`、`blocked`、`done`、`failed`、`idle`；用于徽标、泳道、侧边栏图形和工具行。 |
| 字体 | 角色阶梯：`display 28/36`、`title 20/28`、`heading 16/24 600`、`body 14/22`、`body-reading 15/26`（助手 markdown）、`label 13/20 500`、`caption 12/18`、`micro 11/14`、`mono 13/20`、`mono-small 12/18`；删除按尺寸命名的 token。 |
| 间距 | 4px 基数：`0,1(4),2(8),3(12),4(16),5(20),6(24),8(32),10(40),12(48)`。 |
| 圆角 | `xs 4`、`sm 6`、`md 8`、`lg 12`、`xl 16`、`full`。 |
| 层级 | `0` 平面、`1` 卡片细线、`2` 弹层、`3` 对话框/sheet、`4` toast；深色模式通过提高表面亮度表达层级，阴影保持克制。 |
| 图层 | `base 0`、`sticky 10`、`dropdown 100`、`overlay 200`、`modal 300`、`toast 400`、`tooltip 500`。 |
| 动效 | 时长 `instant 80`、`fast 140`、`base 200`、`slow 280`、`deliberate 400`；缓动 `standard (0.2,0,0,1)`、`enter (0,0,0,1)`、`exit (0.3,0,1,1)`，以及用 CSS `linear()` 近似的 `spring` 用于落定。全局 `prefers-reduced-motion` 块将除透明度渐变外的所有时长 token 映射为 `0.01ms`。 |

侧边栏改为同色调：浅色模式比画布深一级，深色模式再深一级，去掉生硬的石墨色分界。品牌定制仍可通过相同的 alias 覆盖实现。

### 阶段 2：基础组件（`ui-primitives`）

扩展 [ui-primitives](../../../../packages/client/ui-primitives/README.zh.md)，让功能包组合组件，而不是重新给原生元素写样式：

- `Button` 尺寸 `sm/md/lg` × 变体 `primary/secondary/ghost/danger`，以及必须提供无障碍标签的 `IconButton`。
- `Tabs`：下划线与分段两种样式，支持计数徽标和 roving focus。
- `StatusBadge` 与 `StatusGlyph`，由状态 token 驱动；运行态带小型进度弧动画。
- `Card` 与 `Section`：带标题、操作区和可折叠空状态。`EmptyState` 提供一个图标、一句话和一个操作。
- `Skeleton`、`KeyValue`、`Avatar`（参与者首字母与角色色调）、`Kbd`、`Popover`、`SplitPane`、`Sheet`。
- `FactValue`：分别渲染已观察、不可用、未知、过期、已隐藏和已截断的值；`SimClock`：不经数值转换地格式化精确十进制时间。
- `CommandPalette` 外壳：带分组、预览区和键盘模型的模糊列表，数据经由 slot 提供。

### 阶段 3：外壳与导航

- 落地上文侧边栏信息架构，统一文案为 团队任务 / Team work、工作文件夹 / Working folder、收件箱 / Inbox。
- 为 `401/403` 增加 `ConnectionBanner` 状态，说明本地凭据已失效以及如何从终端重新打开；侧边栏和设置页不再内联打印传输错误。
- 在 `ui-layout` 中引入对话面板，并移除 inspecting 对话框变体。

### 阶段 4：Team "任务控制台"（`ui-team`）

- **头部**按信息架构实现；标签显示计数，没有内容的模块（`Workflows`、`Audit`）收进"更多"。
- **"需要你处理"条**：非空时位于概览顶部，列出审批、提问、计划评审和阻塞项，并提供内联主操作，取代侧栏中的"待处理项"卡片。
- **成员泳道**：每个参与者一行，包含头像、角色、状态徽标、当前活动（"bash · 12s""等待 T-3 评审"）以及近期步骤分段条；点击在对话面板中打开该成员的会话。
- **任务看板**：按 `TeamTaskSnapshot['phase']` 分列；当 [team-scheduler-dag](../../../../packages/team/team-scheduler-dag/README.zh.md) 数据存在时，可切换为依赖图。卡片显示主题、负责人头像和阻塞项。
- **紧凑 KPI 行**（完成/总数、运行中、token、耗时）并入头部行，取代四个大卡片。
- **动态流**带相对时间实时推送记录；手动刷新移至溢出菜单，名为"从服务器重新加载"。
- **术语映射**：执行与参与状态使用人话标签，tooltip 中保留协议术语。

### 阶段 5：对话（`ui-conversation`、`ui-tool`、`ui-trajectory`）

- **阅读布局**：720–760px 栏宽，`body-reading` 字体；用户气泡改用 `accent/subtle`，取代饱和蓝。
- **发送者身份**：Team 投递的轮次渲染身份 chip（头像、角色、名称），隐藏协议前缀。这需要会话事件携带结构化发送者元数据；按根规则（模型可见输入必须可从会话日志重建），模型可见文本保持不变。若该元数据缺失，先在所属 Team 包中为会话事件增加字段。
- **过程分组**：连续的 think、上下文与工具行折叠为一个"工作了 42s · 6 步"的展开项；运行中显示当前步骤的单行实时滚动提示。失败步骤使该组保持展开，并使用 `failed` 状态色。
- **工具行**：前置状态图形，右对齐耗时；`diff`/`terminal`/`generic` 块统一为带标题栏（路径、语言、复制）的样式。
- **消息操作**在悬停和 focus-within 时出现，并保持键盘可达。
- **轮次元数据**：遥测行改为每轮次的"ⓘ"弹层，并在输入框中加入上下文环形图（[ContextMeter](../../../../packages/client/ui-conversation/README.zh.md)）。
- **输入框**：输入区上方加状态行（"正在运行 bash · 12s"、停止）；排队的插话消息显示为可移除的 chip；模型、权限和预设 chip 在左侧编组，发送按钮在右。
- **Trajectory**：步骤条改为可拖动的缩略导航，也可在 Chat 中作为可折叠侧栏使用；角色 chip 使用状态与角色色板，取代大写彩色文字。

### 阶段 6：仿真观测台（`ui-simulation`）

仿真成为与 Team 平级的工作区，与 Team 页面共享外壳、头部结构、标签、检查器面板和关注事项模型。目标是呈现被模拟的世界、它的时间和因果关系，同时保留 [ui-simulation](../../../../packages/client/ui-simulation/README.zh.md) 与 [simulation-product](../../../../packages/simulation/simulation-product/README.zh.md) 定义的每一项语义区分：

- 业务数据留在 Client runtime。
- 读取保持有界。
- 绑定版本的分页保留显式刷新。
- 任何视图都不暗示领域本身没有断言的接受、送达或完成。

**运行头部与控制条。**

- **已保存阶段与驱动器。** 已保存阶段（暂停、运行、停滞、完成）显示为徽标；驱动器观察是独立指示器，只在观察到驱动器活跃时才有动画。"已请求运行、未观察到驱动器"使用空心圆环，因此持久化的运行阶段不会被看成正在调度。
- **模拟时钟。** `SimClock` 组件保留精确的十进制字符串，渲染为分组数字加本地化单位（"1,240 分钟"），tooltip 显示精确值，绝不经过 `Number` 转换。
- **额度条。** 当前区间显示为一条分段条，已知占用、预留、未知尝试（斜纹）和显式追加额度各占一段，旁边是区间进度。信息入口说明：已占用额度不等于精确的模型用量。
- **驻留槽位与主机池。** 驻留槽位显示为一排圆点：活跃、预留、已撤销待释放（空心）和空闲。主机模型池是独立的 chip，并标明为主机全局。
- **主操作。** 唯一的主按钮遵循 Host 的开始/暂停提示。点击开始会打开启动面板，以卡片展示模型路由、每次请求预留、区间额度、驻留上限和主机并发上限。待定操作保留原标签并显示进度；结果未知时只提供查询和精确重试。
- **溢出菜单。** 包含检查点、恢复、实体输入、日志导出和请求历史。

**运行目录。** 每行显示名称、场景与版本、阶段图形、`SimClock`、迷你额度条和"需要你处理"计数。重复的"不可用"单元格改为一个带原因 tooltip 的"不可用"标签。状态刷新沿用现有按 `controlRefreshMs` 发起的有界 `runStatuses` 批量读取，因此去掉手动的"刷新运行状态"按钮。ID 移入溢出菜单（"复制 ID"）。分页紧邻列表。

**概览。**

- **"需要你处理"条。** 按优先级列出任务审核、任务取消、未知外部操作、带恢复动作的调度停止、冲突确认、额度或容量追加，以及投递失败。
- **人话摘要。** 每项都有摘要，例如"采购方 → 供应方：库存转移 1 件 · 已应用 · 报告已发布（接收方处理另行确认）"；任务和操作 ID 仍可在展开项中复制。
- **脉搏行。** 包含每个额度区间的决策与消息速率迷你折线、人口仪表、决策队列（开放、已提交、排队、已预留）以及效果流水线计数。

**世界。**

- **实体列表。** 显示类别图标、认知 chip（Agent、确定性、无），以及由写入者状态派生的驻留指示（活跃 = 驻留，已释放 = 休眠，预留/撤销 = 过渡中）。点击 Team 绑定会在对话面板中打开该 actor 的会话。名称最多显示两行，在检查器中可展开。
- **关系图。** 图视图以实体为节点、关系为边，组织作用域构成容器，时间滑块选择所观察的模拟时间。它首先基于现有的单实体 `relationships` 分区，展示所选实体的自我网络。全局关系图要等下文列出的运行级读取落地，并限制可见节点数；超过上限时按作用域和类别聚类，并可退回表格视图。

**时间线。**

- **泳道与标记。** 每个实体一条泳道（虚拟化），x 轴为模拟时间。决策按状态显示为不同标记：开放（空心）、已提交（半填充）、已接受（实心）、已取消（✕，原因见 tooltip）。同一时刻的槽位按槽位顺序堆叠，操作以小刻度挂在所属决策下方，检查点为竖线，当前时间显示为游标。
- **因果箭头。** 通信箭头连接发送方与接收方泳道，线型表示已确认的最远阶段：虚线 = 已接受，实线 = 已发布，实心箭头 = 已回执。箭头从不暗示业务已处理。
- **精确定位。** 位置相对窗口起点用 `BigInt` 从十进制字符串计算；过于密集的窗口切换为分桶计数。
- **分页。** 在时间范围筛选落地之前，时间线渲染已加载的决策分页，并在两端提供显式的"加载更多"。

**效果。** 流水线看板依次为 待处理 → 已应用/已拒绝 → 已发布 → 输入已持久化 → 已回执，另有"已阻塞"（权限或依赖）和"结果未知"两条侧泳道。未知卡片使用琥珀色斜纹，并打开现有的精确重试表单。每张卡片显示类别、实体、决策链接和任务引用。底部常驻说明：回执不等于业务接受。现有表格保留为视图切换。

**决策检查器。**

- **双时钟。** 模拟时间与真实推理时间使用不同图标显示。
- **上下文。** 上下文统计显示为按分区字节数分段的堆叠条，区分必选与可选；"本地冻结视图，不是完整模型请求"标签始终可见。
- **条目与来源。** 上下文条目带来源类型图标，来源链接到确切的 Team 频道。

**知识。** 卡片以不同图标展示来源类型（观察、已送达报告、推断、信念、摘要），前提链接绘制为小型推导图。每张卡片带时间可见性徽标；被隐藏的正文显示锁形图标及所需权限。

**检查点与恢复。**

- **检查点轨道。** 横向轨道展示检查点状态：进行中、失败（带诊断阶段与代码 chip）或完成（带 `publishedAt`），并突出最近一次成功的检查点。
- **恢复。** 恢复采用分步面板：先选择检查点，再查看分页的 Run/Team/Channel/Session 引用，最后确认。面板写明后果：旧写入者退役、所有者保持暂停、不重放任何内容。

**日志。** 虚拟化日志使用按族着色的类别 chip（run、business、scheduler、outbox），序号列标注为"序号（非时间）"。读者持有历史内容权限时，原始 JSON 用 `JsonTree` 展示。导出作为后台任务运行：进度条以 `maxExportPages` 为上限，最终校验步骤可见，并可取消。

**创建。** 双栏向导左侧为步骤（模板 → 参与者与库存 → 限额 → 检查），右侧为实时摘要卡片。预检问题内联显示在对应字段上。页脚保留"检查配置"和主操作"创建暂停的运行"；放弃或保留输入改为关闭按钮的行为，并需确认。横幅说明运行创建后保持暂停，不请求模型。

**过期与真实性状态。** 阶段 2 新增的共享 `FactValue` 组件负责渲染以下状态：

- 已观察
- 不可用：虚线框 "—"，附原因
- 未知：琥珀色斜纹 "?"
- 过期：变暗，附时钟图标
- 已隐藏：锁形图标
- 已截断：渐隐，可展开

版本变化时，在受影响模块顶部显示中性的"有更新 · 刷新 (R)"标签，取代红字句子；红色只用于真正的失败。Team 页面使用同一组件。

**Team 桥接。**

- **仿真管理的 Team。** 横幅说明由哪个仿真管理，并提供返回链接。
- **双向链接。** 实体与参与者页面互相链接。
- **actor 会话。** 从 actor 打开的会话带"仿真 actor"chip；其中 `simulation_observe` / `simulation_stage` / `simulation_submit` 工具行显示已暂存、已提交或已接受的提案 chip。

**规模。** 表格、泳道和日志都做虚拟化。时间线与关系图的标记超过约 500 个时，从 SVG 切换为 canvas。所有视图只读取有界分页，从不逐行发起检查读取，从而保留 `apps/web/tests/simulation-workspace.snapshot.ts` 与读取规模测试中的请求数断言。

**数据依赖。** 这些视图需要在 `simulation-product` 与 `client/runtime` 中新增有界产品读取。每项读取都遵循现有的授权、`maxPageSize`/`maxBytes` 与版本绑定游标规则，UI 从不通过扫描分页自行推导：

1. 给定模拟时间与作用域的运行级关系分页，用于全局关系图。
2. 决策浏览的模拟时间范围筛选，用于时间线滚动。
3. 通信与转移操作摘要中的目标实体，用于因果箭头。
4. 按区间聚合的序列（决策、消息、已占用 token），用于迷你折线。
5. 按实体的资源余额。由于余额可能是私有数据，它需要单独的授权决策，因此暂缓；在其落地之前不提供资源账本视图。

### 阶段 7：关注事项与全局交互

- **收件箱**（`ui-team` attention、`ui-user-questions` 与 `ui-simulation`）：跨 Team 和仿真运行的单一队列，涵盖审批、提问、计划评审、阻塞项、仿真任务审核与取消、未知外部操作以及调度停止。仿真事项保留其精确原始命令与当前栅栏语义；收件箱打开它们现有的表单，而不是发出新命令。支持 `J`/`K` 导航、`Enter` 打开、`A` 批准、`R` 拒绝或跳过；后端操作允许时，提供带撤销的乐观 toast。
- **命令面板**（`⌘K` / `Ctrl+K`）：跳转到 Team、成员会话、仿真运行、实体或设置项；执行 [ui-commands](../../../../packages/client/ui-commands/README.zh.md) 中的斜杠命令；新建 Team 任务。结果来自 slot 注册的提供方，功能包无需新增跨功能导出即可贡献内容。
- **悬停预览**：任务、成员和产物引用复用现有 `HoverCard`。
- **快捷键浮层**（`?`）列出已注册的快捷键。快捷键通过一个外壳服务统一注册，以便在注册时检测冲突。

### 阶段 8：动效规范

| 交互 | 规范 |
|---|---|
| 面板开合、侧边栏折叠 | `slow` + `standard`；内容交叉淡化 `fast`；拖拽期间从不动画。 |
| 弹层/菜单进入 / 退出 | scale 0.97→1 + 淡入，`fast` + `enter`；退出 `instant` + `exit`；变换原点位于触发器。 |
| 对话框/sheet | translateY 8px + 淡入，`base` + `enter`；遮罩淡入 `base`。 |
| 状态变化（徽标、泳道） | 颜色交叉过渡 `base`；`needs-you` 只脉冲一次（不循环）。 |
| 运行指示 | 1.2s 线性弧形旋转；离屏或标签页隐藏时暂停；减少动效时静止。 |
| 列表插入（动态、收件箱） | 通过 `grid-template-rows 0fr→1fr` 实现高度自适应 + 淡入，`base` + `spring`；移除 `fast` + `exit`。 |
| 过程分组实时提示 | 文本以 4px 位移 + 淡入切换，`fast`；节流至每秒不超过 4 次更新。 |
| 标签切换 | 下划线指示器滑动 `base` + `spring`；内容淡入 `fast`；无布局抖动。 |
| Toast | 从右下滑入 `base` + `spring`；5s 自动消失，悬停或聚焦时暂停。 |

除明确的 grid 行高模式外，只对 `transform` 和 `opacity` 做动画。

## 备选方案

**引入组件库或 Tailwind。** 起步更快，但 [packages/client/AGENTS.md](../../../../packages/client/AGENTS.md) 明确禁止两者。slot 模型已经提供了按功能隔离；缺的是 token 与基础组件层，而不是框架。

**只换皮、不改信息架构。** 仅更换颜色和字体会保留模态会话、以空为先的概览和手动刷新，而这些正是密度和层级问题的主因。

**保留模态协调者会话，只是放大。** 模态框仍会遮住对话所讨论的 Team 状态，标题也仍然层层叠加。侧边面板让两者同时可见，并复用现有的列求解器。

**保留石墨色侧边栏。** 它的品牌对比强烈，但在浅色模式下割裂界面，还重复了一整套色板。同色调侧边栏依然允许通过 alias 进行品牌覆盖。

**单分支一次性重写。** 可以避免中间态的视觉混杂，但违背 stacked PR 策略，评审不可行，还会让无关的客户端工作阻塞数周。

**把仿真并入 Team 页面。** 仿真运行有自己的权限、日志和生命周期，也可以在没有绑定 Team 的情况下存在。嵌入 Team 页面会在同一界面中混合两套权限模型；让实体与受管 Team 双向链接，可以保持各自归属清晰。

**为仿真使用通用仪表盘图表。** 在计数器上叠一组折线图很容易，但会掩盖领域所依赖的区分（已占用与实际、回执与接受、不可用与零）。时间线、效果流水线和 `FactValue` 直接编码了这些区分。关系图布局仍可使用维护良好、只负责布局的依赖（例如力导向或分层布局包），按 [verify-client-packages](../../../../scripts/verify-client-packages.ts) 声明；它不是组件库。

## 验收标准

- 只有一套色板和一套角色刻度。功能 CSS Module 在棘轮白名单之外不含字面颜色、字号、圆角、z-index 或时长；到阶段 10 白名单清空。
- 首次使用的用户无需借助侧边栏，即可从空状态创建 Team 任务。
- 在 1440×900 的 Team 页面中，首屏无需滚动即可看到：Team 状态、每个待处理的人工操作、每位成员的当前活动和任务进度。
- 宽度 ≥ 1280px 时，打开协调者或成员对话后 Team 页面仍然可见。
- 无需任何手动刷新控件即可看到推送的 Team 变更；重新加载仍保留在溢出菜单中。
- 主内容区不出现原始传输错误或协议 ID；协议细节仍可通过详情入口查看。
- 收件箱分拣、命令面板导航和 Team 创建都能纯键盘完成，快捷键浮层列出这些操作。
- 在 1440×900 的仿真运行页面中，首屏无需滚动即可看到：已保存阶段、驱动器观察、模拟时钟、区间额度结构、驻留槽位，以及每个待处理人工事项的人话摘要。
- 每种仿真真实性状态都通过 `FactValue` 渲染。不可用的计数绝不显示为 `0`，过期或版本变化提示不使用错误样式。
- 世界、时间线和效果视图能以有界分页渲染基准规模（1000 个实体）的运行，且不逐行发起检查读取；现有仿真快照套件在 json 与 sqlite 下都通过。
- 浅色与深色模式都通过对比度检查；减少动效会移除所有非透明度动效。
- 每个阶段都通过 `pnpm run typecheck`、`pnpm run lint`、聚焦的 `pnpm run test` 以及 `CLOCKY_SNAPSHOT=replay pnpm run test:web`。

## 风险

- **token 迁移触及每个客户端包。** 阶段 1 影响面最大。棘轮门禁和视觉基线让回归保持可评审；预发布立场允许直接删除旧名称而不加兼容层。
- **发送者身份可能需要变更会话事件。** 如果会话日志中尚无 Team 发送者元数据，阶段 5 依赖 Team 包的事件变更、其 SDK 负责方，以及一个可运行示例快照。
- **实时泳道可能开销较大。** 成员泳道需要读取每个参与者的当前活动，必须使用有界窗口的推送投影而非轮询；`client/runtime` 可能需要新的读模型。
- **键盘快捷键可能冲突**，涉及浏览器、输入法和输入框的绑定。需要注册时的冲突检测和输入法组合态保护。
- **新增仿真读取会扩大产品接口面。** 运行级关系、时间范围筛选、操作目标和区间序列在被 UI 使用前，都需要在 `simulation-product` 中具备授权、字节上限、游标绑定和 Host 测试。
- **视觉隐喻可能夸大事实。** 一个箭头、一个实心标记或一列绿色都可能暗示日志并未断言的送达或完成。每种仿真编码只对应一个具名领域状态，并由组件测试断言这一映射。
- **精确模拟时间难以绘图。** 时间是任意精度十进制数，坐标轴计算必须停留在 `BigInt` 与字符串空间，并能处理跨度超出 `Number` 精度的窗口。
- **放弃的能力：** 石墨色侧边栏的品牌外观、产品组合中的旧版工作区会话树，以及按尺寸命名的字体 token。

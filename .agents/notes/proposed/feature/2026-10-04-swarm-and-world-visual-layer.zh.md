# Agent Note: Team 与 Simulation 的蜂群与世界可视化层

Status: proposed

[English](2026-10-04-swarm-and-world-visual-layer.md) | 中文

## 问题

[Web UI 重构](2026-10-02-web-ui-redesign.zh.md)已交付信息架构、角色 token、基础组件、诚实状态、对话面板和命令面板。它的成果是一个运维控制台，但没有让产品的两个差异点成为用户第一眼看到的东西：一群 agent（智能体）通过并行运行更快地完成工作，以及一个在模拟时间中运转的模拟组织。

以下发现来自重构完成后 [packages/client](../../../../packages/client/README.zh.md) 下的源码：

- **并行没有画面。** Team 概览只用一个 KPI 数字表示并行工作。[TaskBoard](../../../../packages/client/ui-team/src/client/TaskBoard.tsx) 每列最多显示四张卡片。依赖只以 `dependencyCount` 标签或工作流视图中的“依赖”文字出现。界面看不出有多少 agent 同时运行、工作如何沿依赖展开、吞吐如何随时间变化。
- **蜂群结构只是列表。** 协调者、worker、reviewer、频道成员、任务归属和子 Team 都渲染成行，用户看不出谁和谁协作。
- **两种模式看起来一样。** Team 与 Simulation 是侧边栏中两个样式相同的按钮，底下是同一块中性画布。界面没有提示当前处于哪种模式，也没有说明 Simulation 模拟的是不同规模的组织。
- **动效止步于控件。** 重构的动效表覆盖弹层、对话框、toast 和列表插入。没有任何动效把一次实时数据变化串联到多个视图，例如任务切换阶段、消息送达或 Team 完成。推送来的状态只表现为文字变化。
- **已规定的可视化没有落地。** 重构规定了 Team 依赖图、成员当前活动、Simulation 的世界、时间线、效果视图与检查点轨道，以及读取 R1–R4，但源码中都不存在。如果在各功能包内分别实现，就会重复布局、命中检测、视口、键盘遍历、canvas 切换和减少动效处理。

## 提案

在已交付的重构之上增加一个表现层，并接手重构已规定但未落地的可视化。本 note 不改变重构的任何信息架构、诚实状态编码或 Simulation 编码。它原样沿用这些编码实现接手的视图，负责所有视图如何渲染和运动，以及下文列出的新 Team 视图。[开发计划](../../../plans/2026-10-04-swarm-and-world-visual-layer/development-plan.md)负责工作包、顺序和状态，其[清单](../../../plans/2026-10-04-swarm-and-world-visual-layer/checklist.md)跟踪完成情况。

### 设计原则

1. **蜂群与世界是第一画面。** 每种模式的概览以一个由真实数据驱动的实时可视化开头，表格退到一次切换之外。
2. **炫目但不夸大。** 可视化沿用 2026-10-02 重构的诚实状态：显示已加载数与总数，页外引用画成幽灵节点，陈旧观测降低饱和度，不可用值画成虚线空槽。每种视觉编码对应一个具名的领域状态，并由组件测试断言这种对应。
3. **只有观察到的实时变化才动。** 首次加载、刷新、回放和导航都静默呈现已稳定的状态，历史变化永远不会被当作正在发生来表演。
4. **动效分层并有上限。** 每一层都有频率、时长和并发上限。
5. **每个可视化都有等价视图。** 列表或表格视图展示相同的条目，键盘遍历能到达每个节点。

### 视觉方向与 token

设计评审从深色主题开始，并要求浅色主题同等完成。画布带一层极淡的点阵网格，作为图的坐标空间。浮动面板使用玻璃材质，实时状态使用光晕，指标使用等宽表格数字。

[ui-theme](../../../../packages/client/ui-theme/README.zh.md) 新增以下 token 族，每个都有浅色和深色值：

| 族 | Token | 用途 |
|---|---|---|
| 模式身份 | `--clocky-mode-{team,simulation}-{fg,bg,subtle,glow,gradient}` | Team 用电光青到钴蓝的色阶；Simulation 用紫到洋红的色阶。只用于外壳（背景、模式切换器、头部光晕），从不用于承载状态的标记。 |
| 光晕 | `--clocky-glow-{running,needs-you,failed,done}` | 由状态角色派生的 box-shadow 组合 |
| 材质 | `--clocky-surface-glass`、`--clocky-blur-glass` | 浮动面板与浮层 |
| 可视化 | `--clocky-viz-{grid,edge,edge-active,edge-ghost,node-ring,halo}` | 图的网格、连线、幽灵引用 |
| 字体 | `--clocky-type-hero`（40/48/600）、`--clocky-type-metric`（32/36 等宽） | 横幅数字与仪表 |
| 动效 | `--clocky-duration-{orbit,flow,celebrate}`、`--clocky-ease-emphasized`、`--clocky-stagger-step` | 环境漂移、消息粒子、里程碑时刻、错峰入场 |

Simulation 身份色阶必须与 `waiting` 状态角色可区分。token 测试在两种主题下测量对比度和色相距离。

### 动效层级

| 层级 | 示例 | 时长 | 上限 | 减少动效时 |
|---|---|---|---|---|
| L0 环境 | 背景漂移、网格视差 | 周期不少于 20s，不透明度不超过 0.35 | 每屏一个；隐藏或离屏时暂停 | 静止 |
| L1 实时信号 | 运行节点光晕、频道消息粒子、运行卡片扫光 | 粒子飞行约 1.2s | 同时 24 个粒子；超出部分合并为一次“+N”脉冲 | 一次不透明度闪烁 |
| L2 状态转场 | 看板卡片换列、节点阶段变化、数字滚动、进度环 | 200–400ms，使用 `spring` | 同一时刻一组编排；可被打断 | 立即切换 |
| L3 时刻 | 集结、收敛、点火、封存、停滞 | 不超过 1.2s，只播一次 | 只在实时观察到的转换上触发；任意输入可跳过 | 仅淡入淡出 |

约束：

- 只对 `transform` 和 `opacity` 做动画。粒子沿曲线连线运动时，WAAPI 关键帧把路径采样成一组 `translate` 步骤。
- 连线描绘入场需要 SVG `stroke-dashoffset`。[web-styling.md](../../../../docs/web-styling.zh.md) 为 `ui-viz` 内的 SVG 连线增加一条窄例外，`verify-client-style-tokens` 只对该包放行。
- React 只在数据变化时渲染，逐帧工作通过 ref 和 WAAPI 完成。
- 重构的规则继续有效：`needs-you` 只脉冲一次而不循环，运行指示在减少动效下静止，对话框和菜单保持原地淡入。

### `ui-viz` 包

`@clocky/clocky-client-ui-viz` 是展示层包，不接触 Cordis 上下文，也不依赖服务。功能包通过 props 向它传入视图模型。

- **布局函数**是确定性的纯函数。`layoutLayered` 使用最长路径分层和重心法减少交叉。`layoutRadialSwarm` 使用带种子的 `d3-force` 模拟，稳定后停止，新节点增量放置。`layoutLanes` 接收注入的位置函数，因此 Simulation 调用方可以在 `BigInt` 空间中保持精确的十进制时间。
- **渲染**在约 500 个标记以内使用 SVG，超过后使用 canvas，与 2026-10-02 重构的阈值一致。两种渲染方式的命中检测和焦点行为相同。
- **交互**提供节点间的空间漫游焦点、无障碍描述构建器，以及每个可视化都必须满足的列表视图约定。
- **基础组件**包括 `Odometer`、`RadialProgress`、`Sparkline`、`PulseHalo`、`FlowParticles` 和 `AmbientBackdrop`。
- **性能**方面，文档隐藏或元素离屏时暂停所有动画工作。

`d3-force` 是唯一新增的运行时依赖，遵循[优先使用依赖而非手写](../../implemented/process/2026-07-26-dependencies-over-hand-rolling.zh.md)，并按 [verify-client-packages](../../../../scripts/verify-client-packages.ts) 声明。分层布局自行实现，因为有界窗口让图保持较小规模。

### Team 视图

```text
┌ Mission banner ──────────────────────────────────────────────────────────┐
│ folder › short title  ● Active   [Open coordinator] [⋯]                 │
│ ◔ 12/20 done   ⚡ 5 running   ↗ throughput   ⏱ 01:24:10   Σ 1.2M tokens │
│ Overview · Tasks · Channels · Members · Artifacts · More▾               │
├───────────────────────────────────────────────┬──────────────────────────┤
│ Swarm topology        [Topology|Flow|Lanes|List] │ ⚑ Needs you            │
│   coordinator at center, workers in orbit      │ Live feed              │
│   message particles along channel edges        │                        │
├───────────────────────────────────────────────┴──────────────────────────┤
│ Task board (FLIP column moves)   │ Agent pods (state ring, current task) │
└──────────────────────────────────────────────────────────────────────────┘
```

- **任务横幅。** 它扩展 [ui-team](../../../../packages/client/ui-team/README.zh.md) 头部的 KPI 行。进度环按权威任务计数分阶段着色。“正在运行”统计已分配和运行中的任务。耗时从 Team 的 `createdAt` 起算。token 用量使用数字滚动。吞吐迷你曲线需要 T3，T3 落地前不显示，也不做估算。
- **蜂群拓扑。** 节点是已加载的参与者。已加载任务引用的子 Team 形成簇。连线来自已加载任务的归属与审核关系，以及已加载频道的成员关系。节点状态来自成员就绪度，T1 补充当前活动标签。粒子只在用户已打开实时读取的频道上飞行；其他 Team 日志推进让受影响节点脉冲一次。视图显示已加载成员数与总数。
- **任务流图。** 它实现重构中的看板/图切换。工作流计划按其有界的 `blockedBy` 窗口绘制，所选任务的依赖邻域来自现有依赖读取。页外依赖画成幽灵节点。只有整张图都已加载时才显示关键路径。全 Team 依赖图需要等待 T2。
- **Agent 泳道。** 每个参与者一条泳道，每次任务尝试一段条形，范围取自 `TaskAttemptSnapshot` 的 `assignedAt`、`startedAt` 和 `settledAt`。它需要 T3，因为不允许逐行读取任务详情。在此之前，每条泳道只显示 T1 当前活动。并行加速比（尝试时间之和除以墙钟跨度）只在 T3 覆盖整个窗口时显示。
- **看板与动态流。** 卡片用 FLIP 在列间移动，计数使用数字滚动。动态条目错峰进入，突发事件合并为一条。
- **Agent 舱。** 成员泳道在头像外增加状态环，显示 T1 当前活动，并对陈旧数据降低亮度。

### Simulation 视图

`ui-viz` 实现 2026-10-02 重构规定的世界、时间线、效果和检查点轨道，原样使用其编码，并按其读取规则实现 R1–R4。R1 和 R2 落地前，世界和时间线以重构定义的有界回退形式交付。本 note 增加：

- **运行控制台。** 开始时播放点火序列，随后交给驱动器状态环。按重构要求，状态环只在观察到驱动器活跃时转动。
- **席位图。** 驻留槽位改为网格，区分活跃、已预留、等待释放和空闲。
- **实体星图。** 在 R1 提供运行级关系之前，世界视图按类别聚合已加载实体，并让具备 agent 认知的实体发光。在当前模拟时间实时观察到的决策会在对应实体上泛起涟漪。
- **规模预览。** 创建时根据已安装模板的限额预览组织规模。

### 外壳

- 两个工作区都注册了导航时，[ui-sidebar](../../../../packages/client/ui-sidebar/README.zh.md) 渲染一个带滑动指示条的分段模式切换器。切换模式会改变环境背景的色调。未部署 Simulation 的环境保持现在的单一入口。
- 重构的启动器输入框上方放置两张模式卡片，每张显示一个实时缩略预览以及最近的 Team 或运行。

### 里程碑时刻

| 时刻 | 触发 | 编排 |
|---|---|---|
| 集结 | 实时观察到新 Team 且参与者加入 | 协调者在中心放大出现；worker 错峰进入轨道；频道连线描绘出来 |
| 收敛 | Team 阶段实时变为 `completed` | 节点向最终产物节点聚拢；结果卡片揭开 |
| 点火 | Simulation 运行的开始请求被接受 | 开始控件变为驱动器状态环；时钟开始滚动；世界从暗淡转为全色调 |
| 封存 | 检查点实时完成或失败 | 一个标记落到时间线上；失败时标记裂开并链接到诊断 |
| 停滞 | Team 阶段实时变为 `stalled` | 横幅出现 needs-you 光晕；需要你处理条脉冲一次 |

### Team 读取

每项读取都遵循 2026-10-02 重构的 R 系列读取规则：授权、`maxPageSize` 与 `maxBytes`、绑定版本的游标、拒绝路径测试，以及中英文 README 更新。它们都不新增会话事件，也不改变模型可见输入。

1. **T1 成员当前活动。** 每个参与者当前活动的推送式有界读模型，即重构为成员泳道规定的读模型。
2. **T2 任务依赖分页。** 一个 Team 内任务之间的有界依赖边，用于全 Team 任务流图。
3. **T3 执行时间线。** 每个参与者的有界尝试区间，以及按区间统计的完成数，用于泳道、吞吐迷你曲线和加速比。
4. **T4 频道流量。** 每个频道按区间统计的消息数，在没有打开实时频道读取时用作连线权重。

## 备选方案

**重新打开 2026-10-02 重构。** 那项工作已经完成。为了表现层和未落地的视图而重新打开它，会把已交付和新增的范围混在一起，并模糊它的验收标准。单独的 note 加上明确的职责划分表，让两个范围都便于评审。

**在各功能包内分别构建可视化。** 这样不需要新包，但会在至少五个视图中重复布局、焦点、canvas 切换和减少动效处理。

**采用 React Flow、Cytoscape 或 ECharts 等图表库。** [客户端规则](../../../../packages/client/AGENTS.md)禁止组件库，这些库也自带样式体系。缺的只是布局，`d3-force` 已经提供。

**用 elkjs 做分层布局。** 它约 1.4 MB。有界窗口让任务图足够小，最长路径分层加重心排序即可满足。

**用 WebGL 渲染 3D 蜂群。** 这是最炫目的方案，但损害可读性、无障碍和低端设备性能。

**加载时把历史回放成动画。** 这样每次访问都很生动，但会误报事件发生的时间，并违背只对实时变化做动画的原则。

**浅色优先设计。** 监控会话时间长，光晕在白底上效果差。浅色主题同等完成度仍是硬性要求。

## 验收标准

- 在 1440×900 下不滚动时，Team 概览显示任务横幅、包含每个已加载参与者及其状态的蜂群拓扑，以及需要你处理条。Simulation 概览显示带时钟、额度、席位图的运行控制台和世界视图。
- 每个可视化都有包含相同条目的列表或表格视图，并支持完整的键盘遍历，由 jsdom 测试覆盖。
- 没有任何可视化把未加载的条目显示为不存在。已加载数与总数可见，页外引用画成幽灵节点。
- 加载和刷新后没有正在运行的 L2 或 L3 动画（e2e）。
- 减少动效下没有任何非不透明度动效（e2e）。
- 150 个节点加 24 个粒子的性能测试中，第 95 百分位帧时间不超过 18 ms；标签页隐藏时不做任何动画工作。
- `verify-client-style-tokens` 通过，唯一例外是文档记录的 `stroke-dashoffset`；模式身份 token 从不出现在状态标记上。
- 模式身份 token 在两种主题下都通过对比度检查。
- 加速比和吞吐只依据 T3 数据渲染，从不估算。
- `pnpm run typecheck`、`pnpm run lint`、聚焦的 `pnpm run test` 和 `CLOCKY_SNAPSHOT=replay pnpm run test:web` 通过，每个 GUI PR 附带从真实服务流程录制的 GIF。

## 风险

- **视觉可能夸大。** 一条线、一个实心节点或一段收敛动画，可能暗示数据并未断言的完整性或因果关系。对应关系测试和已加载/总数标签是防线。
- **动效疲劳。** 长时间监控会放大环境和信号动效。层级上限和只对实时变化做动画的规则是防线。
- **包体积。** 除非客户端模块系统能延迟加载，否则 `d3-force` 和可视化代码会在每个概览页加载。
- **布局抖动。** 数据变化时力导布局可能打乱节点。必须使用带种子的布局、保留已稳定位置并增量放置。
- **新读取扩大产品面。** T1–T4 与 R1–R4 在任何视图依赖它们之前，都需要 Host 测试和授权评审。
- **接手的范围。** 世界关系图和连续时间线依赖 `simulation-product` 中的 R1 和 R2。这些读取落地前，视图保持有界回退形式。
- **深色优先评审可能忽视浅色。** 视觉基线为每个新视图采集两种主题。
- **放弃的能力：**以列表为主的概览。列表仍在一次切换之内。

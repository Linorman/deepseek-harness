# WebUI、Team 与 Simulation 产品需求

设计日期：2026-09-28。状态：实施中，整体尚未完成。面向产品、前端、Host、Team 与 Simulation 维护者。

本文定义目标行为和验收要求；开发 checklist、当前状态与剩余工作统一维护在 [实施计划](implementation-plan.md#1-实施顺序与依赖)；接口、持久化与运行时所有权查看 [API 与运行时设计](api-and-runtime.md)；架构取舍查看 [Agent Note](../../.agents/notes/proposed/architecture/2026-09-28-web-team-simulation-product-integration.zh.md)。

## 1. 工作重点与范围

WebUI 应让用户看清：团队正在做什么、阻塞在哪里、下一步谁来处理；仿真处于什么模拟时间、产生了什么结果、如何安全继续。

### 1.1 交付顺序

既定优先级：**产品功能、真实运行和失败恢复优先，UI 美化与视觉优化最后。** 基本可操作性、授权和状态正确性随功能交付。

| 工作包 | 重点与交付结果 |
|---|---|
| A · Team 正确性 | 纠正身份误标；离页依赖可编辑；空产物／工作流可刷新 |
| B · Team 可执行性 | 表单匹配权限；成员阻塞原因明确；待处理入口完整 |
| C · Simulation 读取 | Web／SDK 有界授权读取、结果追溯；浏览零模型调用 |
| D · Simulation 运行 | 创建、调度、输入、检查点与中断恢复形成真实 Host 闭环 |
| E · 自动任务执行 | 生产 executor 完成分配、执行、交付、attempt 与完成对账 |
| F · 重构与性能 | 按职责拆分，测量并修复热点，保持行为及恢复保证 |

此表不表示当前进度。A/B 可独立交付；C → D → E 依次建立读取、运行、自动执行能力。F 的职责拆分可在相关回归具备后穿插，性能优化须先有基线。前置条件见 [实施顺序](implementation-plan.md#1-实施顺序与依赖)。

### 1.2 首期边界

| 范围 | 要求 |
|---|---|
| 部署 | 同一 Host，本地 JSON／SQLite 存储，已支持的进程内 actor |
| 保留的架构 | Team、Session、Simulation 各自负责原有事实；不重写 agent-loop，不把世界状态塞进 Team 或 Session 日志 |
| 首期不承诺 | 远程多 Host 仿真、任意外部副作用、历史世界回滚、完整场景图形化编辑器、拖动改变任务状态 |

### 1.3 全局约束

- 查看、刷新、展开详情和检查 Session 不启动执行；关闭页面或浏览器断线不关闭 Host 持有的运行。
- 分页、重连和刷新不改变对象业务含义；业务数据由 runtime 管理，注册时创建的 UI store 只保存视图与草稿。
- 可用操作与阻塞原因由 Host 返回，每次写入重新鉴权；UI 不能放宽底层限制。
- 操作结果以权威记录解释，草稿与未知结果遵循 [通用交互要求](#5-通用交互要求)。

## 2. 页面与导航

Team 保留日常协作入口及现有概览、任务、频道、成员、产物、工作流和审计视图，Session 按需打开。挂载 Simulation 产品服务时，增加同级“仿真”入口，具有独立运行列表、详情和管理权限。未部署时隐藏入口；失效深链解释未部署或不可访问，并提供返回入口。

| 页面 | 优先展示 | 主要动作 |
|---|---|---|
| Team 概览 | 权威任务总数、待处理事项、成员／任务预览、最近动态 | 查看全部待处理、进入任务、打开协调会话 |
| Team 任务 | 有界列表、筛选、独立任务摘要 | 新建、编辑依赖、审核、停止、删除、查看执行记录 |
| Team 成员 | 身份、参与资格、执行就绪度及阻塞原因 | 邀请、允许参与、检查执行配置、查看记录 |
| Team 频道 | 频道、消息、草稿、邀请与协议状态 | 接受邀请、发送、查看送达结果 |
| Team 产物／工作流 | 有界内容、空态与读取状态 | 刷新；产物另提供预览、下载及来源任务入口 |
| 仿真列表 | 场景、模拟时间、调度／阻塞／恢复状态 | 创建、打开、恢复已登记运行 |
| 仿真详情 | 概览、实体、决策、操作与通信、检查点、记录 | 调度控制、输入事件、检查点、恢复 |

Simulation 的关联 Team 默认只读并标明“由仿真管理执行”。用户可检查任务、频道和 Session；普通 Team 运行、恢复、发送等绕过仿真行政服务的入口不展示，后端也必须独立拒绝。

## 3. Team 功能需求

T1–T3 对应 A，T4–T7 对应 B；编号用于定位需求。

### T1. 负责人身份不受分页影响

以 ownerId 判断是否分配，名称仅用于展示。概览、任务列表／摘要、尝试历史和频道参与者统一使用下表规则。

| 权威身份与查询结果 | 展示 | 可用动作 |
|---|---|---|
| 没有 ownerId | 未分配 | 根据任务权限提供编辑入口 |
| ownerId 存在，名称已解析 | 成员名称 | 查看该成员或对应历史尝试 |
| ownerId 存在，名称未加载 | 已分配 · 缩短的成员 ID | 按需加载详情、复制完整 ID |
| 同一授权上下文内网络读取失败或断线 | 保留已知名称；没有名称则保留获准的 ID，并提示详情不可用 | 重试 |
| 权限撤销或认证主体变化 | 清除不再获准的名字与详情，显示不可访问状态 | 返回允许访问的列表 |
| 成员已离开 | 历史名称与“已离开” | 查看历史执行，不暗示当前可调度 |

仅通过有界、授权查询补全当前屏幕所需名字，不遍历所有成员。runtime 名称缓存按连接、主体授权代际、Team 和身份隔离；翻页不清除任务引用。forbidden、退出登录或主体变化使受影响缓存失效，不泄露未授权身份或隐藏成员存在性。

### T2. 跨页依赖可编辑，冲突不丢草稿

编辑器分为“已选依赖”和“添加依赖”：前者读取完整 blockedBy，离页或名称未加载的依赖仍显示 ID 和移除按钮；后者使用同 Team 的有界服务端搜索／分页，排除自身及已删除任务。

候选分页独立于任务表格。选择与移除只改草稿，明确提交才发送完整依赖集合。候选为空、加载失败、无搜索结果分别提示，读取失败不清空已有选择。

Host 提交时验证 Team 归属、授权、任务状态、依赖合法性和循环。revision 冲突保留草稿并展示字段差异；用户基于最新记录确认后，以新命令身份提交。已删除依赖须列出条目和移除入口，不自动改写依赖。

### T3. 空产物与空工作流仍可使用

产物和工作流始终保留模块框架、刷新入口，异步状态遵循 [通用反馈](#53-异步反馈)。产物成功空结果显示“暂无产物，任务发布结果后会出现在这里”。

没有读取 provider 的产物显示“仅有引用，当前部署不能读取内容”。图片、二进制文件和文本按 provider 批准的格式处理；不根据扩展名擅自内联可执行内容。保留现有授权、下载和文本预览字节上限，文件来源链接指向确切任务/attempt。

### T4. 任务表单只承诺实际可用能力

Host 根据人工主体授权、已注册 provider、调度器支持、Team 规则及生命周期计算能力；浏览器不按插件名、成员 role 或固定枚举推断。

仅允许 shared 时，基础表单只提供共享工作区；高级区域列出其他模式及未授权／缺 provider 等原因。读写范围限制在输入前说明；敏感权限仅返回选择所需结果，不暴露完整 grant。

优先显示目标、说明、依赖和可用执行模式；placement、预算、能力约束放入高级区域。说明预算单位及 provider/model 含义，不只显示字段名。缺少执行选项仍可保存受支持的普通任务；必要条件不满足则禁止提交并指出处理位置。

能力读取失败保留草稿、禁用相关提交并提供重试，不猜测权限。每次写入重新验证；错误定位到字段或整表，权限拒绝不得显示为“内部错误”。

### T5. 成员参与资格与执行就绪度分开

操作命名为“允许参与”，active 仅供必要诊断。成员卡分别展示参与资格和执行状态，不共用“已激活”徽标。

| 参与资格 | 执行就绪度 | 用户解释 |
|---|---|---|
| invited/provisioning | 不适用 | 尚未允许参与或准备未完成 |
| active | route-unavailable | 已允许参与，但当前没有匹配执行配置 |
| active | ready | 已有可用执行配置，将按调度策略启动 |
| active | starting/resident/busy | 启动中、运行环境就绪或正在执行 |
| active | capacity-wait | 等待并发或资源容量，显示可公开的原因 |
| active | recovery-required | 旧执行尚未确认停止，需要恢复处理 |
| left | 不可调度 | 已离开团队，历史记录保留 |

Host 从实际 route、provider、运行绑定与容量计算就绪度，React 不重算。ready 须附观察版本，调度时重查，不保证下一次必然成功。service 和 remote-agent 按实际执行机制解释，不套用本地模型模板。

邀请自定义 agent 优先使用部署已注册配置。允许登记无路由成员，但提交前提示“不会自动执行任务”，详情列出缺失项和部署配置位置；任意 provider 字符串不能获得受信任执行环境。

### T6. 概览提供完整待处理入口

总数来自权威聚合，预览来自 Team 专属有界投影，不能以当前任务页或全局 inbox 窗口代替。排序依次为恢复／未知结果、人工审批／问题、任务审核；同级按创建时间和稳定 ID 排序。

总数非零即显示“查看全部待处理”，不受预览失败或漏载影响。目标页保留 Team 筛选，区分可处理、等待权限、已被他人处理和读取失败。回答前重查当前记录；过期表单保留安全草稿并提示变化。

### T7. 任务搜索明确查询范围

局部搜索标明“仅搜索当前已加载任务”；全 Team 搜索走 Host 分页查询，不在前端抓取所有页。已提交搜索和状态筛选进入 URL；切换筛选重置分页，清除立即生效并恢复焦点，中文 IME 组合期间不提交。

## 4. Simulation 功能需求

主流程：新建 → 准备完成并建立初始检查点 → 显式开始 → 观察结果／输入事件 → 暂停 → 检查点 → 中断后验证恢复至暂停 → 显式继续。自动任务模式在这条流程上补齐生产执行与完成对账。

### S1. 创建与首次启动

1. 从“仿真”进入运行列表，点击“新建仿真”。选择 Host 已安装的、带版本的场景模板，查看支持的存储、决策策略和模型配置。
2. 填写运行名称、模板允许的初始参数、实体/驻留与运行预算；查看主机共享模型并发上限、模拟时间单位、规则和策略版本。现有模型 permit 上限属于服务全局，本表单不能修改它；若后续增加单 run 限流，须独立实现并继续受共享上限约束。模型凭据通过已有 credentials 机制选择，不在模板 JSON 内粘贴密钥。
3. Host 预检配置、权限、provider 与模板闭包；错误返回具体字段。创建操作登记稳定 run 身份和不可变配置，不执行模型推理。
4. 进入 paused 的运行详情，显示实体/Team/频道预备情况；全部准备完成后、首次推理前建立初始完整检查点。部分准备失败可对账并继续同一创建流程，不能另建一套身份掩盖失败。初始检查点完成前不允许启动模型。
5. 用户点击“开始调度”，查看会产生模型请求的预算摘要；成功后观察调度和决策状态。

运行模板是受信任部署配置，不允许浏览器上传可执行 JavaScript、任意 cordis.yml、绝对存储路径或未授权模型路由。不可变 run spec 创建后只读；要变更规则版本或时钟定义，创建新运行。

### S2. 详情优先回答状态、阻塞与下一步

页头固定显示运行名称、场景版本、调度状态、独立的连接/恢复状态和主要操作。指标区显示模拟时间及单位、已用/上限预算、实体数、驻留占用、待决策数量与待处理外部操作；没有可信值时显示不可用，不显示零。

| 模块 | 首屏内容 | 按需详情 |
|---|---|---|
| 概览 | 当前阻塞与下一步、模拟时间、关键额度、最近业务事件 | 原因、责任对象和可执行操作 |
| 实体 | 名称、类别、参与关系、认知模式、驻留与 writer 状态 | 授权范围、关系有效区间、Session 与知识来源 |
| 决策 | 当前窗口、冻结 revision、slot 顺序、执行与提交状态 | 授权输入、来源引用、模型/确定性策略、提案与结果 |
| 操作与通信 | pending/applied/rejected/blocked/unknown、重试时间、送达状态 | 幂等操作身份、Team Envelope/任务 receipt、错误与依赖 |
| 检查点 | 请求状态、最近完整记录、来源验证与恢复结果 | Run/Team/Channel/Session 引用及校验失败 |
| 记录 | 有界事件时间线、筛选、导出授权范围内的数据 | 原始事件；面向普通用户的默认视图不展示整段 JSON |

未知结果和待恢复事项在概览显著提示，并提供精确定位。不得把“已提交决策”显示为“业务执行成功”，也不能把“消息已发布”显示为“接收方已处理”。

### S3. 控制操作与恢复保证

| 控件 | 真实含义 | 返回后的保证与限制 |
|---|---|---|
| 开始/继续调度 | 提交持久的 running 管理请求，驱动受限调度器 | 当前前置条件仍须通过；只改 phase 不能代替调度执行器 |
| 暂停调度 | 提交持久的 paused 管理请求 | 阻止后续调度推进；已接受的推理、操作和清理可能继续 |
| 创建检查点 | 暂停、关闭新工作准入、取消/排空受支持的在途工作、退休 actor、验证所有者并发布完整 manifest | 完成后仍保持暂停，不自动重新推理；失败不替换最近成功记录 |
| 验证并恢复运行 | 从完整检查点验证保留历史与当前后缀，处理旧 writer，再返回暂停状态 | 恢复当前持久事实，不回滚历史，不重放已完成的模型请求 |
| 输入事件 | 通过受授权 ingress 登记目标实体、文本和最早可用模拟时间 | 有 receipt 和分配时间，不直接修改世界事实或增加权限 |
| 重试操作 | 查询原幂等操作，满足策略后重试 | 未知结果需先对账；不分配新 key 来绕过去重 |

checkpoint 正在采集、未知 writer 未退休、历史验证失败或预算耗尽时，禁用继续调度并解释原因。暂停调度后仍有在途工作时，页头同时显示“调度已暂停”和“仍有工作收尾”。

恢复对话框明确显示检查点 ID、生成时间、验证对象、当前持久 revision，以及“不会回滚到该时刻”。历史回滚或分叉没有实现时，不提供同义控件。

### S4. 人工输入与知识可见性

输入事件前选择目标实体和可用时间，明确文本将进入其授权输入。提交后展示 receipt、待消费/已消费与关联 decision，不以消息出现在列表中代替消费确认。表单默认不向所有实体广播；广播必须是场景明确允许的操作。

实体详情使用“本次仿真上下文”展示该决策冻结并记录的视图。实际模型请求还可能包含保留的 Session 历史、系统提示和工具定义，因此不把这份局部视图命名为“模型看到的全部内容”；完整请求检查须从已记录请求重建，并单独进行读取授权。世界状态、管理员权限和实体知识可见性分别检查；没有权读取原文时，只展示获准的引用和删节说明。导出遵循同一授权规则。

### S5. 自动任务执行的启用条件

场景能力分为“只创建并对账任务”和“自动执行任务”。自动模式仅在生产 executor、调度、交付、attempt 与完成对账的端到端验证通过后启用。

首期自动执行支持受限的仿真任务：由仿真认知或确定性策略产生允许的世界操作及结果，再由专用 executor 发布任务事实；不赋予 actor 任意 shell/network/普通 Team 工具。任意外部工作任务保留为后续独立执行域，不能直接放开 Simulation Team 的现有发送和工具限制。完整协议见 [运行时设计](api-and-runtime.md)。

### S6. 模拟时间与真实时间分开

模拟时间遵循 run spec 的 tick 单位与原点，UI 保留 canonical decimal string；不得转换成 JavaScript Number 后进行可能失真的运算。排序由 Host 或精确整数比较完成。未定义日历映射时显示“模拟 tick”，不伪装为真实日期。

模型超时、HTTP 等待、租约、重试退避和用户看到的“请求于几秒前”使用真实时间。决策详情分别显示模拟 slot 时间和真实推理开始/截止/完成时间。暂停模拟调度不暂停基础设施超时。

## 5. 通用交互要求

### 5.1 导航与读取隔离

Team 和 Simulation 深链保存对象 ID、模块、已提交筛选与详情选择，不包含密钥、输入正文或未提交草稿。服务器逐次验证所属关系和权限。切换运行取消旧读取；后到的旧响应不能替换新选中对象。

前进／后退恢复筛选、选择与滚动。桌面采用列表加单个非模态摘要，窄屏一次展示一个主要工作区，并提供明确返回入口。任务表、频道消息和 Session 各自拥有滚动；固定表格高度不能裁剪长表单。

### 5.2 草稿与未知操作结果

频道继续保留文本、附件顺序、收件人、delivery 和幂等身份；模块或 Team 切换不能丢失。任务编辑和事件输入也保留未提交草稿，关闭有内容的表单时提供继续编辑/放弃，只有丢失输入时才确认。

敏感草稿默认不写 localStorage；重载可能丢失输入时，提供提示及浏览器离开保护。跨重载保存须另行设计存储、配额、过期和清除授权，不能当作已有能力。

断线不等于失败。未知结果保留原命令 ID，先查询或幂等重试；用户修改语义后才创建新 ID。不得为清除错误而自动再次创建任务、发消息或恢复仿真。

### 5.3 异步反馈

| 状态 | 展示与恢复要求 |
|---|---|
| 首次加载 | 显示加载反馈，不提前判断为空 |
| 成功空结果／筛选无结果 | 分别说明没有数据或没有匹配项，保留模块和相应入口 |
| 后台刷新 | 保留已加载内容，不抢焦点或自动滚动 |
| 局部失败／分页失败 | 展示错误与重试，不把失败当作集合为空 |
| 刷新失败／断线／已过期 | 保留仍获准的内容，标记过期或有更新；撤权后的清理优先于内容保留 |

状态变化保留按钮尺寸；阅读旧消息时只提示新消息。长目标、ID 和错误可展开或复制，不以 hover 作为唯一访问方式。高风险确认写明对象与后果；浏览、筛选、复制不增加确认。

### 5.4 视觉与可访问性

沿用 [DESIGN.md](../../DESIGN.md) 和 [Web 样式规范](../../docs/web-styling.md)：石墨色导航、安静的工作区、语义色、系统字体、共享控件与 CSS Modules。复用 Button、Input、Menu、Modal、焦点管理、locale 和状态反馈；新增持久设计决策实现后，同步设计规范及运行时 token。

浅色／深色、中文／英文、reduced-motion 使用同一状态模型。基础要求包括键盘可操作、明确名称、可见焦点、正文足够对比度、非纯颜色状态和有意义的 live region。视觉与可访问性须在浏览器验证，源码或旧截图不能证明当前实现达标；布局描述本身不代表已验证稿件。

## 6. 技术协作与优化边界

按独立职责拆分，技术细节见 [运行时设计](api-and-runtime.md#8-局部重构与性能)：

- UI：TeamPage 负责组装，产物、审计、表单负责展示与局部生命周期；沿用 slot／props。runtime 的 collections、channels、inbox、inspection 管理业务读取、缓存和取消，不把权威数据放入 React store。
- TeamRun／API：分别拆分 worker pool、workflow、创建／恢复、结果交付及业务 handler，共享认证和错误映射。
- Simulation：划分运行所有者、模型准入、actor 生命周期、checkpoint 协调和任务 executor，保留唯一写队列及授权校验位置。只为独立业务能力增设插件，不为每个面板新建包。

先测量 snapshot 全量复制、提交通知、历史 decisions 扫描、长列表渲染和订阅负载，再考虑精确读取、日志可重建索引、有界投影与失效通知。不能删除恢复校验或用缓存替代权威日志；规模、指标与准入见 [性能验收](implementation-plan.md#6-性能验证与优化准入)。

## 7. 交付完成标准

每阶段须有可独立评审的源码、授权语义、失败恢复和验证。C 只证明读取，D 证明受支持场景可运行，E 才证明自动任务执行；仅增加导航或按钮不算完成。

| 验收 | 必须具备的证据 |
|---|---|
| Team | T1–T7 的正常、分页、授权、冲突与失败回归，见 [回归矩阵](implementation-plan.md#3-team-回归矩阵) |
| Simulation | 当前构建、真实 Host、keyless 浏览器完成创建到中断恢复及结果追溯；自动任务从生产路径产生完成记录，见 [运行验收](implementation-plan.md#4-simulation-api-与运行验收) |
| 交互质量 | 页面、数据、尺寸、输入、状态、语言、主题与可访问性的本轮证据，见 [浏览器验收](implementation-plan.md#5-浏览器视觉与可访问性验收) |

报告分别列明通过、失败和未验证范围。真实模型与跨 Host 验证单独声明；unit／snapshot 不替代未执行验证，测试 helper 不替代生产执行闭环。

# Team 与 Simulation WebUI 改进方案

状态：本轮已实施并完成验收，完成范围与验证见实施计划。审查于 2026-10-01 开始，浏览器取证跨至 10-02（Asia/Shanghai）。对象为 `dbfb6e25b9` 加当前工作区改动，经本轮重新构建的 WebUI；不代表该提交的干净版本。

**建议进行以工作流程为中心的 UI 局部重构：保留 Team／Simulation 的服务、权限和运行时，重整页面框架、信息层级、表单和跨对象导航。** 当前最影响使用的不是色彩，而是空间没有分配给正在做的事、业务事实与诊断信息混排，以及不同页面没有共同的布局约束。

阅读顺序：本文说明目标设计；[实测审查](audit.md)提供 15 张本轮截图和可复核问题；[实施与验收](implementation-plan.md)定义修改位置、依赖、阶段和验收标准。[设计决策](../../.agents/notes/implemented/architecture/2026-10-01-webui-workspace-hierarchy.md)记录方案选择与风险。

## 1. 产品定位与本轮边界

用户面对两个相关但不同的工作对象：Team 用来组织并完成真实工作；Simulation 用来建立场景、显式推进运行、观察结果和追溯依据。Session 是某个参与者的执行记录；它既不是第三种全局工作区，也不应该替代 Team 的任务与待办。Simulation 引用 Team，不表示两者共享管理权限。

已有 [9 月 28 日方案](../webui-team-simulation-2026-09-28/design.md)定义了完整业务路径；[DESIGN.md](../../DESIGN.md)和 [UX-CONTRACT.md](../../UX-CONTRACT.md)已有正确的运行时约束。本提案补充当前实现缺失的布局与阅读层级，不重写那些业务规范。主方案适配长时间桌面操作，窄屏保留观察、核查和受支持的操作能力。

本轮已经操作真实组件、真实 HTTP/WebSocket Host 和持久化；数据来自隔离的 keyless 场景。没有调用付费模型，也没有改产品源码。仿真创建成功并建立初始检查点；未执行调度、恢复、任务审核或外部投递，不能据此声明这些闭环通过。

## 2. 优先解决的问题

| 优先级 | 实测问题 | 设计决策 |
|---|---|---|
| P1 | Team 概览／频道宽度随内容收缩；Simulation 页头挤压标题和刷新按钮 | 统一工作区宽度与滚动约束，分开身份、状态、操作和模块导航 |
| P1 | 390px 仿真页的模块导航在 y≈728px，实体详情首屏不可见 | 紧凑状态摘要；窄屏详情进入独立阅读层，保留返回和对象名称 |
| P1 | 关联 Team 被拒绝后，URL 指向新 Team，但正文仍是旧 Team | 独立的目标拒绝状态与“返回来源”，避免旧对象冒充目标对象 |
| P1 | 同一创建请求同时显示“请求已完成”和旧的“准备仍待完成” | 统一请求阅读模型，区分最新持久结果与较早回执，优先核对结果 |
| P2 | “待处理 0”与任务的“待处理 3”并存 | 人类待办叫“需要你处理”；pending task 叫“待执行” |
| P2 | 创建表单约 380px 宽，先展示长说明和部署字段 | 宽表单／窄屏完整页面，基本配置优先，高级额度按需展开 |
| P2 | 实体、决策、操作、检查点套用 ID／状态／详情三列表格 | 各模块用领域列；共用表格行为而非强制同一列结构 |
| P2 | “新任务”、Team、任务、工作区混用；仿真入口靠近设置 | 明确对象层级及上下文中的创建对象，Team 与仿真作为并列入口 |

P1 表示在继续堆叠功能之前应完成的可用性修复，并不表示已经证明数据损坏或权限绕过。问题证据、根因与局限见[实测审查](audit.md)。

## 3. 全局信息架构

全局侧栏上部固定“团队工作”“仿真”；下部保留设置。在“团队工作”中显示已有 Team 目录，在“仿真”中显示运行目录。不要同时把完整 Team 目录、完整仿真目录和模块目录塞进一根窄栏。跨工作区切换保留各自选择、筛选、滚动和内存草稿。

“新任务”改为明确创建根工作对象的“新建团队工作”；进入某个 Team 后的按钮仍叫“新建任务”。Team 内导航使用“概览、任务、频道、成员、产物”，次要模块进入“更多”。本轮不增设全局跨域待办聚合服务；已有 Team 收件箱必须标明所属范围，Simulation 待处理在当前运行中呈现。

Simulation 保留“概览、实体、决策、操作、检查点、记录”六个模块；新增“请求记录”作为“更多”中的诊断入口，集中读取现有持久请求和内存原操作。只有跨重载定位需求经过验证后，才增加对应 URL 选择值，避免擅自复用“记录”所代表的世界事件日志。

| 层级 | 用户问题 | 页面责任 |
|---|---|---|
| 工作区与目录 | 我要处理哪个团队／运行？ | 名称、业务状态、需要处理的数量；可搜索、有界分页 |
| 对象概览 | 现在怎样，下一步是什么？ | 状态摘要、需要人处理的事项、关键进展与相关对象 |
| 模块列表 | 哪些对象需要比较或定位？ | 领域列、筛选、分页、明确选中项 |
| 对象详情 | 为什么处于此状态，有什么证据？ | 摘要、可执行操作、关联来源；诊断字段后置 |
| 深入检查 | 模型实际做了什么？ | 经独立授权的 Session、原文、尝试历史与回执 |

## 4. 页面框架与尺寸

延续石墨侧栏、浅色／深色工作底、系统字体和蓝色动作，不引入新主题或组件库。让视觉区别体现职责：工作区身份清楚，状态克制，当前任务占最大空间。

桌面页从上到下为身份行、状态摘要、模块导航、内容。标题区占可用宽度，操作区按内容保留宽度，不让长状态列表参与标题行的横向收缩。状态字段以成组的标签和值布局，不能把独立 `dt`／`dd` 当成任意换行的词流。

| 区域 | 建议目标（需实现时实测） | 约束 |
|---|---|---|
| 全局侧栏 | 224px／56px，沿用现有伸缩 | 目录可以滚动，设置保持可达 |
| 工作区外边距 | 桌面 24–32px，窄屏 16px | 工作底覆盖全部余宽，不随模块数据量收缩 |
| 身份与状态 | 常规桌面合计约 112–144px | 允许长名称增加高度；完整名称能显式展开 |
| 模块导航 | 约 44px | 内容短时仍与标题对齐；窄屏用有标签的模块选择器 |
| 列表与详情 | 列表占剩余空间，详情 360–420px | 剩余列表不足约 480px 时切为单主面板，而非硬挤三栏 |
| 基础控件 | 36px 高；正文 14/22px，辅助文本 ≥12/18px | 主动作有明确强调；中文短标签不折成单字列 |
| 创建表单 | 桌面 720–880px，窄屏单栏完整视图 | 高级选项折叠，底部主动作稳定且不遮挡字段 |

布局模式按容器可用宽度决定；上述数字是初始设计目标，不能直接作为所有屏幕的固定高度。列表／详情有完整 `min-width: 0`、`min-height: 0` 和 flex 伸展链；表格内部滚动。概览和长表单允许自然纵向滚动，不通过给祖先加 `overflow: hidden` 强行“修好”截图。频道的列表、历史、输入区各自有明确滚动责任。

在 390×844 下，常规状态的运行名称、状态、主动作和模块入口应在顶部约 240px 内出现；进入实体详情后直接呈现实体名称与摘要，运行的诊断状态折叠。验收还必须覆盖 320 CSS px 回流；当前 390px 截图不证明符合 [WCAG 回流要求](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)。

## 5. Team 工作区

### 5.1 概览：进展与人类待办分开

第一层显示 Team 目标、生命周期和“与协调者沟通”。指标带保留“任务完成、执行中、需要你处理”，用量降为次要摘要。完成比率必须标成“任务完成”，不能表现为目标达成率。`pending` 改成“待执行”；“需要你处理”只来自现有 attention 读取，不由 pending task 数推导。

主区放执行任务，右侧放需要人处理的事项。出现审批、审核或输入请求时，事项给出对象、原因、等待状态和动作；无事项时缩成一条安静提示，不让大空卡与执行列表平分空间。成员、最近动态、产物仍可作为有限预览，完整集合由模块承接。

本轮样例人为关闭了任务调度器，不能据“3 个任务未分配”判定生产故障。未来如果显示“因能力不足等待”，必须来自有界的 Host 原因投影，不能由 UI 猜测。没有原因时只显示可确认的“待分配”。

### 5.2 任务：延续当前最清楚的列表＋摘要

保留任务列表、筛选和旁置摘要，减少对已有流程的扰动。摘要先显示名称、业务状态、负责人、依赖、最近结果和当前可用动作；完整描述与 attempts 后置。任务行的动作名称带任务名，关闭详情恢复行或筛选控件焦点。复用当前草稿、版本冲突核对、删除／停止授权，不将这些行为迁到表格内部重写。

把“刷新并返回首页”分成含义明确的“刷新本页”和“回到第一页”；若当前 API 只能刷新第一页，则显示“刷新到第一页”，不能承诺保留游标。页脚显示当前页条数与匹配总数；不把本页排序当作全量排序。全量排序或新筛选须先有 Host 能力。

### 5.3 频道：沟通区与传输配置分层

频道名称优先使用人能识别的参与者／用途；`human · coordinator`、`direct`、投递协议放入副标题或详情。统一“频道／通道”的产品文案。进入频道后，空历史显示“尚无消息”，输入区使用普通消息框和附件入口；多段文字的顺序编辑仅在确有多内容块时展开。

作者身份、接收者和投递方式不能删除；常规值用简明摘要展示，编辑放在“接收者与投递方式”。保留顺序附件、草稿恢复与原幂等发送身份。发送受理、投递完成和对方处理仍是不同状态。

### 5.4 会话：把“查看”与“沟通”说清楚

协调会话沿用当前宽视图和 conversation 实现，标题叫“与协调者沟通”，空态引用当前目标并说明输入会交给谁。worker 的只读入口继续叫“执行记录”，不出现暗示可直接控制 worker 的输入。第一次创建 Team 的宣传空态不应复用到已有 Team 的空会话中。

关闭视图只返回来源，不改变执行。暂不把完整 Session 永久塞入任务摘要，也不新增另一套消息渲染器；若将来要支持长时间对照，先验证展开模式的使用需求。

## 6. Simulation 工作区

### 6.1 目录：先选运行，再看主机资源

首屏由标题、搜索、新建入口和运行列表组成。每行优先展示名称、模板版本、调度状态、模拟时间及需要关注的事项。ID 与登记时间放在次级信息；不要在每个目录项复制全部运行诊断。Host 共享模型池收进明确标记为“主机资源”的折叠区，不能让它成为空目录的主体，也不能误标为单运行用量。

空目录展示“还没有仿真运行”和“新建仿真”；未装管理能力时解释只能查看，并引导到部署文档。搜索无结果与读取失败分别展示；加载完成之前不报空。

### 6.2 创建：场景、输入、额度、确认

沿用 Host 已安装模板和不可变 spec。一个表单按“场景 → 基本输入 → 运行额度 → 确认”分组：模板名称／用途／执行模式在选择时就说明；名称和模板参数紧随其后；默认额度用简短摘要展示，点击“调整额度”展开允许编辑的字段；模型路由、规则版本、策略版本属于只读配置详情。

“检查配置”放在表单底部的主动作附近。错误关联字段并保留输入；预检通过不免除最终 Host 准入。主按钮明确叫“创建暂停的运行”，成功受理后显示准备进度并打开同一个运行。未知结果保留当前操作，只显示“核对创建结果”和在允许时出现的“重试原请求”，不能重新分配身份。

关闭保留输入；“放弃输入”是次级动作并说明损失。草稿的内存／重载限制用简短帮助说明，不能占据表单第一屏的大半区域。首次准备完成和初始检查点成功之前不能展示可用的开始动作。

### 6.3 运行概览：状态、下一步、进展

页头只保留“运行名＋模板”“调度状态＋模拟时间”“当前主动作＋更多”。连接状态在断开／过期时醒目显示，正常连接用小标记。版本、writer、恢复名额、底层所有权和共享模型池移到“运行详情”。

状态摘要必须同时容纳业务调度与实际在途工作。例如“调度已暂停 · 仍有工作收尾”；不能把 paused 简化成“全部停止”。开始／继续／暂停的可用性来自 `control.actions` 等现有权威提示，主操作随状态选择，重复或不适用操作进入次级位置。

概览首先显示需要处理的问题：未知结果、待审核、恢复阻塞、预算不足。每项有原因、对象和直接入口。其次显示模拟时间、预算占用、待决策、未结算操作等少量指标，再放近期已授权记录。任务审核与任务控制在数量为零时使用紧凑空态；认知模式不支持的自动任务功能不应以完整空模块出现。是否支持须来自已安装执行模式，不由计数为零推断。

保留技术语义，但改变披露位置：模拟时间保持精确字符串和单位；真实时间用于请求时间／基础设施超时；预算占用包含预留与未知用量，不改名为实际费用；模型池是 Host 共享资源。缺值用“不可用”，不能填零。

### 6.4 集合与证据：按领域设计列

| 模块 | 默认行摘要 | 详情分区 |
|---|---|---|
| 实体 | 名称、类别、认知模式、有效状态 | 概况、关系、知识、关联执行；ID 次要但可复制 |
| 决策 | 实体、模拟时刻／slot、执行与提交状态 | 执行、冻结上下文、知识引用；标清来源版本 |
| 操作 | 操作类型、相关对象、执行结果、投递状态 | 结果、attempts、依赖、原 receipt；精确重试 |
| 检查点 | 可识别名称、保存状态、来源验证状态 | 引用完整性、诊断、验证并恢复入口 |
| 记录 | 序号、可读事件名、相关对象／动作 | 原始类型、原文与来源；导出授权范围 |

表中超出现有有界 DTO 的字段先标缺口，不能通过逐行全对象查询补齐。记录类型先对已知事件做本地标签映射，未知类型保留原字符串；事件类型不能自由推断为业务成功。集合行使用对象名链接／按钮代替一排同名“查看详情”，并提供清楚的选中样式。

实体详情不先堆 ID 和版本号。默认读名称、状态、关系摘要和可用操作；精确引用与版本放在技术详情。知识、冻结上下文、原始来源必须保留不同含义与权限；不把“信念”写成世界事实，不把部分上下文命名为完整模型请求。

### 6.5 请求：一个身份，一处清楚的当前结果

按 run 和 command ID 展示一个请求条目，组合已取得的持久元数据与内存回执，明确各自观察时间／版本和是否过期。本轮观察到持久目录已完成，但较早回执仍显示准备中；前端应显示“已完成；本地回执待核对”，不会据旧回执突出重试按钮。

最新结果的确定和更新归 runtime。只有查询成功才能用新 receipt 替换旧 receipt；结果无法比较时标明“状态待核对”，禁用依赖不明状态的动作。未知结果仍按原 ID 查询／重试；终态不得触发新的执行。UI 合并展示不合并权限、journal 或数据生命周期。

## 7. 跨工作区导航与反馈

从 Simulation 打开关联 Team／Session 时，保留“来自〈运行〉／〈实体〉”的来源条和返回动作。目标依旧独立鉴权。无权限时显示目标不可访问及“返回实体”，不能把原 Team 的标题、频道与数据放在目标 URL 下当作主内容；旧草稿可以留在内存，但不冒充新对象。

只把可分享的对象身份、模块和已提交筛选放进 URL；来源描述从授权读取或当前内存上下文恢复，不携带正文或密钥。不把上述来源条当作新的授权凭据。浏览器 Back／Forward 和明确返回需恢复来源 selection；失败时保留来源可用路径。

| 情况 | 用户应看到 | 保留／失效规则 |
|---|---|---|
| 首次加载 | 稳定的加载占位和对象身份 | 不提前显示空集合 |
| 后台刷新 | 原内容＋轻量刷新标记 | 不抢焦点、不重排选中项、不滚到顶部 |
| 分页失败 | 本页内容＋就地重试 | 保留游标，禁止使用无效 continuation |
| 断线或版本变化 | 明确“内容可能已过期” | 草稿保留；写操作按当前状态重新核对 |
| 撤权 | 正文清理与访问说明 | 撤权优先于保留旧内容，不能仅盖一层错误 |
| 命令结果未知 | 原请求身份＋核对／显式重试 | 不自动重新创建，不产生新幂等 ID |
| 输入冲突 | 当前值与拟提交值差异 | 保留草稿，明确确认当前版本后才提交 |

## 8. 视觉与可访问性取舍

优先统一几何、字体和状态表达，再微调颜色与动效。保留现有 token；页面摘要、表格和长表单使用不同密度，不把每个字段都包成卡片。正常状态减少解释性段落，异常状态保留可行动原因。主要按钮和次级文本动作有一致的强调关系。

键盘、焦点、读屏名称、控件尺寸、对比度需实测。本轮只核实了部分语义与导航，不声明无障碍合规。重复“查看详情”应补对象名；小按钮应测量，按 [WCAG 2.5.8](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)核对 24×24 CSS px 或适用的间距例外；触控布局以 44px 操作为设计目标。模态打开／关闭、非模态详情返回和筛选清除都需要可预期焦点。

不建议首轮增加装饰性关系图、可拖动看板或动画仪表盘：当前核心困难是阅读与定位，这些组件会增加导航负担。关系图仅在用户确有拓扑探索任务、有界查询和替代文本列表都具备后再评估。

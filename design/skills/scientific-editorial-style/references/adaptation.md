# 内容映射与适配

## 保留语言而不是保留原站业务

先将业务拆成六类信息，再选择组件。不要把所有产品都套成 DFM、ScienceBuddy、ScienceIDE 和 JEPA 的章节，也不要发明并不存在的研究关系。

| 语义 | 界面角色 | 不同行业示例 |
| --- | --- | --- |
| 主题 | 衬线主标题 | 一项研究目标、一个平台定位、一个待解决问题 |
| 论述 | 无衬线段落 | 方法、过程、机制、限制 |
| 元信息 | 等宽索引 | 编号、日期、版本、类别 |
| 关系 | 细线信息图 | 数据经过哪些步骤、结果如何返回 |
| 证据 | 暖色关键位置 | 验证结果、重要测量、选定候选 |
| 行动 | 清楚的链接或按钮 | 阅读报告、查看代码、开始使用、联系 |

## 新研究机构页面

可以先提出研究主题，再解释方法、独立方向和公开成果。每个方向采用同样的标题与图解模块，但图形拓扑根据真实机制变化。方向之间没有依赖时，不因画面需要而强行画成串联流水线。

## 技术产品介绍

将左侧身份列用作模块名称和一句定位，右侧解释能力、输入、输出与限制。图解表达已实现的机制；未来设想需要独立标注。如果产品没有论文，不强制创建成果列表，可以使用版本记录、案例或技术文档入口。

## 高频工作台

保留低饱和颜色、细分隔、无衬线正文和等宽元信息。衬线集中在页面标题或空状态说明，避免给每个表格单元、表单标签和操作按钮都加衬线。采用 reading 模式，正文即时显示，环境通常静态，关键反馈仍明确。

任务管理、监控和编辑器中的真实状态使用产品语义。不能把科研图中的琥珀验证点直接当成警告、成功、运行三种状态的同一颜色。

## 局部组件请求

只改按钮时，应用形状、文字、边框和相关追光；不添加粒子背景、衬线页标题或全站导航。只改信息图时，匹配其容器和现有字体环境，建立点线环语法；不要求用户重做整页。

## 品牌或字体受限

品牌蓝不能改时，保留其过程角色并检查与暗底的对比。没有衬线字体时，优先使用被允许的可用衬线 fallback；完全不能使用衬线时，用字重、字级、行距和元信息差异保留层级，清楚说明字体身份未完全复现。

暖色不能使用时，用更高亮度、轮廓或符号强调证据位置，并明确这属于受约束迁移。不要暗自引入用户禁止的颜色来追求参考相似度。

## 一页执行简报

实现前可以内部形成以下短表，不需要为每个字段向用户提问：

| 决策 | 需要填写的内容 |
| --- | --- |
| 范围 | 整页、局部模块、单一组件或审阅 |
| 模式 | reference 或 reading，及选择依据 |
| 内容角色 | 主题、论述、元信息、关系、证据、行动 |
| 结构 | 采用哪些组件，省略哪些无关模块 |
| 图形 | 实体、路径、反馈与适合的拓扑 |
| 运动 | 一次进入、持续示意、短反馈、环境层分别是否需要 |
| 限制 | 现有品牌、字体、框架、设备和静态替代 |
| 验证 | 对照哪些截图和状态，哪些参数需要实测 |

输出实施结果时只交代有影响的选择和偏差，不重复整张内部决策表。
